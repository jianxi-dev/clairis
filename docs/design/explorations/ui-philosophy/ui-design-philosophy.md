# 渐晰界面设计 — 决策逻辑与目标手册

> 版本: v1.0  
> 基于: 2026-07-12 ~ 2026-07-14 全部设计讨论  
> 用途: 后续设计与开发的决策依据，偏离本文档需单独说明

---

## 一、核心设计哲学

### 1.1 一句话

**用最短路径、最少干扰达成用户所愿。**

### 1.2 三原则

| 原则 | 含义 | 对应反模式 |
|------|------|-----------|
| 内容是王 | 界面 chrome 不抢注意力，不占用文档展示空间 | 大工具栏、常驻侧栏、装饰性元素 |
| 减法至上 | 每个元素必须证明自己存在。删不掉 = 不该存在 | "用户可能用到"、"加一个以防万一" |
| 操作即所得 | 用户意图和系统响应之间步骤 = 1。超过一步就要反思 | 多步骤弹窗、层层菜单、确认对话框 |

### 1.3 苹果级对标

设计产出应达到 Apple Notes / Bear / Xcode 的水准。具体标准：
- 打开就写，无需学习
- 没有令人焦虑的状态指示（如红色未保存）
- 功能的发现不依赖文档，靠直觉

## 二、核心决策逻辑

### 2.1 删除清单比新增清单更重要

每次设计迭代先问：**"还有什么可以删的？"**

已确认的删除清单：

| 删除项 | 原因 |
|--------|------|
| 左侧边栏 | 导航已由 Cmd+P 完整承载 |
| 右侧边栏 | Clairis 无边栏哲学 |
| 浮动工具栏 | 38px 回收给内容区，操作进 More 菜单 |
| amber 未保存点 | Cmd+N 自动生成文件 + 2s 自动保存 = 无未保存态 |
| Cmd+S | 自动保存已足够；Ctrl+S 原地触发（无 UI） |
| 快捷时钟 | 未保存态删除后无核心功能 |
| "+" 新建按钮 | Cmd+N 足够 |
| 阅读模式（独立） | 合并进"预览+全屏" |
| 红色用于脏状态 | 红色 = 错误专用 |

### 2.2 不隐藏功能

如果用户需要用某个功能，它应该**在界面上可见或可发现**。

- 不放进 More 菜单了事
- 不加 hover 才出现的秘密按钮
- 抽屉 / 折叠 / 自动隐藏 != 好的发现性

### 2.3 默认不打扰

| 路径 | 正确做法 |
|------|---------|
| 新建文件 | 自动生成 `Unnamed-YYYY-MM-DD-HHMM.md` 并自动保存。零弹窗 |
| 保存文件 | 自动保存成功 = 不告诉用户。只有失败才出声 |
| 关闭应用 | 无需确认（内容已保存） |
| 打开应用 | 直接到工作现场（最近文件 / 继续上次） |

### 2.4 先键盘后鼠标

高频操作必须有快捷键。但快捷键的触发不给用户造成记忆负担：
- 善用肌肉记忆（Ctrl+Tab 浏览器风格）
- 方向语义直观（Cmd+Option+→ = 向右分栏）
- 冲突有清晰裁决

## 三、具体设计规范

### 3.1 新建文件

**不要用户操心。**

```
Cmd+N → 立即在 ~/Documents/Jianxi/ 创建 Unnamed-2026-07-13-1030.md
      → 2s debounce 写入该路径
      → 用户全程无需关心保存
      → 想改名时双击页签直接编辑
```

### 3.2 文件名编辑

**双击页签 = 重命名。** 替代 Cmd+Shift+S 弹窗选路径。

- 双击进入 input 编辑态
- 输入框只读扩展名部分（`.md`）
- Enter = 保存, Esc = 取消
- 非法字符：`/ \ : * ? " < > |` 禁止

### 3.3 页面宽度调整

状态栏显示当前宽度值，点击弹浮窗：
- 滑块 400-1200px
- **仅三档快捷**：窄(480)、标准(720)、宽(960)
- 三档不在滑块边界上（滑块范围 > 五档范围）

**教训**: 不是档位越多越好。三个认知档位覆盖使用场景，滑块负责精细调节。

### 3.4 分栏操作

**多种方式，一个结果。**

- 快捷键：Cmd+Option+→ / ↓
- 拖拽页签到画布边缘：24px 蓝色拖入暗示带 → 松手生成
- 拖拽页签到分隔线另一侧：移到对面面板
- 关闭分栏：Cmd+Shift+W / 双击分隔线

**不加常驻分栏图标**。右侧 controls 区空间有限，拖拽暗示在意图产生时出现即足够。

### 3.5 分栏内历史导航

**双指左右滑动触摸板 = 切换文件间历史。**

- 左扫 → 历史上一个文件
- 右扫 → 历史上一个文件
- 视觉：文档从边缘滑入（150ms spring）
- 每个分栏面板独立维护历史栈
- Cmd+[ / Cmd+] = 同一功能的键盘入口

**设计意图**: 与浏览器双指后退/前进同构，已有肌肉记忆，免教学。

### 3.6 全屏

**不单独加按钮。**

- 预览模式下，模式切换图标从 Eye → Maximize2（外向箭头）
- 点击 Maximize2 → 进全屏
- 退出：Esc / 光标距顶 60px chrome 滑出 / 顶部 24px 热区

**设计意图**: 全屏是预览的延伸状态，两者心理距离近。图标 state 切换不引入新按钮。

### 3.7 图标系统

**统一 Lucide Icons。**

- 1.5px stroke, 24px grid, 圆角线头（Rounded）
- MIT 许可，商用 OK
- tree-shakeable，打包零额外成本
- 不用自定义 SVG、不用 Font Awesome、不用 Heroicons

### 3.8 状态栏分级

| 层级 | 显示 | 条件 |
|------|------|------|
| 常驻（opacity 0.6）| 行/列 · 字数 · 阅读进度 · 页面宽度 · 模式 | 始终 |
| tooltip（hover）| 完整路径、编码 UTF-8、换行符 LF/CRLF | 鼠标悬停 |
| 临时（opacity 1.0, 3s 淡回）| 保存失败红色提示 | 出错时 |
| 可点击 | 页面宽度（弹浮窗）、编码（弹选择器）、格式（弹选择器）、模式（切模式）| 始终 |

### 3.9 语义色

| 颜色 | 含义 | 用于 |
|------|------|------|
| 品牌蓝 #0071e3 | 激活/选中 | 时钟徽章、选区、聚焦环 |
| 红 #ff3b30 | 错误 | 保存失败 |

**红色绝不用于脏/未保存。**

## 四、绝对反模式（Never Do）

| 反模式 | 印哥原话 |
|--------|---------|
| "越多选项越多按钮就越好" | "不是越多选项越多按钮就越好，而是用最少做出更多最方便的功能" |
| 藏功能在 More 菜单 | "抽屉 / 折叠 / 自动隐藏 != 好的发现性" |
| 新建文件弹 Cmd+S 弹窗 | "Cmd+Shift+S也要弹出窗口，然后选路径命名，是不是也很麻烦" |
| amber 点 + morph 动画 | "全部删除。因为不再有'未保存'这个状态" |
| 默认隐藏工具栏 | "默认隐藏功能不是好的设计" |
| 5 档快捷 | "还是3档选项就好，还是分窄/中/宽" |
| 把关闭按钮默认隐藏 | "点击关闭按钮才出现是不必要的视觉复杂度" |

## 六、检验清单

每个设计决策需通过以下检查：

- [ ] **能删吗？** 这个元素删掉会影响核心功能吗？
- [ ] **能合并吗？** 能不能和其他入口合并？
- [ ] **默认出现吗？** 用户需要的时候，它是不是在那里？
- [ ] **能直觉发现吗？** 用户不看书能不能找到？
- [ ] **能一键完成吗？** 操作路径是不是 = 1？
- [ ] **提醒打扰吗？** 不打扰用户，除非出错？
- [ ] **心智模型一致吗？** 和浏览器 / OS 的习惯一致吗？

## 七、印哥的评审模式

印哥在评审设计时典型的追问顺序：

1. **"还有没有更短路径？"** — 任何操作都会被追问能否更简
2. **"这个用户必须知道吗？"** — 信息展示被问价值
3. **"删掉它会怎样？"** — 元素存在必要性被质疑
4. **"能不能让用户不思考？"** — 认知成本被反复压低
5. **"苹果会怎样做？"** — 对标 Apple 级别的产品

## 八、教训记录

| 错误 | 后果 | 修正 |
|------|------|------|
| 把 Cmd+S 从快捷键表移除 | 用户仍然想手动保存 | 加 Ctrl+S（触发保存，无 UI） |
| amber 点 + morph 动画 | 增加视觉复杂度 | 直接删除 |
| 5 档快捷选项 | 认知负荷 | 3 档 + 滑块 |
| 独立的 [+] 全屏按钮 | 多余元素 | 预览 icon 变 Maximize2 |
| 状态栏只显示 UTF-8/LF | 对中文用户零价值 | 分级显示，hover tooltip |
| 状态栏格式标记纯展示 | 砍交互到零 | 可点击弹出选择器 |
| 加快捷时钟图标 | 无功能承载 | 删除 |
| 加永久拖拽暗示线 | 干扰阅读 | hover 才显示 |
| 空状态只有文字 | "你自己琢磨怎么开始" | 2 个 CTA 按钮 |
