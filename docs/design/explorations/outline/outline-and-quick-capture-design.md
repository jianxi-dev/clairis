# 渐晰 — 大纲侧栏与灵感快速录入设计

> 状态: 待 Codex 3 轮对抗审查
> 来源: 印哥需求 + Ponytail 初步设计
> 目标: 大纲无标签页（hover/pin 模式）+ 灵感 quick capture

---

## 一、问题诊断 — 为什么现有设计有问题

### 1.1 大纲：快捷键触发 + 标签页 = 错误
`大纲面板（Cmd+Shift+E）` 违反两个渐晰核心原则：
- **标签页是状态**，不是工具。用户不想"打开一个面板"才能看大纲。他们想抬眼看到内容结构。
- **快捷键 + 面板 = 两个心智模型**。Cmd+Shift+E 触发面板，再点标签页切换——双重操作才能看一个东西。

### 1.2 灵感：Cmd+Shift+N = 错误
- `Cmd+Shift+N` 在 VS Code = 新建窗口、Chrome = 无痕模式——冲突严重
- 灵感录制应该与"应用焦点"解耦：你在读 PDF 时、写邮件时、看网页时，都可能突然想记录。焦点必须在渐晰内才能触发——违背灵感发生场景

## 二、大纲侧栏 — Hover + Pin 模式

### 2.1 空间位置

主画布右侧有一个**细轨道**（不明显），可容纳大纲悬浮面板：

```
┌─────────────────────────────────────────────────┐
│  工具栏                                          │
├──────────────────────────────────┬──────────────┤
│                                  │ [≡] ← 大纲轨道│
│         主画布内容               │              │
│                                  │  ──────────  │
│                                  │              │
└──────────────────────────────────┴──────────────┘
```

**轨道图标：**
- `≡` 竖直标题符号（与 `☰` 区分，不是菜单，是"大纲"的语义 icon）
- 默认状态：悬浮在画布右侧边缘，覆盖在内容之上（不挤压画布）
- 尺寸：28px 宽，高度自适应；图标在顶部（约 32px）

### 2.2 显示三种模式

| 模式 | 触发 | 显示行为 |
|------|------|---------|
| **悬停** | 鼠标移入轨道区域 | 展开大纲面板（悬浮覆盖），移出后收起 |
| **Pin** | 点击 Pin 图标（图钉 📌） | 固定显示，挤压主画布宽度 |
| **Push-out** | 按 Esc / 再次点击轨道 | 收起 |

### 2.3 大纲面板内部

悬浮打开后的面板布局（宽 240px，最大宽度可拖到 400px）：

```
┌─────────────────────┐
│ 大纲            [📌] │ ← Pin 图标；坚写 = Pin 状态
│─────────────────────│
│ 1. 产品定义          │ ← H1：缩进 0
│  1.1 一句话定义      │ ← H2：缩进 12px
│  1.2 产品哲学        │ ← H2
│ 2. 路线图            │ ← H1
│  2.1 Phase M        │ ← H2
│   2.1.1 阅读       │ ← H3：缩进 24px
│ 3. 性能架构          │ ← H1
└─────────────────────┘
```

**标题级别：**
- H1: 14px, bold, #1e1e1e（暗色: #e0e0e0）
- H2: 13px, semibold, #333
- H3: 13px, normal, #555
- H4 及以下: 12px, normal, #777 — 最多显示 H6

**交互：**
- 单击标题 → 文档滚动到对应位置
- 双击标题 + 拖动 → 自定义（不用）
- hover 标题 → 显示右对齐页码/位置百分比
- 当前正在阅读的标题 → 左侧蓝色竖条（active indicator）
- 折叠/展开（仅 Pin 模式下）——默认展开最近两层

### 2.4 实现约束

- **不使用标签页**。大纲面板永远是单窗口、固定宽度的侧栏。
- **不进入任何 TabBar / split 系统**。它不是标签。
- **Pin 状态持久化**：用户 pin 后，下次打开应用默认 pin（config.ts 管理）
- **键盘快捷键保留**：`Cmd+Shift+E` = toggle pin（在位与否都触发）
- **阅读模式下的隐藏**：沉浸阅读时隐藏大纲轨道（像工具栏一样）

### 2.5 大纲轨道设计细节

**轨道图标两种状态：**
- 未 pin: `≡` 半透明灰 (opacity 0.4)
- 已 pin: `≡` 完全不透明 (opacity 1.0) + Pin 图标在该面板上

**展开动画：**
- Hover 触发：150ms ease-out，宽度 0 → 240px
- Push-out 关闭：120ms ease-in，宽度 240px → 0
- Pin 切换：100ms ease-out，画布宽度重分配（主画布宽度 = 原宽度 - 240px）

## 三、灵感快速录入 — Quick Capture

### 3.1 不是"灵感文件夹里的 .md"

当前需求说：
> 随手记录一些日常问题、待办事项、或需要临时记录的应是最常需要的；灵感是偶尔录入的。

**重新理解：**
"随手记录"跟"灵感录入"可以是同一个窗口，取决于用户行为频率：
- **随手记录**：高频、结构化（待办、问题、碎片）
- **灵感录入**：低频、自由形式（灵感、想法）

**both go through `Cmd+Shift+.` 同一入口**。场景差异通过保存后的分类体现。

### 3.2 Quick Capture 窗口规格

**触发：** `Cmd+Shift+.`（系统级全局，任何 App 焦点下触发）

**窗口样式：**

```
┌─────────────────────────────────────┐
│ [定到前面] [最小化]              [✕] │ ← 顶栏，极简
├─────────────────────────────────────┤
│                                      │
│ [输入区域 — 光标永远在这里]       │
│                                     │
│                                     │
│                                     │
├─────────────────────────────────────┤
│ 📋 从剪贴板      📎 附文件    [→ 保存] │ ← 底栏
└─────────────────────────────────────┘
```

### 3.3 核心交互

| 行为 | 规格 |
|------|------|
| 按下快捷键到窗口可打字 | 热启动 < 50ms / 冷启动 < 200ms |
| 窗口出现位置 | 屏幕中央偏右上方（不遮挡当前内容） |
| 输入区域 | 永远 auto-focus，window mount 瞬间可盲打 |
| 最小化 | 按钮点击 → 窗口缩成"药丸"贴在屏幕边缘（顶/底/左/右四边可选） |
| 定到前面 | Toggle；启用后窗口始终在最前（手忙脚乱时不丢） |
| 拖动调整 | 可拖动到任意位置；可调整大小（最小 300x200） |
| 保存 | Enter 保存并关闭 / Shift+Enter 保存并再开一条 |
| 关闭 | Esc 即保存并关闭（不丢内容） |

### 3.4 保存后的行为

**保存内容：**
```
~/documents/inbox.md  ← 默认保存位置
  或
~/documents/journal/YYYY-MM-DD.md  ← 可选时间戳格式

格式：
- [ ] 待办内容        ← 检测"- ["前缀自动识别为待办
- 普通文本
- 灵感片段            ← 默认

标签自动识别：
- "- [ ]" → 待办条目
- "#tag" → 标签
- "@person" → mention
- "http..." → 链接（markdown 渲染）
```

**保存后操作：**
- 保存 + 关闭窗口
- 保存 + 不关闭（继续下一条）
- 保存 + 附加分类灵感文件夹（用户选择）

### 3.5 查看与整理 — R 阶段功能

录入是 R 阶段的重点，但整理也是：

**R 阶段的查看入口：**
- 统一文件面板 `Cmd+P` 空查询下的"继续"分组显示最近 5 条快速录入
- 文件面板内单独筛选"Quick Capture"分类
- 自定义日视图（`Cmd+Shift+J`；打开显示今天的 `inbox.md` 按时间线排列）

**整理动作（R 阶段完成后补充）：**
- 将快速录入转正为文档（"这篇文章"意图变成正式作品）
- 删除已完成或无关的条目
- 重命名/分类（灵感文件夹归档）
- 合并同主题多条记录为一个文档

### 3.6 与灵感模式（主画布 Cmd+2 万花筒）的关系

| 功能 | 入口 | 阶段 | 职责 |
|------|------|------|------|
| 灵感快速录入 | Cmd+Shift+.（全局） | P1 | 高速输入，从不丢想法 |
| 灵感模式 | Cmd+2（画布模式） | P1 | 浏览 / 发散 / 视觉灵感 |
| 灵感文件夹 | 文件面板 | P1 | 持久化存储 |
| 查看整理 | Cmd+P / 文件面板 | R 期 | 日视图 + 归档 |

## 四、与其他渐晰需求的对齐

### 4.1 导航面板可以访问灵感数据

文件面板"继续"分组可以包含最近录入的 quick capture 条目（`recentQuickCaptures`）——但 priority 低于文档。排序规则：
1. 当前任务现场文档
2. 今天录入的 quick capture
3. 最近访问文档
4. 未保存 / 待处理

### 4.2 状态归属

| 功能 | Store Slice | 字段 |
|------|------------|------|
| 大纲 Pin 状态 | nav.ts | `outlinePinned` |
| 大纲展开层级 | nav.ts | `outlineCollapsedSet` |
| 大纲选中标题 | nav.ts | `outlineActiveId` |
| Quick Capture 窗口位置 | config.ts | `captureWindowPos` |
| Quick Capture always-on-top | config.ts | `captureAlwaysOnTop` |
| Quick Capture 条目列表 | nav.ts | `quickCaptures[]` |
| Quick Capture 保存目录 | config.ts | `captureSavePath` |

### 4.3 快捷键总结

```
Cmd+Shift+E     → toggle 大纲 Pin（悬浮 = hover，再按 = pin）
Cmd+Shift+.     → 打开 Quick Capture 窗口（系统级全局）
Cmd+Shift+J     → 打开今日 Quick Capture 视图（可选，R 阶段）
Cmd+N           → 新建文档（应用焦点内，保留）
```

## 六、为什么这样设计

### 6.1 大纲侧栏

**为什么 Hover 而非 Cmd+?：**
- 用户看-outline 是"低头看手中书"级别的动作，不是"打开一个面板"
- Hover 可用 < 200ms 完成；Cmd+Shift+E 需要按键 → 肌肉记忆 → 触发 → 等待展开

**为什么 Pin：**
- 有些用户习惯左侧大纲永远在（像 Typora）
- Pin 模式挤出主画布；Hover 模式覆盖主画布——满足不同用户

**为什么不进入 TabBar：**
- 大纲是导航工具，不是内容。它不拥有自己的路径/文件/状态。

### 6.2 灵感快速录入

**为什么不是灵感文件夹：**
- 灵感文件夹是持久化存储层，不是录入入口
- 操作越轻越好。点击灵感文件夹 → 浏览 → 新建 → 写 → 保存 = 6 步
- Cmd+Shift+. → 打字 → Esc = 3 步

**为什么 always-on-top：**
- 在读网页/PDF 写 review 时，灵感转瞬即逝。切回渐晰窗口 → 灵感 backed up → 回去继续看。
- 一个 Pin 按钮 = 用户自己决定是否置顶，控制感在用户手。

**为什么 Shift+Enter 再开：**
- "串写"场景：想到三条相关 idea。不需要退出再 Cmd+Shift+. 再退出再重新打开。Shift+Enter = save + new line

**为什么保存到 `inbox.md`：**
- inbox 模式降低决策负担。用户不需要选文件名、选地点、选标题。就是一个列表。
- 整理才是 R 阶段任务。录入时别管整理。

## 七、Codex 审查预留

以下未解决问题留给 Codex 审查：
- Quick Capture 窗口怎么实现 always-on-top？Tauri v2 有 `Window::set_always_on_top()`，但系统级触发、独立窗口、不抢焦点——需要怎么处理？
- 大纲 hover 在 Mac 上的 hover 性能——Tauri webview 的 hover 精度如何？有什么限制？
- "药丸"最小化动画 — Electron/Tauri 有原生支持还是需要 CSS 动画？
- Quick Capture 输入内容如果很高（几千字），窗口高度超出屏幕怎么办？最大化 → 最小化逻辑？
