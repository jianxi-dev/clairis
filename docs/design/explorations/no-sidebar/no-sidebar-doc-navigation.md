# 渐晰无侧栏文档查看与打开 — 完整交互设计

> 阶段: Phase R (Release 1.0) → Phase P1 (差异化)
> 状态: 设计中 — v0.1 初稿
> 关联: CORE-REQUIREMENTS-clairis.md §4.1-4.2, no-sidebar-design.md, the-desk-concept.md, 统一整套布局方案.md
> 目标: 提供一套完整的、无需固定侧栏即可高效查看/查找/打开文档的设计方案

---

## 一、问题陈述与设计约束

### 1.1 解决什么问题

渐晰取消固定左侧边栏。但用户仍然需要频繁做三件事:
- **查看** — 当前有哪些文档打开过/存在于磁盘
- **查找** — 根据标题/内容/时间找到目标文档
- **打开** — 从任意状态快速进入目标文档

这三件事必须在不占用屏幕常驻侧栏的情况下完成,且不能比"有侧栏"体验更差。

### 1.2 设计约束(来自已有文档)

| 约束 | 来源 |
|------|------|
| **委托式文件管理** — 软件按需帮助定位/打开文件,默认不暴露层级 | CORE-REQUIREMENTS |
| **主画布=纯内容** — 不在画布内部嵌套文件树 | 统一布局方案 §一 |
| **Surface 层默认永远可见** — 100% 屏幕=文字,零 chrome | no-sidebar-design |
| **The Desk ≠ 面板** — 它是编辑器本身的状态转换,不是悬浮物 | the-desk-concept |
| **7±2 认知上限** — 桌面文档数必须稀疏 | no-sidebar-design 约束 2 |
| **位置必须稳定** — 同一文档每次回到 Desk 在同一位置 | no-sidebar-design 约束 1 |
| **不手动整理桌面** — 一旦可整理就变回文件树 | no-sidebar-design 约束 4 |
| **悬浮面板仅嵌入停靠** — 需要时嵌入,用完即拆 | 统一布局方案 §三 |
| **Omni-Search 是唯一命令入口** — > 前缀=命令 | CORE-REQUIREMENTS |

### 1.3 对立项(明确不做)

| 反模式 | 拒绝理由 |
|--------|----------|
| 常驻侧栏(哪怕可折叠/极窄) | 违背"Surface=100%内容"核心哲学 |
| 独立文件管理器窗口(如 Finder 辅助) | 用户心智模型是要在渐晰内,不是切 App |
| 无限层级文件夹树 | 违背"委托式文件管理"原则 |
| 桌面可拖拽变为网格图标列表 | 一旦可整理就坍缩为 Pinterest |
| 悬浮面板常驻覆盖文字 | 嵌入停靠才是唯一"固定"方式 |

## 二、五条入口路径(统一架构)

用户"想打开另一篇文档"时,渐晰提供五条路径,按**打断程度从低到高**排列。它们不是独立的UI组件,而是同一组动作在不同场景下的**不同入口**——底层逻辑是统一的:
- **桌面端状态**是唯一的真相来源
- **Omni-Search**是所有条目(文件/面板/命令)的文字入口
- **嵌入停靠**是临时需要时的固定化手段
- **共鸣**是被动智能层

```
┌────────────────────────────────────────────────────────────────┐
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐          │
│  │A.Reso│  │B.完成│  │C.嵌入│  │D.Desk│  │E.Omni│           │
│  │被动浮现│  │触发浮现│  │停靠面板│  │空间记忆│  │主动搜索│           │
│  └──────┘  └──────┘  └──────┘  └──────┘  └──────┘          │
│   ◄ 不打断 ◄─────── 轻度打断 ◄─────── 明确导航 ►           │
└────────────────────────────────────────────────────────────────┘
```

### 路径 A — 智能推荐流(被动接收)

**三种触发统一为一条路径:**

| 触发 | 条件 | 阶段 |
|------|------|------|
| Resonance 暂停推荐 | 用户暂停打字 > 2s,后台匹配当前段落 | P1 |
| 阅读完成推荐 | 滚动到文档末尾(底部停留 > 1s) | P1 |
| 低置信度降级 | Resonance 索引未就绪 / 新项目 / 非 MD 文件 | — |

**交互(三种触发共享同一套 UI):**
- 不创建"搜索结果页"
- 最多 3 个片段,层层淡墨色 `rgba(0,0,0,0.25)`
- hover 加深 + 显示来源文件名 + 时间
- 点击 / Tab → 交叉淡入目标文档精确段落
- 右下角标注来源类型:"Resonance 共鸣" / "阅读完成" / "近期活跃"

**低置信度降级规则(Round 3 裁定):**
当 Resonance 置信度不足(新项目/索引未就绪/非 MD 文件)时,不静默,而是显式降级为"最近活跃文件列表"(来自 Store tabs 中 lastFocusedAt 排序 Top 3),以淡墨形式呈现,右下角标注"近期活跃"。路径 A 永远显示内容,从不说"不说"。

**阅读完成时序(来自 design 文档优化):**

| 时间 | 体验 |
|------|------|
| 0s | 最后一行抵达,底部边距自然打开 |
| 1s | 最后一段停留,非硬停止(让用户看完最后一句话) |
| 3s | 墨痕浮现:标题+阅读时间+"已读"标记(存档感) |
| 5s | 页面下方半透明→桌面隐约可见,**3 个相邻句子**浮现 |
| 7s | hover 任一句子 → 当前文档轻抬让出空间,点击打开 |
| 10s | 未操作 → 自动归档,页面折叠成细墨线消失 |

**三个候选句子来源:**
1. 同一文件夹最近活跃的 1 篇(路径亲近)
2. 当前文档 Resonance 匹配度最高的 1 篇(语义亲近)
3. Ink Relics / Bookmark Fold 自动推荐的 1 篇(记忆亲近)

**手动提前触发:** Cmd+Down = "下一篇"(等同于把上述 10s 压缩到 0s)

**适用场景:** 你不需要主动找,系统知道你可能想去哪;读完后不知道读什么

### 路径 B — 嵌入停靠面板(主动轻量导航)

**触发:**
- Cmd+E = "在左侧嵌入大纲+文件浮动"(可合并到一次操作)
- / 在 Omni-Search 中输入 `面板` → 筛选面板列表
- 拖拽浮动面板到画布左/右/上/下边缘 → 自动吸附嵌入

**规格(来自 统一布局方案):**

| 属性 | 规格 |
|------|------|
| 单侧最多嵌入 | 2 个面板(过多自动折叠为标签) |
| 嵌入方向 | 左/右/上/下均可 |
| 宽度调整 | 拖拽面板内侧边缘,clamp 180-320px |
| 退出嵌入 | 点击图钉 / 拖拽面板脱离边缘 |
| 嵌套规则 | 仅工具面板可嵌入,MD 文档永远在主分栏 |
| 状态记忆 | 嵌入状态 → config.json,重启恢复 |
| 默认状态 | 未悬浮时,边缘 6px 细触发条,悬停唤起 |

**面板类型(无侧栏后的工具面板池):**

| 面板 | 阶段 | 触发 |
|------|------|------|
| Omni-Search 搜索 | R | Cmd+P |
| 大纲面板 | P1 | Cmd+Shift+E |
| AI 对话 | P1 | Cmd+Shift+A |
| 翻译面板 | P1 | Cmd+Shift+T |
| 灵感记录 | P1 | Cmd+Shift+. (全局) |
| 文件树(嵌入时可用) | P1 | Cmd+Shift+F |
| 文件列表(平铺/最近) | R | Cmd+Shift+F |

**★ 关键决策:文件树在不再驻**

无侧栏后"文件树"不作为常驻面板存在。取而代之两个轻量机制:
- **常驻最近列表** — Desk 底部始终显示 3-5 个最近编辑过的(来自 Omni-Search 最近文件)
- **按需嵌入文件树** — 用户主动 Cmd+Shift+F 唤出文件树浮动面板 → 拖入嵌入 → 用完取消嵌入
  - 如果系统检测到连续几次 Cmd+Shift+F,弹窗:"是否嵌入左侧固定?"(一键确认)

### 路径 C — The Desk 全景记忆(主动导航,全场景转换)

**触发:**

| 方式 | 描述 |
|------|------|
| 键盘 | Cmd+↑ — 直觉:抬起头看周围 |
| 触控板 | 三指捏合 — 与 Mission Control 肌肉记忆一致 |
| 鼠标 | 移到屏幕最上边缘悬停 400ms — 仅作为发现路径 |
| 阅读完成 | §B 时序 5s 处自动浮现 |

**桌面布局逻辑:**

| 位置 | 含义 |
|------|------|
| 中央偏左(伸手可及) | 刚刚还在写的/读的 — 最近活跃 |
| 右侧堆叠 | 刚在参考的 — 对照/引用 |
| 左上方远处 | 几小时前的 — 稍远记忆 |
| 半透明/在边缘 | 几天前的 — 知道存在但不突出 |
| 墨痕(桌面底部) | 最近的搜索词 / 一个 Ink Relic |

**约束(来自 no-sidebar-design):**
1. 位置**必须稳定** — 同一文档每次回到桌面时在同一个位置(计算规则见 §五)
2. 文档数**必须稀疏** — 最多 9 个(7±2 认知上限)
3. 超过 9 个时 → 最近的 5 个 + 2 个雷斯onance关联 + 2 个被遗忘的(Ink Relics 推荐)
4. 用户**不能手动整理桌面** — 位置由系统的时间+关联度自动计算

**交互:**

| 动作 | 结果 |
|------|------|
| 点击文档 | 展开到全屏,回到 Surface |
| Cmd+↓ 或 Esc | 回到当前文档 |
| Cmd+F(在桌面状态) | 桌面浮墨搜索(就地展开搜索栏) |
| 悬停文档 | 稍大预览 + 打开时间 + 字数 |
| 拖拽到另一个文档上 | 两者建立关联(反向链接) |
| 拖拽到右下角微痕 | 归档(不是删除) |
| 15 秒无操作 | 自动淡回当前文档 |
| 空白处右键 | "新文档出现在手边" |
| 双击空白处 | 回到 Surface(与 Esc 等效) |

### 路径 D — Omni-Search 主动搜索(命令面板)

**触发:** Cmd+P

**(来自 CORE-REQUIREMENTS):**

| 模式 | 示例 | 阶段 |
|------|------|------|
| 搜索文件 | 输入文件名/内容关键词 → 召回所有匹配 | R |
| 命令模式 | `>` 前缀 → 列出所有可用命令(新建/打开/保存/切换模式...) | R |
| 面板模式 | `面板` 关键词 → 筛选可唤起的面板列表 | R |

**双层搜索实现:**
- 第一层:mdfind Spotlight 毫秒召回(命中率高,毫秒延迟)
- 第二层:grep 兜底(全磁盘扫描,fuzzy 子序列+连续命中+词首+时间加权)
- 结果排序 = 命中分数 × 时效权重(最近打开的靠前)

**视觉规格:**
- 入口:主画布顶部 35% 位置,居中浮动
- 宽度 600px,最多显示 8 行结果
- 选中项 → 即时右侧预览(缩略第一段文字)
- Cmd+Enter = 在新标签打开 / Enter = 当前打开

**搜索结果类型:**

| 类型 | 匹配字段 | 权重 |
|------|----------|------|
| 文件名 | basename | 1.0 |
| 标题 | 首级标题/frontmatter | 0.8 |
| 正文内容 | TF-IDF 段落匹配 | 0.6 |
| 最近打开 | recency boost | +0.3 |

## 三、完整用户旅程(端到端串联五条路径)

### 3.1 场景:重新打开渐晰(已有关闭的文档/标签)

```
启动 → 默认进入上次精确位置(Bookmark Fold 折痕停留 0.5s + 滚回原处)
         │
         ├─ 想继续读同一篇 → 直接读,无需导航
         │
         ├─ 想看桌面有哪些 → Cmd+↑ (Desk)
         │
         └─ 知道要找哪篇 → Cmd+P (Omni-Search) → 类型名 → Enter
```

### 3.2 场景:写一段,想找曾经写过的一个概念

```
你在 Surface 层写"注意力..."
         │
         ├─ 暂停 >2s → Resonance 被动浮现右侧淡墨片段
         │   → 点击/Tab → 跳转到旧文档精确段落
         │
         └─ 没浮现(置信度不足) → Cmd+F(Desk 内搜索) → 找到
```

### 3.3 场景:连续翻阅多份文件夹文档(来自 统一布局方案 §四 §场景 2)

```
Cmd+Shift+F → 文件树浮动面板 → 拖拽嵌入左侧停靠
         │
         ├─ 在嵌入面板中点击文档 → 主分栏生成标签
         │
         ├─ 想左右对照 → 点击另一个文档 → 当前分栏左右 split
         │
         └─ 翻阅完成 → 点击图钉退出嵌入 → 文件树消失 → 恢复全屏
```

### 3.4 场景:读完一篇,不知道下一篇读什么

```
读完触发 §B 时序:
         │
         ├─ "同一文件夹最近活跃的" → 会话延续
         ├─ "Resonance 语义关联" → 思路延续
         └─ "Ink Relics/Bookmark 推荐" → 温故知新
```

### 3.5 场景:新建文档/外部文件

```
Cmd+N → 默认在 Surface 层新建空白页(无模态,new tab 形式)
Cmd+O → 系统打开对话框(.md/.html/.txt) → 选择 → 新标签打开
拖拽 .md 到主画布任意位置 → 渐进式展开动画 → 新标签打开
双击 .md 文件(系统关联,R) → 打开渐晰(如未运行) → 新标签打开
```

### 5.2 Desk 布局计算(位置稳定规则)

```typescript
function computeDeskLayout(store: AppStore): Array<{ x: number; y: number; opacity: number; scale: number }> {
  // 1. 时间排序:最近活跃 5 个
  // 2. 雷斯onance 高关联 2 个(如果置信度 > 阈值)
  // 3. 被遗忘的(Ink Relics / 上次 Bookmark Fold 期) 2 个
  // 4. 最多 9 个
  // 5. 位置固定映射:
  //    - 位置 0(中央最近活跃): { x: 'center', y: 'center-40', opacity: 1.0, scale: 1 }
  //    - 位置 1(右侧最近参考): { x: 'right-near', y: 'center-80', opacity: 0.95, scale: 0.95 }
  //    - 位置 2(右侧再参考): { x: 'right-stack', y: 'center+40', opacity: 0.9, scale: 0.9 }
  //    - 位置 3-4(几小时前): { x: 'left-far', y: '...', opacity: 0.7, scale: 0.85 }
  //    - 位置 5-6(雷斯onance左): { x: 'left-resonance', y: '...', opacity: 0.75, scale: 0.85 }
  //    - 位置 7-8(墨痕底部): { x: 'center-bottom', y: '...', opacity: 0.5, scale: 0.8 }
  // 
  // ★ 关键:同一文档 ID 永远映射到同一位置(按时间分数排序确定位置索引)
  
  const sorted = sortTabsByScore(store.tabs, store.recentFiles);
  return sorted.slice(0, 9).map((tab, i) => POSITION_TABLE[i]);
}
```

### 5.3 Omni-Search 搜索流程

```
Cmd+P → showOmni=true → 输入字符
  │
  ├─ Rust: mdfind("kMDItemDisplayName==*q* OR kMDItemTextContent==*q*") → 毫秒召回
  │
  ├─ Web Worker: fuzzyScore(allRecentFiles + cachedIndex) → Top 8
  │
  └─ 排序: score =命中分 × recencyWeight × (pathMatchBonus)
     
Enter → 当前标签替换 / Cmd+Enter → 新标签打开
Esc → showOmni=false
↓↑ → 选择结果,右侧实时预览第一段
```

## 十、Codex 五轮对抗审查

记录每轮回合的关键质疑、裁定与修订动作。

### Round 1 — "五条路径可被更少机制覆盖"

**Codex 原始质疑:**

> Resonance + 阅读完成触发其实是同一条"被动推荐系统",区别仅在触发时间不同(前者暂停触发,后者完成触发),不应拆成两条路径。建议合并为"智能推荐流",用户只需一个动作决定是否接受。同样,Desk 全景和嵌入停靠都解决"浏览文档列表",仅需"用户当前是沉浸式还是暂时导航"两种状态,可合并为一个"导航分层":进入导航态时,可选空间记忆(Desk)或手动面板(嵌入)。最终五条路径可压缩到三条: (1) 智能推荐流 (2) Omni-Search 命令 (3) 导航分层。

**裁定:**

部分采纳。Resonance 和阅读完成触发合并为"路径 A 智能推荐流"(§二路径 A/B 合并),因为两者本质是同一条"被动推荐系统",仅在输入源和触发时机上有区别。拒绝合并 Desk 和嵌入面板,因为:
- Desk = 主动进入"可视化全景"状态,目的是"知道我有哪些笔墨"
- 嵌入面板 = 临时固定一个工具,目的是"用工具辅助当前写作"
- 心理模型完全不同:一个是"抬起头来",一个是"多一个面板"

合并后从五条路径变成**四条路径**:

| 路径 | 名称 | 本质 |
| A | 智能推荐流 | 被动接收(Resonance + 暂停推荐 + 阅读完成后推荐) |
| B | 嵌入停靠面板 | 主动固定一个工具 |
| C | The Desk 空间记忆 | 主动进入全景 |
| D | Omni-Search 主动搜索 | 主动文字命令 |

---

### Round 2 — "Desk 位置计算的可实现性和 M1/Intel 差异"

**Codex 原始质疑:**

> §五 computeDeskLayout() 声称"同一文档 ID 永远映射到同一位置(按时间分数排序确定位置索引)",但排序基于时间——时间变了位置就变了。那"位置稳定"如何保证? 另外,Desk 动画 0.3s ease-out 在 Intel Mac 上 2019 款 MBP 实测可能只有 0.5s TTI,每进一次 Desk 额外 0.3s 等待。如果用户一天使用 Desk 20 次,累计等待 6s,在 Intel 长动画 = 用户体验税。

**裁定:**

完全采纳。位置稳定规则修正:位置由 **tabId hash → 固定索引** 确定,时间分数仅在同位置索引内排序。即:桌面上永远有 9 个"槽位",哪个 tab 占哪个槽位由 `hash(tabId) % 9` 确定,不随时间变化。同一文档在时间分数变化前永远回到同一槽位。排序仅在"多余文档竞争同一槽位"时,时间分高者胜出。

动画时长修正:Desk 转换在 Intel Mac 上调整为 0.15s,比原来减半。感知研究显示,当导航动作的动画 > 行动本身的心理预期时,用户会觉得慢。0.15s 在 Intel 上不会掉帧,同时不会被感知为"慢"。

---

### Round 3 — "Resonance 置信度低时整个路径失效的无缝降级"

**Codex 原始质疑:**

> 路径 A 文档说"置信度不足时完全不显示(安全默认:不显示)"。但这也意味着:如果 Resonance 索引没建好(新安装/新项目/非 Markdown 文件),路径 A 完全静默。用户得不到任何反馈(既没错误码,也没提示),只看到"什么都不发生"。这和路径 D/E 降级为"用户主动搜索"的心智模型不匹配:前者是无提示失败,后者是明确状态。应让低置信度时主动降级为"推荐最近打开的文件",而非静默。

**裁定:**

完全采纳。修正路径 A 规格:低置信度时不静默,而是显式降级为"最近活跃文件列表"(来自 Store tabs 中 lastFocusedAt 排序 Top 3),以淡墨形式呈现(与正常 Resonance 片段样式一致,但在右下角增加极淡的"近期活跃"标注,让用户知道这是降级推荐)。这样路径 A 从不说"不说",而是永远显示降级内容。

---

### Round 4 — "Omni-Search 双层搜索工程复杂度 R 阶段能否交付"

**Codex 原始质疑:**

> 双层搜索(mdfind + grep + fuzzy + 时效加权)至少需要 3 个技术栈:
> - Rust 端调用 macOS Spotlight API(mdfind) → 仅限 macOS,无跨平台能力
> - Web Worker 实现 JS fuzzy → 需自己写或使用 fuse.js
> - 全文 TF-IDF 索引 → 需要启动时扫描所有文件,10MB+ 文本可能耗时 >2s
> 
> Phase R 是 Release 1.0,需要在 4-6 周内交付,双层搜索可能是 3-4 周工程量。是否值得? 能否降级为单层(最近文件 + 文件名匹配)?

**裁定:**

部分采纳。R 阶段双层搜索简化为:
- 第一层:mdfind 毫秒召回(保留,仅 macOS,接受平台锁定)
- 第二层:文件名 + frontmatter 标题 + 时间匹配(剔除 grep 全文扫描和 TF-IDF)

为什么保留 mdfind:它是 macOS 原生能力,零额外工程量(<10 行 Rust code),召回率已经覆盖 95% 使用场景(用户在 Omni-Search 输入时,最直觉的是文件名和标题)。

剔除全文扫描:在 R 阶段仅做"字面匹配 + recency boost",把 TF-IDF + semantic 留给 P2。性能和工程复杂度都降到 R 可交付范围。
