## 一、取代文件树 — 侧栏的全新方案

### 方案 1: 时间轴流

把文件按"时间"排列，像社交信息流。不让你想"文件放在哪"。

```
┌─ 今天 ────────────────────────┐
│ 📄 设计哲学.md         2h ago  │
│   设计的本质不是解决问题…        │
├─ 昨天 ────────────────────────┤
│ 📄 周会记录.md         4h ago  │
│   讨论了 Q3 架构方向…           │
├─ 本周 ────────────────────────┤
│ 📄 技术架构.md                │
│   Rust 和 Go 的选择…           │
└───────────────────────────────┘
```

**实际体验:** 你打开 jianming，侧栏自动显示今天/昨天/本周写过的东西。你不需要想"这个文件在哪里"，它在"你最近写它的时候"的位置。搜索是主要导航方式。

### 方案 2: 智能伴侣侧栏 ⭐（推荐）

侧栏不是文件列表，是一个"助手"。它根据你当前在做什么，动态推荐你需要什么。

```
┌───────────────────────────────┐
│ 🔍 [搜索或跳转…]              │
│                               │
│ 📌 正在写                     │
│  📄 设计哲学.md               │ ← 当前文档
│                               │
│ 🔗 你可能需要这个              │
│  📄 CORE-REQUIREMENTS.md      │ ← AI 自动推荐的关联文档
│  📄 设计咨询备忘.md            │
│                               │
│ ⚡ 快捷操作                    │
│  [📝 新笔记] [📁 新集合] [🔗]  │
│                               │
│ 🕐 最近                       │
│  📄 周会记录.md · 2h ago      │
└───────────────────────────────┘
```

**与旧文件树的区别:**
- 旧: 你先想"文件在哪个文件夹"，再展开 → 找到 → 点击
- 新: 侧栏直接告诉你"你现在需要什么"。你只管写，它跟着变

### 方案 3: 星群导航（最创新）

文件不放在文件夹里，而是按"内容关联"排列成星群。

```
          📄 设计咨询备忘
              ↗    ↖
  📄 排版规范 ←────→ 📄 设计哲学.md ←─── 📄 架构设计
              ↙         ↓
          📄 Token 方案    📄 组件树

符号含义:
  星星大小 = 文件重要性（越大越重要）
  星星亮度 = 最近活跃度（越亮最近写过）
  连线     = 两个文档有关联
  拖拽两个星星靠近 → jianming 解释它们的关联
```

**实际体验:** 你打开 jianming 看到的不是文件夹树，是一个"思想宇宙"。你的文档按语义自动排列。你点击星星打开文件，hover 看到关联关系。不需要手动组织——jianming 替你组织。

## 二、情绪陪伴 — 编辑器感知你的状态

### 场景 1: 你在专注写作（Flow 心流状态）

```
你连续打字超过 10 分钟，没停下来点菜单、没切窗口。

编辑器检测到:
· 打字节奏稳定（每秒 3-5 字符）
· 很少用删除键
· 没有切换文档
· 没有点工具栏

→ 编辑器自动做这些事:
   1. 工具栏渐渐淡出 → 只剩极淡的轮廓线
   2. 行号变暗 50%
   3. 侧栏自动缩成窄条（只剩图标）
   4. 光标从闪烁 → 变成温和的呼吸光晕
   5. 底部极淡显示: ⚡ flow · 12min · 340字

   如果你继续写 30 分钟:
   6. 底部提示: "你已经专注写了 30 分钟。约 1,200 字。你在状态中。"
```

**你感受到:** "编辑器在给我让路。它不是消失了，是退到背景里保护我的注意力。"

### 场景 2: 你卡住了（反复修改同一段）

```
你在同一段话上改了又删、删了又改，持续 5 分钟。

编辑器检测到:
· 删除键使用率 > 输入率 × 3
· 光标在同一区域反复跳跃
· 超过 30 秒没有新增内容

→ 编辑器自动做这些事:
   1. 段落边缘出现极淡的琥珀色光晕（代表"这段在发热"）
   2. 光标旁边出现 3 个小选项（不打断你，极淡）:
      [↩ 恢复前一个版本]  [📌 先放一放]  [❓ 问 AI]
   3. 你继续改 → 编辑器不多说（保持安静）
   4. 你停下来 3 秒 → 选项稍微明显一点
   5. 忽略 → 10 秒后选项自动消失
```

**你感受到:** "编辑器知道我在纠结。它没有弹窗教育我，只是安静地递了三个选项。我用不用都行。"

### 场景 3: 深夜还在写

```
凌晨 1 点，你还在写。

编辑器检测到:
· 当前时间是凌晨 1:00-5:00
· 会话已持续 2+ 小时
· 打字速度开始下降

→ 编辑器自动:
   1. 色温从冷白转为暖白（减少蓝光刺激）
   2. 整体亮度降低 20%
   3. 底部淡出:
      🌙 深夜了。保存一个版本再休息？
   4. 保存时自动加标签 "深夜快照"
   5. 第二天首次打开时显示:
      "你昨晚写到很晚。需要回顾一下吗？"
```

**你感受到:** 不是"你该睡了"的管教感，是"我在陪你"的温暖感。

## 三、阅读体验 — 读和写是两个人格

写作时 → 工具人格：功能、效率、有反馈
阅读时 → 沉浸人格：安静、美观、无干扰

```
写作态 (Edit Mode)                 阅读态 (Reading Mode)
┌─────────────────────┐           ┌─────────────────────┐
│ 工具栏: B I S 代码  │           │ 无工具栏             │
│ ─────────────────── │           │                     │
│ 等宽字体 JetBrains  │           │ 比例字体 Literata   │
│ 行距 1.5            │           │ 行距 2.0            │
│ 侧栏可见            │           │ 全屏无 chrome       │
│ 光标闪烁            │           │ 无光标              │
│ 打字有涟漪反馈       │           │ 翻页动画 (左右滑)    │
│                    │           │ 进度条 ▰▰▰▰▰▱▱▱▱ 42% │
│                    │           │ 预计阅读剩余 8 分钟   │
└─────────────────────┘           └─────────────────────┘

切换方式: 点击右上角 "阅读" 按钮，或按 Cmd+Shift+R
过渡动画: 0.5 秒平滑变换（工具栏淡出→字体切换→边距展开）
```

### 阅读透镜 — 同一篇文章，不同"滤镜"

```
阅读时，右侧边缘有一根细的垂直控件:

┌───────────────────────┬──┐
│                       │S │  ← Summary 透镜
│  正文内容…             │  │    每段旁边出现一句话摘要
│                       │  │    适合快速扫读
│                       ├──┤
│                       │C │  ← Critique 透镜
│                       │  │    薄弱论点有灰色虚线下划线
│                       │  │    重复观点有细线连接
│                       ├──┤
│                       │D │  ← Definitions 透镜
│                       │  │    术语底色微变，点击展开解释
│                       │  │    不打断阅读流
│                       ├──┤
│                       │A │  ← Argument 透镜
│                       │  │    显示论证结构标记
│                       │  │    主张🟦 证据🟩 反对🟥 结论🟨
│                       ├──┤
│                       │S│C│ ← 组合模式
│                       │  │    Summary + Critique 同时启用
│                       │  │    拖拽一个透镜到另一个上即可
└───────────────────────┴──┘

实际操作:
  点击 S → 进入 Summary 模式
  点击 C → Summary 关闭，Critique 开启
  从 S 拖拽到 C → 两个同时开启
  点击空白 → 关闭所有透镜
```

**实际体验:** 你不是在看"一页文字"，你有一个智能阅读助手。点 Summary 看到大纲，点 Critique 看到论证分析，点 Definitions 解释术语。不想用时完全隐身。

## 四、归来体验 — 每次打开都是重逢

### 日常归来（几小时后再打开）

```
Step 1: 你按 Cmd+Tab 切换到 jianming
Step 2: 0.3 秒内自动完成:
   · 分栏比例滑入上次的位置
   · 滚动条滑到上次的段落
   · 光标在旧位置闪烁
   · 侧栏状态恢复（上次展开/折叠状态）
Step 3: 文档上方出现半透明卡片:
   ┌─────────────────────────────────┐
   │ 你离开 3 小时了                   │
   │ 上次写到: "设计的本质不是…"       │
   │ 第 3 节 · 进度 42%               │
   │ [继续写 · 按任意键]              │
   └─────────────────────────────────┘
Step 4: 你按下一个键 → 卡片淡出
        编辑器回到精确离开状态
```

**你感受到:** "它记得我。像没离开过。"

### 久别重逢（3 天以上）

```
┌─────────────────────────────────────┐
│                                     │
│  ☕️ 三天不见了                       │
│                                     │
│  你上次在写:"设计哲学.md"             │
│  已经写到第 4 节，当时在打磨引言       │
│                                     │
│  你不在的时候:                        │
│  · 这篇文档新增了 2 条反向链接         │
│  · 你的周会和它有内容重叠              │
│                                     │
│  [回到上次位置]  [看看新关联]          │
│                                     │
└─────────────────────────────────────┘

区别:
  日常归来 → 恢复精确位置，显示简明卡片
  久别归来 → 重建"上下文"（这篇在讲什么、你当时在想什么）
```

## 五、三个完整产品概念

### 概念 A · 工作室 (The Atelier)

**一句话:** jianming 是一个"写作空间"，不是"写作软件"。

**打开它你会看到:**
```
┌──────────────────────────────────────┐
│  (工具栏已淡出 — 你在写)             │
│                                      │
│  设计的本质不是…                     │
│  每次我坐在桌前…                     │
│                                      │
│  ┌──── 侧栏 ──────────────────┐     │
│  │  你现在在写: 设计哲学.md     │     │
│  │  关联: 架构设计 (打开 2h ago)│     │
│  │  被删段落: 3 段可恢复        │     │
│  └────────────────────────────┘     │
└──────────────────────────────────────┘
```

**完成一篇时的体验:**
1. 写完最后一段
2. 点"完成"（不是保存，是"完成"）
3. 编辑器自动进入"最终阅读"——全屏，无 chrome，像读一本书
4. 读完后点"确认" → 生成"快照" + 显示写作统计
5. 编辑器关闭文档，回到"空间"（星群视图）

### 概念 B · 伴侣 (The Companion)

**一句话:** jianming 是你想和它一起工作的编辑器。

**关键体验:**
- 没有"AI 对话浮窗"。AI 的建议出现在最自然的上下文
- 你改写段落 → 页边出现:"之前的版本更简洁，要看吗？"
- 你阅读文章 → 右侧透镜给出摘要/分析
- AI 多数时候不说话——它在，但不烦你

**信任感来源:**
- 第一周: 几乎不说话，只观察
- 第二周: 偶尔在合适时机提建议
- 你忽略建议 → 它记住"这时候不要说话"
- 拒绝 3 次以上的功能 → 自动隐藏

### 概念 C · 容器 (The Vessel)

**一句话:** 通过"意义"找文件，不是通过"路径"。

**打开一个旧文件你看到:**
```
📂 doc/designs/design-consultation-20260702.md
↑ 路径还在，但你不必关心

实际你看到的大纲:

  ❓ 问题 — "现有的设计有哪些问题？"
  🟦 主张 — "应该用 Linear + Notion 混合路线"
  🟩 证据 — "用户调研显示 70% 偏好简洁 chrome"
  🔄 转折 — "但内容区需要温暖感"
  ❓ 未解决 — "暗色模式的品牌色需要验证"

↓ 这才是你找文件的方式——按"它讲了什么"，不是"它在哪个文件夹"
```

**怎么用:**
- 搜索时按"概念"搜：搜"排版规范" → 所有提到排版的文件都出来
- 创建关联：把两个文件"连接"在一起（不用放到同一个文件夹）
- 自动聚类：jianming 发现两个文件在讲类似内容 → 在侧栏推荐"你可能想把它们归档在一起"

## 六、总结 — 设计原则

1. **编辑器不是工具，是空间** — 用户打开不是"开始工作"，是"回到一个地方"
2. **克制建立信任** — AI 少说话比多说话好。被忽略 3 次的功能自动隐藏
3. **读和写两个人格** — 同一款应用，两种完全不同的界面和感受
4. **每次归来都是重逢** — 不是"加载文件"，是"回到上次离开的地方"
5. **文件管理应该消失** — 用户不应该管理文件，编辑器应该替用户管理
