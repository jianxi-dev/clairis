# 阅读视图六项反馈修复计划

针对你验证后的 6 个问题，逐项给出根因与改法。涉及文件：`src/renderers/markdown.ts`、`src/renderers/mermaid.ts`（新增）、`src/components/Content/PreviewView.tsx`、`src/components/Content/ReaderSettingsPopover.tsx`、`src/styles/reader.css`。

## 1. 支持 mermaid

**根因**：渲染器把所有围栏代码块都当代码处理，没有 mermaid 分支。

**改法**
- 已安装 `mermaid` 依赖（新增 110 个包）。
- `src/renderers/markdown.ts` 的 code 渲染器：`mermaid` 语言输出 `<div class="mermaid-block wide"><pre class="mermaid">源码</pre></div>`（不带语言标签和复制按钮）。
- 新增 `src/renderers/mermaid.ts`：动态 `import("mermaid")`（懒加载，不进主包），`securityLevel: "strict"`，按当前明暗选 `theme: dark | default`，把 SVG 写进 `.mermaid-view`，成功后隐藏源码 `pre`。渲染失败（语法错 / jsdom 无布局）时保留源码文本，不报错。
- `PreviewView.tsx`：内容变化后调用渲染；另外监听 `<html>` 的 class 变化，切换深/浅色时重渲一次（源码留在 DOM 里，随时可重渲）。
- `reader.css`：给 `.mermaid-block` 加底色、边框、圆角、横向滚动；`svg` 居中且最大宽度 100%。

## 2. 阅读配色：从「换标题色」升级为「阅读主题」

**根因（不只是配色问题，是分层问题）**：现在阅读视图的标题色是从编辑器的 `headingColors`（CodeMirror 里给源码标题上色的配置）注入的 `--heading-h1…h6`。这意味着**编辑态的源码配色在决定阅读态的呈现**，两者本来是两件事；而除标题外的加粗、链接、引用、callout 又各自写死一套色，整体没有一处能“一套风格”地切换。所以要补的不是几行色值，而是缺一层“阅读主题”。

**设计**
- 引入 **阅读主题（reading theme）**：一个主题 = 一组语义变量，同时决定**标题三级色 + 加粗色 + 强调/链接色 + 行内代码色 + 引用与 callout 主色**。切一次换整套，而不是只换标题，观感才协调。变量名按用途而非按元素命名，元素只做映射：
  - `--tone-1` → h1/h2（主层级）
  - `--tone-2` → h3/h4
  - `--tone-3` → h5/h6
  - `--tone-ink` → `strong`、行内代码
  - `--tone-accent` → 链接、引用边、callout 主色、任务勾选色
- **与编辑器标题色解耦，但不打破现状**：优先级定为 阅读主题 > 编辑器 headingColors > 默认墨色。CSS 写成 `color: var(--tone-1, var(--heading-h1, var(--reader-ink-strong)))`。默认主题「纸墨」**不定义** `--tone-*`，于是行为与今天完全一致（仍跟随编辑器标题色）；选定其他主题时 `--tone-*` 出现，整体覆盖。既不回归，也不用迁移配置。
- **预设 4 套**（覆盖主要阅读场景，不再按色相堆数量）：

  | 主题 | 取向 | 适用 |
  | --- | --- | --- |
  | 纸墨（默认） | 暖白纸 + 近黑墨 + 靛青 | 长文阅读，最小干扰 |
  | 靛青 | 深靛蓝标题 + 偏蓝墨 | 技术文档、笔记 |
  | 松绿 | 墨绿标题 + 低饱和绿强调 | 长时间阅读，低刺激 |
  | 赭石 | 暖棕标题 + 赭红加粗 | 中文长文、人文类 |

  每套深/浅各一份色值（深色下统一走高亮度同色相）。
- **扩展成本**：新增主题 = 面板常量数组加一项 + reader.css 加一个 `html[data-skin="x"] .preview-content {}` 块。沿用已有 `config.readerSkin` 字段与 `documentElement.dataset.skin` 机制，不动 Rust 配置结构。
- **面板交互**：主题按钮带一个色块（该主题的 `--tone-1`），比纯文字 pill 直观——用户在选“效果”，不是在选名字。字号/行宽维持现有 pill + 滑块。

## 3. 背景色只铺一屏

**根因**：`.preview-shell` 写了 `height: 100%`，高度锁死在一屏；真正滚动的是外层容器（ContentArea 的 `overflow: auto` 容器）。内容超过一屏后，纸面背景只画了第一屏，往下露出框架底色。

**改法**：`.preview-shell` 改为 `min-height: 100%` + 纵向 flex，`.preview-content` 加 `flex: 1`。短文档仍满屏，长文档背景随内容延伸到底。

## 4. callout 内容重复

**根因**：`convertCallouts` 用 `bq.firstElementChild` 取标题所在元素，却用 `bq.childNodes.slice(1)` 拼正文。首子元素前面若有空白文本节点，两个索引错位，整段正文被拼接两次。

**改法**：以 `firstElementChild` 在 `childNodes` 中的真实位置为起点取后续兄弟节点（`indexOf(first) + 1`），索引永不错位。

## 5. 内嵌 HTML+CSS 深色未转色

**根因**：内嵌 HTML 的颜色写死在 `style` 属性里，CSS 变量和 `.dark` 规则都盖不住内联样式——这是文件本身决定的，不是漏配。

**改法**（只在 markdown 内嵌 HTML 上生效；独立 .html 文件是 iframe 内的另一个文档，无法干预）
- 渲染后处理：扫描带 `style` 的元素，把 `color` / `background-color` / `border-color` 的 hex、rgb 值换成 `var(--dc-N, 原色)`，同时算出深色替代值（浅底→深底、深字→浅字，保留色相，边界外的颜色不动）。
- 深色替换值通过 `takeDarkVars()` 交给 `PreviewView`，由它渲染一个 `<style>`，在 `.dark` 下定义这些变量。原色作为 `var()` 兜底值保留，浅色模式完全不受影响。
- 已经是深色底/浅色字的元素不动，避免二次反转把配色搞坏。

## 6. 表格圆角与列宽

**改法**
- 圆角：表格独立用更大的 `--reader-radius-lg`（12px），并给 `.table-wrap` 加 1px 边框——没有边框的圆角在浅底上看不出来；同时去掉内部首尾行的重复边框。
- 列宽挤/高：表头去掉 `white-space: nowrap`（长表头不再撑爆列宽），表格改 `width: max-content; min-width: 100%`，列按内容自然展开，超宽时由外层横向滚动，而不是把文字压成竖条。

## 验证

- `npx tsc --noEmit`、`npx vitest run src/__tests__/markdownRender.test.ts`、CSS manifest 检查。
- 新增用例：mermaid 输出 `.mermaid-block`、callout 正文只出现一次、内联浅色底生成 `--dc-N` 变量。
- 最后按仓库约定跑 `npm run tauri dev`，用一份含 callout、mermaid、表格、内嵌 HTML 的测试文档手动过一遍关键路径（滚动到底看背景、切深色看内嵌色块和 mermaid、切 4 套配色看标题与加粗）。
