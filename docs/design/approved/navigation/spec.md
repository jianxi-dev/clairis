# 标月无侧栏导航 — 最终方案

> 状态: 已定稿  
> 来源: Codex / Ponytail / 印哥 三方收敛  
> 替代: `no-sidebar-desk-file-list-proposal.md`（归档）  
> 目标: 无侧栏场景下，用户切换文件、找文件、恢复上下文、确认状态安全

---

## 一、一句话结论

**两个入口，零新概念。**

- `Cmd+P` → 统一面板（空查询=当前上下文；输入=全局搜索；带词=局部相关）
- `Cmd+[` / `Cmd+]` → 标准后退/前进

没有任何叫 Desk / Portal / Shelf / Workspace 的用户可见系统。它们被降级为同一面板里的视图或行为。

数据源只有三个：导航历史、引用关系、用户操作。不新增第四种数据。

---

## 二、原方案问题诊断

原方案 `no-sidebar-desk-file-list-proposal.md` 洞察正确（解释力优先），但产品形态过重：

| 原设计 | 问题 |
|--------|------|
| 10个独立命名系统 | 用户需要学一套新导航语言 |
| Desk/Portal/Shelf/Workspace 边界不清 | 概念膨胀，实际数据源只有3个 |
| 11种来源理由标签 | 用户记不住 |
| Trail = 浏览器后退可视化 | 重新发明已有快捷键 |
| 阅读收尾台 | Cmd+W 已解决 99.9% |
| 稳定哈希槽 | 过早优化 |
| Workspace 自动聚类 | 要么是 Shelf 子集，要么是噪音 |

**结论：收敛成一个统一面板，取消命名系统，保留正文上下文触发。**

---

## 三、最终方案

### 3.1 入口定义

| 入口 | 行为 |
|------|------|
| `Cmd+P` | 打开统一面板。空查询 → 当前上下文视图；输入文字 → 全局搜索；带选中文本 → 局部相关视图 |
| `Cmd+[` | 后退（标准历史栈） |
| `Cmd+]` | 前进（标准历史栈） |
| `Esc` | 关闭面板 / 回到进入前状态 |

只有 `Cmd+P` 是新的。其余复用操作系统标准快捷键。

### 3.2 面板视图（自动切换，用户无需选择）

面板根据打开时的上下文自动选择视图，不需要用户手动切换：

**A. 空查询 — 上下文视图**（用户意图：继续刚才的工作）

```
┌─ ⌘ ──────────────────────────────────┐
│                                       │
│  继续                                  │
│  ● 无侧栏方案.md        读到："Desk是…" │
│  ◦ The Desk 概念        "引用过 · 3min" │
│  ◦ 三栏布局方案          "分屏对照 · 昨天"│
│                                       │
│  待处理                                 │
│  ● CORE-REQUIREMENTS    "未保存 ⚡"      │
│  ◦ 搜索实现.md           "读到一半"      │
│                                       │
│  最近                                   │
│  ◦ 设计原则.md           昨天            │
│  ◦ docs/index.html       周一            │
└───────────────────────────────────────┘
```

**B. 最近 — 全部文件视图**（新增文件时从这里打开）

面板空查询时，"最近"分组展示**当前工作目录下的全部文件**，按最近访问/修改时间倒序排列，不只是用户曾打开过的：

```
┌─ ⌘ ──────────────────────────────────┐
│                                       │
│  继续                                  │
│  ● 无侧栏方案.md        读到："Desk是…" │
│  ◦ The Desk 概念        "引用过 · 3min" │
│  ◦ 三栏布局方案          "分屏对照 · 昨天"│
│                                       │
│  待处理                                 │
│  ● CORE-REQUIREMENTS    "未保存 ⚡"      │
│  ◦ 搜索实现.md           "读到一半"      │
│                                       │
│  全部                                   │
│  ◦ 设计原则.md           周一 · docs    │
│  ◦ 新版原型说明.md       周三 · drafts  │
│  ◦ 07-会议记录.md        周四 · notes   │
│  ◦ index.html            上周 · output  │
└───────────────────────────────────────┘
```

**视图展示顺序规则（从上到下）：**
1. **继续** — 当前任务现场（引用过/分屏对照/跳转过），最多 5 条
2. **待处理** — 状态风险文档（未保存/读到一半/失效），最多 5 条
3. **全部** — 工作目录下所有文件（按 mtime 倒序），超过 20 条时提示切换搜索

> 如果项目文件总数 > 20 条，"全部"默认显示最近 20 个文件，其余折叠为"显示全部 →"按钮。点击后展开或引导用户用搜索过滤。

**C. 输入搜索 — 全局搜索视图**（用户意图：明确找文件）

```
┌─ ⌘ desk ─────────────────────────────┐
│                                       │
│  ● The Desk 概念        命中标题        │
│  ◦ 无侧栏方案.md         正文命中        │
│  ◦ 三栏布局方案           路径命中        │
└───────────────────────────────────────┘
```

**D. 带选中文本 — 局部相关视图**（用户意图：从正文触发，找相关文档）

选中文本 + `Cmd+P`，面板顶部显示搜索词，显示相关文档：

```
┌─ ⌘ "上下文地图" ─────────────────────┐
│                                       │
│  与"上下文地图"相关                    │
│  ● The Desk 概念        包含该词        │
│  ◦ 无侧栏方案.md         引用关系        │
└───────────────────────────────────────┘
```

### 3.3 文件项规格

每个条目只显示三行：

```
[状态点] 标题                              [时间]
         记忆线索 / 命中片段
         来源理由 · 父目录
```

**状态点：**
- 实心点 = 当前打开
- 空心点 = 近期打开
- 墨点 = 未保存
- 折角 = 读到一半

**来源理由：** 自然语言片段，不用标签模板。
- `"引用过"` `"分屏对照"` `"3min前"` `"读到一半"` `"未保存"`

**记忆线索：**
- 编辑过 → 上次编辑位置一句话
- 搜索命中 → 命中片段高亮
- 读到一半 → "读到：..."
- 新文档 → 首行内容

**标题优先级：** `frontmatter title` > `H1` > 文件名（隐藏 `.md`，同名冲突时再显示）

### 3.4 文件项交互

| 动作 | 行为 |
|------|------|
| `Enter` | 打开到主 Surface |
| `Space` | Peek 预览（不跳转） |
| `Cmd+Enter` | 旁开 |
| `Tab` | 固定到当前任务（临时Pin） |
| `Cmd+C` | 复制路径 |
| `Ctrl+1` ~ `Ctrl+9` | 直接打开对应序号的条目（免Enter，最常用操作） |
| `hover` | 显示完整路径 + 字数 + 状态 |

> **Ctrl+数字快捷键规则：** 面板打开后，数字 1~9 对应面板中当前显示的第 1~9 条文件项。按 `Ctrl+1` 直接打开第一条，`Ctrl+2` 打开第二条，以此类推。条目左侧可显示淡色数字标记（按下 Ctrl 时高亮），不干扰正常浏览。

### 3.5 正文中的内联入口

选中文本后 `Cmd+P` 自动带上该词作为搜索词。不需要单独 Portal 系统 — 这就是 Portal，只是不说。

## 四、数据模型（最小集）

只保留三个数据源，不新增：

```typescript
// 导航历史 — 已有
interface NavHistoryEntry {
  docId: string;
  lastAccessed: number;
  accessType: 'open' | 'split' | 'portal' | 'search';
  cameFrom?: string; // 上一个文档 id
}

// 引用关系 — 解析正文 wiki-link / md-link 得到
interface DocRelation {
  from: string;
  to: string;
  type: 'reference' | 'backlink';
}

// 用户操作 — 记录显著动作
interface UserAction {
  docId: string;
  action: 'edit' | 'pin' | 'peek' | 'read-progress';
  timestamp: number;
  cursorPosition?: number;
}
```

面板的"当前上下文视图"从这三个数据源实时计算，不缓存、不持久化到独立存储。

## 五、取消的系统列表（明确不做）

| 原概念 | 降级为 |
|--------|--------|
| Desk | 面板空查询时的默认视图 |
| Shelf | 文件项上的 `Tab` 固定行为 |
| Portal | 选中文本 + `Cmd=P` |
| Workspace | 先不做独立界面 |
| Trail | 标准 `Cmd+[` 后退 |
| 阅读收尾台 | 关闭文档即结束 |
| 自然语言搜索 | R阶段不做 |
| 稳定哈希槽 | 直接用 relevance 排序 |
| 安心提示 | 系统 toast，不进导航系统 |
| Omni Search 命令模式 | R阶段只搜文件，不搜命令 |

## 六、实施阶段

### R 阶段（两周内上线）

1. `Cmd+P` 统一面板（空查询=上下文视图，输入=搜索）
2. Space Peek
3. 标准后退/前进
4. 统一文件项组件（标题 + 理由片段 + 状态点）
5. 选中文本 + `Cmd+P` 带词搜索
6. 系统 toast（保存/未保存/路径失效）
7. 可选：经典侧栏兼容开关

R 阶段搜索只做：文件名 + `frontmatter title` + `H1` + 父目录。不做正文全文索引。

### P1 阶段（用户反馈驱动）

- 分组扩展到 10 条/组
- "固定到当前任务"的列表管理
- `Cmd+[` 长按显示最近路径
- 更丰富的文件项行为（旁开、Peek、固定）

### P2 阶段（确认需要后开启）

- 语义搜索 / 本地 embedding
- 自动任务聚类

---

## 七、最终原则

无侧栏导航的关键不是"显示更多文件"，而是"在正确的时机显示正确的文件"。

每个文件项必须回答：它是谁？它和我现在有什么关系？我上次对它做了什么？

面板不需要用户选择视图。它根据打开时的上下文自动判断。

用户不需要学习新系统的名字。他只需要记住 `Cmd+P`。
