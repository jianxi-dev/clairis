# 交付路线图

本路线图只做**阶段目标摘要**，回答“分几步做、每步要达成什么”。

> ⚠️ **本路线图不自称功能验收真相源。** 逐功能可验收行为（requirement 与 scenario）见 `openspec/specs/`；阶段内的功能细节不在此复制。产品级范围边界见 [范围边界](../product/scope.md)。

## 一、阶段原则

- **阶段唯一原则**：每个功能只标一个阶段（M / R / P1 / P2 / 远期）。
  > 来源：全量需求文档 §0.2「裁定规则」（历史原稿已被取代，历史存根 `docs/CORE-REQUIREMENTS-clairis.md`；现行阶段归属见本路线图）。

## 二、阶段目标摘要

| 阶段 | 定位 | 阶段目标摘要 |
|------|------|--------------|
| Phase M（软著 MVP） | 占位与最小可用 | 单栏阅读 + 基础编辑 + 打开保存 |
| Phase R（Release 1.0） | 正式发布 | 多页签 + 文件搜索 + 字号缩放 + GFM 完整 + 沉浸阅读 + 统一文件面板 |
| Phase P1 | 差异化 | 展卷仪式 + 悬浮面板 + 嵌入停靠 + 双栏分栏 + AI 对话 + 主画布模式（灵感 / 磁场）+ 视觉引擎 |
| Phase P2 | 完整版 | 空间导航模式 + 知识网络 + 成长系统 + 移动端 + 灵感同步 |
| 远期 | 生态扩展 | 多平台 / 团队 / 更多语种 |

> 来源：全量需求文档 §1.5「路线图摘要」（历史原稿已被取代，历史存根 `docs/CORE-REQUIREMENTS-clairis.md`；摘要原文提炼，未增减阶段结论）。

## 三、阶段定位说明

- **Phase M**：先满足阅读，申请软著 + 占位，再扩展编辑和成长功能（“先阅读，再编辑，终智能”）。
  > 来源：[MVP-渐明-v1](../archive/2026/legacy-docs/MVP-渐明-v1.md) §目标、§1.3「进化路径」。
- **Phase R**：发布 1.0，补齐多任务、检索与完整阅读体验。
- **Phase P1**：做出差异化（仪式、面板体系、AI、主画布多模式）。
- **Phase P2**：完整版（空间导航、知识网络、成长系统、移动端）。
