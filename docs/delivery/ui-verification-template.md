# UI 交付验收模板（三件证据）

> 对应 change `ui-quality-gate-v1` 任务 1.3 / 规格 UQ-3。每个**用户可见**的交付都要附齐三件证据，缺任一件按未交付退回。
> 视觉数值的唯一来源是 [设计系统规范](../design/system/spec.md)：本模板只引用条款号与 token 名，不复制像素值。

## 为什么是三件

「编译通过 + 单测绿」证明不了用户看到的界面对。三件证据各管一段：

- **截图对**管「看得见的」：明暗两主题、宽窄两窗口，四个格子一起看，才暴露只在某主题或某宽度下出现的偏差。
- **可复现步骤**管「别人能重走」：评审或用户按步骤在真实应用里走一遍，而不是看一张静态图猜交互。
- **计算样式断言**管「数值对不对」：从计算样式读出的具体值，用 token 名或条款号表述，不靠肉眼比对。

## 一、截图对（明/暗 × 1280/400）

四个格子，一格一图。每格标注它证明的**关键态**（例如：打开、切换、取消、外部点击、空态、关闭）。

| 主题 | 窗口宽度 | 截图 | 本图证明的关键态 |
| --- | --- | --- | --- |
| 明（`:root`） | 1280 |  |  |
| 明（`:root`） | 400 |  |  |
| 暗（`.dark`） | 1280 |  |  |
| 暗（`.dark`） | 400 |  |  |

填写示例（把表格复制进 PR 正文，逐格补链接与态名）：

```markdown
| 主题 | 窗口宽度 | 截图 | 本图证明的关键态 |
| --- | --- | --- | --- |
| 明 | 1280 | ![明-宽](.artifacts/1649/light-1280.png) | 打开：菜单展开且焦点在首项 |
| 明 | 400 | ![明-窄](.artifacts/1649/light-400.png) | 窄窗：菜单仍完整展开，不被裁切 |
| 暗 | 1280 | ![暗-宽](.artifacts/1649/dark-1280.png) | 暗色下选中格文字可读（对比度达标） |
| 暗 | 400 | ![暗-窄](.artifacts/1649/dark-400.png) | 暗色窄窗：同上，无残留 |
```

判据：

- **四格齐全**，缺任一主题或任一宽度即退回。
- 每格有截图且**标了关键态**；只写「正常」不算态名。
- 截图为真实渲染所得（`npm run tauri dev` 或 dev server），不是设计稿或原型截图。

## 二、可复现步骤

编号步骤，评审能照着在真实应用里走一遍；每步写明**预期观察**。

填写示例：

```markdown
1. `npm run tauri dev`，打开任意 Markdown 文件。
   预期：阅读态正常渲染，无浮层。
2. 按 `?` 打开快捷键帮助。
   预期：浮层展开，焦点落在关闭按钮。
3. 按 Esc。
   预期：浮层关闭，编辑器内容不变（无保存、无删除）。
```

判据：

- 步骤**可照着执行**：含启动命令与具体操作，不是一句「打开看看」。
- 每步有**预期观察**；只写动作不写预期，等于没写。
- 若该交付已有 e2e 覆盖同一条关键路径，可改为引用该 e2e 用例（写清文件与用例名），但步骤清单仍要给出手工走查的入口。

## 三、计算样式断言

列出断言的**计算样式属性与期望值**，用 token 名或条款号表述。

填写示例：

```markdown
- 选中格文字 `color` 计算值 = `var(--app-on-accent)`，背景 = `var(--app-accent-fill)`（`design-system:§6`）。
- 该文字对填充底的对比度 ≥ 4.5（`design-system:§7.8`）。
- 菜单行高计算值 = `var(--sf-ctrl-height)`；字号 = `--fs-13` 一档（`design-system:§4`）。
```

判据：

- 断言的是**计算样式**（computed style），不是源码里的声明值。
- 期望值写成 **token 名或条款号**，不复制像素数值；数值只在 [设计系统规范](../design/system/spec.md) 定义一次。
- 断言覆盖本次交付实际改动的属性；拿无关属性凑数不算。

## 何时豁免

- 票面标 `no-ui-impact`（纯文档 / 基建 / 脚本 / 测试，用户看不到界面变化）→ 三件证据整体豁免，在 PR 正文写明 `no-ui-impact`。
- 涉 `ui-surface` 标签或 diff 触及 UI 路径的票**不豁免**，且额外要求 `.artifacts/<票号>/state-coverage.json` ≥4 态（见下）。

## 缺证据如何退回

缺任一件证据 → 交付对账按**未交付**处理，退回补齐。规则见 [反馈对齐 §九](../agents/feedback-alignment.md#九交付对账表开发后逐条写明做了什么)：功能点必须能对应到三件证据之一，没有证据的功能点等同没交。

退回应写清缺哪一件、补什么，而不是重写整段。

## 证据放哪里

- 目录：`.artifacts/<票号>/`（票号为 GitHub issue 号）。
- 截图 PNG 与 `state-coverage.json` 随 PR 提交；`state-coverage.json` 记录 ≥4 个状态，每态含 `state` / `screenshot` / `assertion`（取值 `passed` / `failed` / `untested`）。
- 机检：`jq '.states | length' .artifacts/<票号>/state-coverage.json`（<4 为违规）；`jq '.states[] | select(.assertion=="failed")' ...`（有 failed 为违规）。
- 约定细节见 [证据采集规范](../agents/evidence-capture.md)。

## 自检清单（复制进 PR）

```markdown
- [ ] 三件证据齐全：明/暗 × 1280/400 截图对 + 可复现步骤 + 计算样式断言（模板：docs/delivery/ui-verification-template.md）
- [ ] (涉 ui-surface) .artifacts/<票号>/ 截图与 state-coverage.json 已随 PR 提交
```
