# requirements — table-editing-polish

> Spec issue: https://github.com/jianxi-dev/clairis/issues/738
> 生效日期：2026-11-13
> 来源：用户 2026-11-13 无人值守请求（MD 编辑态表格交互清单）。

## What（做什么）

1. 单元格手柄统一：悬停单元格显示统一的表格图标（不再按空/非空切换两套图标）；手柄上下居中贴单元格左边框线外侧；表头单元格不显示手柄；手柄圆角调小。
2. 行/列插入交互重做：鼠标滑入表格时在上边框外（列间）与左边框外（行间）显示小圆点；悬停圆点变为现行"+"图标；点击展开插入/删除操作。
3. 弹出菜单显示修复：手柄/上下文菜单不再被祖先容器裁剪，贴边时翻转或夹取，完整可见。
4. 单元格内 "/" 菜单：输入 "/" 就地弹出统一插入菜单；焦点保持在单元格；过滤词来自单元格；选中后插入到该单元格内；Esc 关闭无 "/" 残留；不再出现「表格外累积多个 /」「选中后插到表格外」。
5. 分栏内容区：接入统一 "/" 菜单 + "+" 新增手柄，插入落点在分栏内容文本。
6. 高亮块内容区：接入统一 "/" 菜单（替代独立片段菜单，片段能力保留为注册表命令）+ "+" 新增手柄，插入落点在内容区光标处。
7. 死代码清理：删除无调用方的表格尾块定位/全角斜杠请求函数；修正菜单夹取基准注释与实现不一致。

## Why（为什么）

- 手柄是表格高频操作入口，图标/位置/圆角三处不一致让入口不可预期，表头手柄造成误触。
- 行/列插入入口藏在边界内侧气泡里，没有外部指示，插入成本高、可发现性差。
- 菜单被裁剪直接挡住功能（菜单项看不全 = 功能不存在）。
- 单元格内 "/" 是坏体验重灾区：焦点被抢、字符累积、插入落点错误——表格内快速插入当前实际不可用。
- 分栏/高亮块是块级内容容器，「能输入内容的地方都该有 + 手柄与 / 菜单」是统一的编辑心智模型；高亮块用独立菜单破坏了统一性。

## Scope（范围）

- 涉及表面：MD 编辑态表格 widget（手柄/边界/菜单）、分栏 widget（内容区编辑）、高亮块 widget（内容区编辑）、斜杠菜单（触发上下文/定位/裁剪/命令注册表）、相关 editor.css。
- 影响既有规格：`editing` E-6（表格单元格编辑、斜杠插入）、E-7（编排层交互契约）、E-14（浮层定位）。
- 数据面：无（不新增配置字段、不改图标注册表数据、不新增菜单数据文件——图标沿用既有注册表）。

## Non-goals（不做）

- 表格列宽拖拽、排序、合并单元格。
- 阅读态表格交互。
- 触屏适配。
- 引用块（正文仍是文档文本，斜杠已正常）。
- 高亮块标题输入框的菜单（无块插入语义）。
- 不新增配置项。
