# requirements — editor-surface-batch16

> Spec issue: https://github.com/jianxi-dev/clairis/issues/695
> 生效日期：2026-11-13
> 来源：用户 2026-11-13 补充修复清单（21 条）+ 两条视频测试缺陷。

## What（做什么）

1. 视频测试基线：`video-transform` 旋转断言按 #518 验收改为逆时针 90°；`video-playlist-memory` 删除固定 sleep，改事件驱动等待。
2. 转换手柄菜单：指针从手柄滑入下级菜单后再上移，菜单不关闭。
3. 图片块与表格块的转换菜单按指针横向位置定位，与标题/文本块一致。
4. 按住转换手柄可把当前块移动到同文档其它位置，落点有插入指示。
5. 全屏下指针滑入按钮区即显示按钮栏与浮层，与未全屏一致。
6. 预览态引用块宽度等于文本块宽度。
7. 编辑态引用块与代码块宽度等于文本块宽度。
8. 编辑态与预览态的标题、正文字体与 md-bundle 预览一致。
9. 编辑态行内/块级公式可见；围栏代码块按语言高亮。
10. 预览态与编辑态统一用 Pele 渲染 mermaid。
11. 插入菜单·表格：指针滑入任意格都选中左上第一格到指针的矩形，滑动流畅，单击插入。
12. 插入菜单·分栏：5 个横向栏目，指针从左横向滑入选中，单击插入。
13. Markdown 打印，版式适合日常办公纸张。
14. 图片描述：工具条按钮在图片下方展开可编辑描述，提交后保存并回显；图标为文本+笔。
15. 图片裁剪：消除裁剪后下方长空白与 `k<!--w=811—>` 泄漏；修正左上角方向；控制点显示裁剪标识与方向光标；二次裁剪按新区域保存。
16. 图片对齐：编辑态新建图片默认居中，工具条高亮当前对齐。
17. 图片双击预览：无极缩放、超界拖动、捏合、旋转、下载、恢复原始尺寸。
18. 图片下两角同为弧形，半径加大。
19. 图片转换手柄使用图片图标；菜单下方含缩进与对齐、剪切、复制、删除。
20. 单击选中图片后拖动锚点调整尺寸，不进入裁剪。
21. 任务列表方框图标改为方框内带打勾。

## Why（为什么）

- 两条视频测试是当前全量套件里唯一的稳定红与已知 flaky；它们让「全绿」不能作为交付信号，必须先修。
- 转换手柄菜单回移消失、菜单不跟随指针属于高频操作的中断；手柄不能拖块使重排只能剪切粘贴。
- 全屏下按钮不浮现，用户在观看态无法调参。
- 引用块/代码块比正文窄，破坏两态同貌（E-8 已要求同貌，实现未达）。
- 字体与 md-bundle 不一致，同一份文档在两个产品里观感不同。
- 编辑态看不到公式、代码不高亮，等于编辑态不能作为写作态。
- Pele 两态不统一，编辑时看不到最终图。
- 表格/分栏插入的选中逻辑与手感不达标，插入成本高。
- 缺打印，办公场景无法落纸。
- 图片类多条是 `image-block-editing` 归档后的残留缺陷：描述不落盘、裁剪写回泄漏标记、二次裁剪失效、双击预览能力缺失。用户明确要求同时给出「为何测试没测出」的答案。

## Scope（范围）

- 涉及表面：MD 编辑态装饰与编排（块手柄、块菜单、插入菜单、表格/分栏、代码、公式、图表、引用）、MD 预览渲染与排版、图片块（描述/裁剪/对齐/缩放/预览浮层/圆角/手柄）、任务列表图标、打印、视频播放器全屏与两条 video e2e。
- 影响既有规格：`editing`（E-8/E-11/E-17 及新增图片/插入菜单条款）、`reading`（预览宽度、字体、图片预览）、`diagram-rendering`（两态同源）、`export`（打印）。
- 数据面：不新增配置字段；描述沿用现有图片属性语法。

## Non-goals（不做）

- 不新增配置项，不改配置快照回滚。
- 不改 pane 树持久化、场景路由、editor remount 约束。
- 不更换图表引擎，不引入新运行时依赖。
- 不改既有 HTML/Word/PDF/mdpkg 导出契约，只新增打印。
- 不做跨文档拖块（只支持同文档内移动）。
