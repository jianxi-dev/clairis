# 渐晰 vs Obsidian 竞品深度分析

> 基于 CORE-REQUIREMENTS v2.2 逐条拆解
> 2026-07-07

***

## 一、市场生存空间评估

### 1.1 赛道定位

渐晰不是"又一个笔记软件"，是 **阅读写作陪伴工具**。两个赛道的本质差异：

| 维度     | 笔记软件赛道                     | 阅读写作陪伴赛道                         |
| ------ | -------------------------- | -------------------------------- |
| 代表产品   | Obsidian / Notion / Logseq | Typora / Bear / Drafts / Ulysses |
| 核心心智   | 知识管理 / 第二大脑                | 沉浸创作 / 心流体验                      |
| 用户决策因素 | 功能多不多、能不能同步                | 写着舒不舒服、够不够美                      |
| 付费意愿   | 低（插件能解决就不付）                | 高（为体验付费）                         |
| 差异化空间  | 红海，功能同质化严重                 | 蓝海，体验差异大                         |

**结论：渐晰应打"阅读写作陪伴"而非"笔记工具"。** 跟 Obsidian 比功能多简直是找死，但比心流体验和仪式感，是另一条赛道。

### 1.2 目标市场规模

核心用户画像（来自需求文档 1.4）：

* 学习者 40% — 需要沉浸式长文阅读 + 读书笔记

* 写作者 30% — 需要专注创作环境 + 仪式感进入状态

* 成长者 20% — 需要目标追踪 + 习惯养成 + 正向反馈

* 灵感寻求者 10% — 需要秒开记录 + 万花筒思维激发

这群人的典型场景：

* 晨间日记 / 每日复盘

* 读书批注 / 论文阅读

* 公众号/长文写作

* 知识卡片积累

**估算可触达市场：** 中文创作者约 5000 万，其中愿意为写作工具付费的约 5-10%（250-500 万人）。即使 1% 渗透，也是 5 万付费用户。

### 1.3 当前形势窗口

* Obsidian 增长放缓（巨头已稳定），但新进入者仍有机会做差异化

* AI 功能成为新分水岭：Obsidian 靠 plugin 实现，体验割裂；渐晰原生集成是优势

* 国产写作软件（熊掌记、思源笔记等）在体验/美学上参差不齐 — 渐晰有机会在设计感上完胜

* 国内市场缺乏"仪式感 + 沉浸 + 美学"的精品写作工具

## 二、渐晰 vs Obsidian 逐维度对比

### 2.1 优势（渐晰能赢的）

| 维度         | 渐晰                          | Obsidian                           |
| ---------- | --------------------------- | ---------------------------------- |
| **开箱即用体验** | 安装即用，无需配置主题/插件              | 新手打开一脸懵，装一堆插件才好用                   |
| **沉浸阅读体验** | 宣纸/护眼/古信笺主题，专为长文阅读优化        | 默认白底黑字，阅读体验平平                      |
| **仪式感系统**  | 展卷/收卷/烛光/雨天 — 独特情绪价值        | 完全无                                |
| **美学品质**   | Literata/Caveat 字体、暗色、留白    | 默认素朴，美化需折腾主题                       |
| **AI 集成度** | 原生 AI 对话+润色+翻译+提问，右侧悬浮/嵌入   | 靠 Text Generator/ Copilot 插件，配置门槛高 |
| **灵感记录**   | Cmd+Shift+. 全局秒开 <200ms，零等待 | Quick Capture 插件需配置、有延迟            |
| **面板系统**   | 悬浮+嵌入停靠+场景组合，拖拽自由           | 靠 Workspace/Styled Panel 等插件拼凑     |
| **主画布模式**  | 文档/灵感/磁场/书桌四模式，心智清晰         | 全部混在"编辑器"里                         |
| **性能节奏**   | 三级加载，Intel Mac <900ms TTI   | 启动较慢，插件多了更慢                        |
| **中文原生**   | 从需求到设计都为中文创作                | 英文优先，中文体验靠社区                       |

### 2.2 劣势（Obsidian 碾压的）

| 维度        | Obsidian                           | 渐晰                      |
| --------- | ---------------------------------- | ----------------------- |
| **插件生态**  | 1000+ 插件，几乎什么都能做                   | 零阶段不考虑插件系统              |
| **主题生态**  | 200+ 社区主题，完全换肤                     | 内置主题有限                  |
| **图谱视图**  | 双向链接 + 关系图，第二大心智                   | 磁场模式 P2 才补，且是"语义关联"非真图谱 |
| **社区规模**  | 庞大社区 + Discord + 论坛 + YouTuber 推荐  | 从零开始                    |
| **免费**    | 个人版完全免费，无功能阉割                      | P1 起收费（仪式+AI）           |
| **跨平台**   | Win/Mac/Linux/Mobile 全平台           | M 阶段仅 Mac，P2 才有移动端      |
| **导入/导出** | 开放 Markdown + frontmatter + 双向链接标准 | Markdown 兼容但未定义导入流程     |
| **协作**    | Sync 付费同步，Share 发布                 | P2 才考虑，远期团队             |
| **可定制性**  | CSS 片段 + 插件 API 改一切                | 封闭产品，所有功能由你提供           |
| **成熟度**   | 5+ 年迭代，稳定可靠                        | MVP 阶段，大量功能占位待补         |

### 2.3 决定性差异（真正拉开差距的点）

**Obsidian 的哲学**：给你一块画布，自己画

* 用户负责折腾，折腾好了很强

* 失败体验：装了 50 个插件，到处冲突，不知道卸哪个

* 心智负担：永远在"配置"而不是"写作"

**渐晰的哲学**：给你一个空间，直接写

* 核心体验出厂即最佳，不需要用户配置

* 成功体验：打开就好看，打字就舒服，写了就有正向反馈

* 心智负担：零

**这个差异，本质上不是功能差异，是产品设计哲学的差异。**

## 三、Obsidian 插件模式 vs 渐晰架构深度对比

### 3.1 Obsidian 插件模式确实更容易"扩展功能"

这是事实，要承认。插件模式的好处：

* 边际成本为零（社区写插件，官方不用养人）

* 总有人想到你没想到的功能

* 用户可以只装自己需要的，保持轻量

* 生态锁定效应：用久了装了一堆插件，迁移成本高

### 3.2 但插件模式有渐晰不需要付出的代价

| 代价    | Obsidian             | 渐晰（封闭）     |
| ----- | -------------------- | ---------- |
| 体验一致性 | 插件 A 和插件 B 可能视觉/交互冲突 | 全套 UI 设计统一 |
| 性能    | 插件越多启动越慢             | 严格控制加载时序   |
| 兼容性   | Obsidian 升级导致插件挂     | 你控制的就不会挂   |
| 质量下限  | 插件质量参差不齐             | 全部自有，品质可控  |
| 心智负担  | 用户需要判断"装哪个"          | 不需要判断      |
| 审美    | 美化需要自己找主题+调 CSS      | 开箱即美       |
| 新手友好度 | 配置地狱                 | 开箱即用       |

### 3.3 渐晰该如何处理"扩展性"问题

**核心策略：不是不扩展，是"官方精选"而非"社区开放"。**

建议路径：

**Phase P1（现在考虑的）：** 封闭，但做足官方功能

* AI 对话 + 翻译 + 润色 + 提问（已规划）

* 悬停面板系统（已规划）

* 10+ 优质模板（仪式感配套）

**Phase P2：** 模板 + 灵感分类体系 + 微插件

* 模板市场：信笺模板、创作模板、学习模板

* 灵感分类预设：晨间日记/读书笔记/灵感卡片

* 微插件（可选）：字数目标、错别字自检、音乐接入

* 这些"微插件"由官方提供，不是开放 API

**远期（如果有必要）：** 逐步开放

* 当产品有 10 万+ 用户时

* 当维护成本需要社区分担时

* 但始终保持**官方体验 > 插件体验**

**关键判断：渐晰应该做"精品餐厅"而非"美食广场"。** 餐厅自己把控每道菜的品质，用户体验一致性高；美食广场什么都有但参差不齐。

## 四、如何让潜在客户更青睐渐晰

### 4.1 定位：不要讲功能，讲"感觉"

用户不会因为"悬浮面板"选渐晰，会因为"每次打开渐晰那一刻的仪式感让我觉得'该写了'"而选。

**核心叙事（一句话）：** 渐晰 — 一个让你想坐下来写的空间。

**支撑点：**

1. 打开应用 = 进入仪式感状态（展卷仪式）
2. 打字时眼前舒服（Literata/Caveat、暗色、留白、字号舒适）
3. 灵感来了零延迟记录（Cmd+Shift+. 秒开）
4. 读完有收卷的完成感（收卷仪式 + 微型总结）
5. 不需要配置任何东西就能这么美

### 4.2 具体获客策略

**策略 1：视频传播（最高优先级）**

Obsidian 靠教程视频（Thomas Frank、Nicole van der Hoeven 等）带火。
渐晰需要的是**感觉视频**：不是"如何配置"，而是**15秒的开卷动画 + 打字音效 + 暖黄烛光**。

传播载体：小红书、即刻、抖音、B站
内容形式：不讲解，纯展示使用场景
目标：让潜在用户看完后说"我想要这种感觉"

**策略 2：中文创作者圈子渗透**

* 给中文 newsletter 作者免费送专业版

* 给小众写作社群赞助/合作

* 在即刻、小红书、作者论坛做口碑

**策略 3：Obsidian 迁移路径（关键）**

做一键从 Obsidian Vault 导入的功能：

* 保留 Markdown 文件结构

* 保留 frontmatter（tags 字段的映射到渐晰的灵感标签）

* 双向链接映射到渐晰磁场模式

**关键洞察：** Obsidian 用户的痛点 — "我装了 100 个插件但还是没进入写作状态"。给他们一个理由离开：不是功能更多，是更舒服。

**策略 4：AI 差异化卖点**

Obsidian 的 AI 是外挂（Text Generator / Copilot / Smart Connections），配置门槛高。
渐晰的 AI 是内置：

* Cmd+Shift+A 直接右边出来

* 默认本地 Ollama（隐私保护）

* AI 主动提问 / 润色 / 摘要直接选中文本右键即可

**策略 5：仪式感作为社交货币**

展卷动画是可截图/可录屏的传播物。让用户觉得：

* 用渐晰 = 我是"认真对待写作"的人,可以加上个人照片

* 开卷动画可以当朋友圈展示

* 收卷的完成感截图可以分享，可以加上个人各种表情的照片

考虑下：是否需要添加一个个人表情夸张的照片功能，通过照片系统自动生成各种表情、动作图。

### 4.3 商业模式避坑

需求文档 §9.1 的版本分层策略整体 OK，但有一个风险：

**风险：P1 仅靠仪式+AI 收费，可能付费转化率极低**

* 仪式感 — 有人认为重要，有人认为花哨

* AI — 目前免费替代品多（ChatGPT、Claude）

**建议调整：**

* P1 的付费墙应该更明确：**"体验升级套餐"**，不是功能解锁

* 把"悬浮面板 + 嵌入停靠"也放 P1 付费版 — 这是效率工具，理性用户也肯买

* AI 做分层：本地 AI 免费，云端 AI 按量收费或包月

* P2 的"知识网络 + 成长系统"才是真正的理性付费理由

**核心：用户为"更好的感觉"付费（感性）+ 为"更高效的工具"付费（理性），两条腿缺一不可。**

## 五、核心风险与应对

### 5.1 最大风险：功能占位 → 始终"够用但不出彩"

需求文档里有大量"占位，需补交互规格"：

* 磁场模式交互规格（P1 必须补）

* 万花筒交互规格（P1 必须补）

* 书桌空间记忆导航规格（P2 必须补）

如果这些占位一直补不上，渐晰就变成了"好看的 Markdown 编辑器"，跟 Typora / Bear / Ulysses 没有本质区别。

**应对：P1 阶段必须把这 4 个交互规格补齐，否则产品没有差异化锚点。**

* 这是优先级最高的事

### 5.2 第二大风险：收费时机过早

如果 P1 功能还没让用户形成习惯就开始收费，会直接流失。

* 免费体验版（Phase M/R）必须有足够的价值让用户养成使用习惯

* 付费点应该在"升级"而非"解锁基础功能"

### 5.3 第三大风险：Obsidian 推出类似功能

Obsidian 已经有几十人在写"仪式/主题/美化"相关插件，社区需求是真实的。

* 渐晰的护城河不是功能，是**体验品质**和**集成度**

* 但需要足够快建立品牌认知，让"仪式感写作"这个心智与渐晰绑定

***

## 六、一句话战略总结

> 渐晰不能也不应该跟 Obsidian 比功能多。
> 渐晰要赢的是：**那些觉得 Obsidian 太重、太折腾、太丑、太没感觉的人。**
> 给这些人一个"打开就想写、写了就舒服、写完有完成感"的空间。
> 这是 Obsidian 永远给不了的——因为它的基因是"开放"，而渐晰的基因是"体验"。
