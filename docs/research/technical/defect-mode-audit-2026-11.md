# 近 30 天缺陷失败模式抽样审计（2026-11）

> 方法与口径见 §1；本文是 `docs/research/technical/oracle-gap-test-strategy.md` v2 §2.1 要求的 P0 前置动作（issue #1443）。
> 单人标注（Sisyphus，2026-11-25），证据一律引自票面原句；局限见 §5。

## 1. 方法

- 样本框：`label:bug created:>=2026-10-25` 全量 110 张（gh issue list）。
- 分层：按标题关键词映射到模块域（媒体/属性面板/编辑与解析/shell 窗口主题/轮盘浮层/测试与基建/规格漂移），比例抽样 25 张。
- 标注口径（策略文档 §2.1 六类 + 1 个对照类）：
  - `no-test`：相关行为无任何测试
  - `not-run`：有测试，但不在交付链路执行（CI/verify），红灯无人看见
  - `weak-oracle`：有测试且执行，但断言是相对/代理/循环判断，抓不住缺陷
  - `stale-oracle`：真值陈旧或规格/实现/测试三方分叉
  - `spec-ambiguity`：规格本身未定义关键语义
  - `env`：真机/OS/时序差异，headless 无法复现
  - `caught`（对照）：既有门禁在正确层级抓到了——用于证明「测试有用」的边界
- 每张标注附票面证据短语；标注只看票面（body），不凭标题猜。

## 4. 校准结论

1. **oracle-gap 修正为「重要成因之一，且与 no-test 同源」**：真值缺失的三种形态（无测试 / 弱断言 / 真值分叉）合计 17/25。策略文档的因果表述（v2 §0.1）与此一致，无需再降级。
2. **not-run 被系统性低估**：25 张里只有 2 张直接归 not-run，但这是因为「红灯存在」必须有人跑过才发现——e2e 全量与 cargo test 不在 CI（#1441 已修），未跑过的红灯不可见。#152 与 #1434 都是「信号存在、无人路由」。CI 优先的判断被审计支持。
3. **正向对照证明门禁在正确层级是有效的**：#309（console errors 真值）、#343（变更门 e2e）都在既有门禁下被抓住。问题从来不是「测试没用」，而是真值不在用户看得到的那一层。
4. **env 类 12%（3/25）支持 DQ-9 双路径分级**：#944/#1112/#548 都属 headless 原理上抓不到的类；这类票的验收必须含真机路径，不该指望 CI。
5. **no-test（36%）是对策分水岭**：为无测试行为「补测试」不可行（行为本身无真值可断言）；对策是策略文档的 oracle 字段 + 逐域真值建设（契约/golden/状态转移表），而不是扩大覆盖率统计。

## 5. 局限

- 单人标注，未做双人一致性校验；争议项（#1034 归 spec-ambiguity 还是 weak-oracle）按主因归类。
- 分层按标题关键词，模块映射有噪声（#1434 同时是测试与规格问题，按主因 stale-oracle 归类）。
- 票面截断 900 字符；如需复核，按票号回溯全文。
- 样本只含 `label:bug`；无标签的隐性缺陷不在框内。
- 复核建议：抽 5 张做双人盲标，口径一致率 ≥80% 再扩量。
