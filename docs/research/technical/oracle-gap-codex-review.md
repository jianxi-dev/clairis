# 《测试为何抓不到明显缺陷》Codex 评审记录与处置

> 评审对象：`docs/research/technical/oracle-gap-test-strategy.md`（draft）
> 评审方式：`codex exec -s read-only`，只读沙箱，禁改文件
> 评审模型：`ccs-longcat/LongCat-2.5`（Codex CLI 默认 provider `ccs-ai-seeyon/glm-5.3-flash` 返回 404，改用同一 model catalog 中可用项；provider 恢复后建议用默认模型复跑一轮）
> 时间：2026-11-25（Asia/Shanghai）

## 1. 结论摘要

Codex 判定 **APPROVE WITH CHANGES**。核心异议是「因果框定有偏」：文档把问题写成「真值缺位（oracle gap）」，但它认为更直接、且已被事实支持的解释是「**现有测试根本没接进 CI**（cargo test 与全部 e2e 都不在 CI）」，以及「真值陈旧/分叉」这一类与「真值缺位」不同的失败。它要求先做缺陷分类审计再定论，并把「接现有测试进 CI」提为 P0。

我接受其中大部分：因果表述需要降级为「多因并列」，并把「接 CI」提为 P0-0；非 UI 部分确实仍偏 UI 形状；变异语料需要试点与判定口径。有一处 Codex 的事实链需要纠正（见 §4）。

## 2. Codex 原始评审（逐字）

```text
VERDICT: APPROVE WITH CHANGES

BLOCKING ISSUES:
1. 「根因不是测试数量不足，而是验收缺少独立真值（oracle）」 -> 未对 110 张 bug 做失败模式分类，竞解释（套件未在 CI 执行、规格歧义、需求 churn、覆盖空洞、批量发布）均未量化排除；先做 20–30 张分层抽查审计，给出「无覆盖/oracle 弱/oracle 陈旧/环境」分布再定论。
2. 「CI 实际运行 tsc --noEmit + vitest --coverage + CSS manifest」 -> 给定事实是 cargo test 与全部 e2e 都不在 CI（verify.sh 仅本地），这本身足以解释「测绿却坏」；文档把它降为第五项指标，应提为 P0 根因与修复（接现有测试进 CI），并据此重写摘要因果。
3. 「#1434 锚点 36 vs 实现 32」 -> 已验证根因是提交 8547e4ce 同时改实现与设计规格却未同步 e2e fixture，属「真值陈旧/变更传播」而非「真值缺位」；当 oracle gap 样本会混淆两类，且变异语料防不住，需单列锚点单一来源修复。
4. 「把每张历史缺陷的根因还原成一个最小『语义突变』」 -> 文本 replace 补丁随源码漂移会打不上，无适用性校验/维护责任人/漂移预算，存活率会把「补丁失效」误计为「测试弱」；先做 15 条试点并定义 applicable/survived/killed 判定与重写机制。
5. 「非 UI 的病灶相同，但真值形态不同」 -> 非 UI 只有断言没有资源：golden 语料、状态转移表都在 P2，且未给出 110 张里非 UI 占比，计划仍呈 UI 形状；先统计非 UI 份额，并把一个模块的解析 golden 语料提到 P0/P1 作对照。
6. 「变异存活率……首季 <30%，逐季下降」 -> 无基线、无口径即定目标，且语料锁定会诱导针对已知 mutant 写过拟合测试；先跑基线得当前存活率，目标由基线导出，并禁止按语料反推测试。
7. 「缺陷复发率……按标签+标题自动分类」+「陈旧锚点数」 -> 标题关键词分类自承粗糙，后者当前无任何采集数据源；指标不可落地即剧场，需先交付可复现采集脚本，否则删除或降级为季度手工审计。
8. 「测试作者 ≠ 实现作者」 -> 单人+agent 工作流未定义触发条件、交接物、仲裁人与成本上限，且与仓库「risk-medium 执行 agent 直接合并」的自动接力规则冲突；限定 risk-high 强制、产出独立断言清单、冲突以规格为准。

NON-BLOCKING ISSUES:
1. 「唯一能统一回答『测试能不能抓明显错误』的手段」 -> 过强：变异测试只度量已知突变的杀伤，无法发现无覆盖路径；改为「目前最直接的跨域强度仪器」。
2. 「缺失或非法 → 禁止开工」 -> 需给出 oracle 枚举值、票面模板与校验脚本落点，并留灰度期，否则变成卡开工的纸面字段。
3. 「每张 bug 留一条可执行用例并带票号」 -> 成本与用例膨胀未估，易退化为「为修复码测试」；改为同环节复发 ≥2 才强制。
4. 「配 CMD_FIDELITY / CMD_VISUAL_BASELINE，或把未配置显式改成失败」 -> 工具链不可用时会全红堵 CI；补迁移开关与降级公告路径。
5. 「真实命令与 tauri-mock 跑同一批用例」 -> 窗口/剪贴板/全屏在 headless CI 易碎，#944 类难稳定复现；先只做配置/文件类序列化契约对拍，OS 效应列例外清单。
6. 「先人工抽查 20 条」 -> 抽查应在建库前做，用于校准 mutant 质量与分类口径，而非建库后验货。
7. 「PR 抽样 10–15 条（按 diff 命中模块选取）」 -> 抽样口径未定义，结果不可复现；写明模块选择与命中判定规则。
8. §12 未回应批量发布节奏与规格歧义两条竞解释 -> 至少各一段，明确承认尚未排除的部分。

MISSING CONTENT:
- 110 张 bug 的失败模式分类分布（核心证据）。
- 「把现有 e2e + cargo test 接进 CI」与建语料的成本/收益对比。
- 变异语料的维护责任、适用性校验与淘汰机制。
- 非 UI 侧具体交付物与试点模块。
- owner、时间盒、回滚/退出标准。
- 各指标采集脚本的落地清单。
- 与自动接力合并规则的衔接条款。
- oracle 字段与 fail-closed 门禁的灰度/豁免机制。

EFFORT/RISK NOTES:
- 「一次性 2–3 人日」偏乐观（OPINION）：110 条根因还原+补丁+期望红映射+运行器+夜间调度更接近 1–2 周，另有持续维护税。
- 契约 round-trip 里窗口/剪贴板风险最高，建议先缩到配置/文件两类。
- 新 CI 步骤若无 flaky 隔离，团队会倾向关掉，反而强化「静默跳过」。
- 语料锁定后，语料外的新缺陷不会反映在指标上，别当唯一仪表盘。
- 「oracle 覆盖率 100%」只证明字段存在，需搭配抽查才防作弊。

ONE-LINE SUMMARY: 方向正确但因果框定有偏——「测试未接入 CI/真值陈旧」被写成「真值缺位」，需先用缺陷分类审计验证、把现有测试接进 CI 提为 P0，再谈变异语料与指标。
```

## 3. 我的处置

| # | 处置 | 理由 |
|---|---|---|
| B1 分类审计 | 采纳 | 110 张只有总量、没有失败模式分布，因果确实只能算工作假设。修订前置动作：20–30 张按 module 分层抽样，标注「无覆盖 / oracle 弱 / 真值陈旧 / 环境或 CI / 规格歧义」。 |
| B2 接 CI | 采纳（提为 P0-0） | 这是比 oracle 更前置的解释：`cargo test` 与 e2e 都不在 CI，测试绿只能证明「跑到的部分绿」。文档摘要的因果顺序要改，指标表里第五项改成第一优先级动作。 |
| B3 #1434 归类 | 部分采纳 + 事实纠正 | 同意它不属于「真值缺位」；但 Codex 说「8547e4ce 同时改了设计规格」不准确：该提交把 `MENU_ROW_HEIGHT` 改为 32、改了 design-system 的圆角表，**没有改** `openspec/specs/editing/spec.md` 的 E-7「行高 36px」条款。准确说法是「实现改了、主规格没改、e2e fixture 仍按规格断言」——真值三方分叉，且能让红灯被看见的唯一出口（e2e）不在 CI。 |
| B4 mutant 漂移 | 采纳 | 试点 15 条，先定义 `applicable / killed / survived` 三态与重写责任；不把「补丁打不上」计入存活。 |
| B5 非 UI 仍偏 UI | 部分采纳 | 66/110 是按标题过滤的粗下界，不能当分类结果；修订时以 B1 审计替换。同时把一个非 UI 试点（配置/文件序列化契约）从 P2 提到 P1。 |
| B6 指标无基线 | 采纳 | 先测基线再定目标；禁止按语料反推测试。 |
| B7 指标不可采集 | 部分采纳 | 「陈旧锚点数」先写采集脚本，写不出就删；「复发率」保留但需 module+类别聚合脚本。 |
| B8 作者分离 | 采纳 | 限 risk-high 强制；risk-medium 用变异语料兜底，避免与自动接力规则冲突。 |
| N1–N8 | 全部采纳或部分采纳 | 措辞降级（「唯一」→「最直接」）、oracle 枚举与灰度、回归语料改「复发 ≥2 强制」、CMD_FIDELITY 灰度、OS 效应例外、抽查先于建库、抽样口径写死、补两条竞解释。 |

## 4. 评审中被我纠正的点

- **#1434 的事实链**（Codex B3）：当前事实是 `src/editors/orchestration/menu-metrics.ts` 的 `MENU_ROW_HEIGHT = 32`（8547e4ce 引入）、`openspec/specs/editing/spec.md:128` 仍写「块菜单 176px 宽、行高 36px」、`e2e/fixtures/editor-anchors.ts:18` 仍断言 36。即规格与实现已经分叉，测试报的是真红；问题是这条红信号只在本地可见。结论：新增失败类别「真值分叉 / 红灯无人路由」，它和「真值缺位」「真值陈旧」并列，变异语料不能替代。
- **非 UI 占比**（Codex B5）：66/110 是标题关键词过滤的下界，不是分类；在审计完成前，文档不应把该数字当证据强度使用。

```text
7. “测试作者 ≠ 实现作者……做不到则以变异语料兜底” -> 变异语料不能替代独立评审；要求留下独立断言会话记录，变异语料只作补充信号。

1. “只做精选语料（110 条约）” -> 110 条历史 bug 不一定都适合建模；先定义入选标准，排除重复、环境性、需求误判类问题。

3. “真实命令与 tauri-mock 跑同一批用例” -> 需说明通过生成 TS 类型 / JSON fixture / 单独集成测试实现，避免伪装成同一端到端运行。
4. “底座用结构/几何断言，像素只做兜底” -> 需定义跨平台容差、更新流程和基准图失效告警，否则会制造脆弱测试。
5. “五项指标进看板” -> 加入防 Goodhart 设计，例如分层追踪、按失败类别归一化，而不是只盯总存活率下降。
6. “锚点单一来源” -> 需要说明源文件、生成物、测试常量的所有权和变更路径，否则双写只是转移。
7. “oracle 字段……禁止写执行者判断” -> 枚举本身可被滥填；机检只能检查合法性，需加抽查和失效回收机制。
```

### 7.1 与第一轮的差异

| 维度 | 第一轮（LongCat） | 第二轮（默认 glm） | 处理 |
|---|---|---|---|
| 因果强度 | 要求先做分类审计 | 直接判「因果过强」，要求改写成「重要成因之一」 | 采纳，摘要改写 |
| 竞因 | 列为「未量化排除」 | 点名需求/设计漂移、批量规模、规格模糊、工作流强度，要求量化对比 | 采纳，新增 §2.1 |
| 变异语料定位 | 质疑可维护性 | 明确指出变异不是独立真值，须拆成「强度审计」与「oracle 建设」 | 采纳，§7 重写 |
| 基准图 vs 变异 | 未涉及 | 指出「人工看基准图会漏」不成立，基准图会直接暴露缺数字 | 采纳（原文表述有误），删除绝对化说法 |
| 顺序 | CI 提为 P0 | P0 先做机械门禁，变异降到 P1 精选 20–30 条 | 采纳，§11 重排 |
| 作者分离 | 与自动接力冲突 | 变异不能替代独立评审，须留独立断言会话记录 | 采纳，§9 收紧 |
| 指标防作弊 | 要求采集脚本 | 追加 Goodhart 与人工确认记录 | 采纳，§8 补 |

两轮共同结论（按一致性加权）：**因果要收窄为多因、机械门禁优先、变异语料降级为 P1 试点、真值必须有独立确认来源。** 本文档已按此修订为 v2；第一轮 Codex 对 #1434 的事实链判断仍以 §4 的核实结论为准。
