# 测试为何抓不到明显缺陷：真值缺位（Oracle Gap）诊断与整改提案

> 状态：draft（v2，已按两轮 Codex 评审修订）。数据采集于 2026-11-25（Asia/Shanghai）。
> 本文只做诊断与提案，不含代码改动。评审记录见 `oracle-gap-codex-review.md`。

## 0. 摘要

1. 近期用户可见缺陷高频出现，但**测试全绿**。经两轮独立评审，本文不再把单一原因写成根因：候选成因至少四类——（a）现有测试未接入 CI（`cargo test` 与全部 e2e 都不在 CI）、（b）验收缺独立真值（oracle 缺位，只有相对断言）、（c）真值陈旧或分叉（规格、实现、测试三方不一致）、（d）规格歧义与批量交付。本文以（b）为主线，其余三类不排除，先用抽样审计分级。
2. 本条在 UI 与非 UI 上都成立，只是真值形态不同：UI 需要基准图/几何规格；序列化需要契约对拍；解析需要固定语料；异步需要状态转移表；性能需要基线数字。
3. 既有 18 条质量门禁（QG-1..9 / DQ-1..9）没有拦住，是因为它们靠**执行者自评**，没有可测量仪器，也没有机检。近 30 天 110 张 bug 与这个判断一致，但相关不等于因果，需 §2.1 的抽样审计。
4. 提议的顺序是：**先做便宜且已明确失效的机械门禁**（真实测试接入 CI、未配置核验即失败、三方一致性机检），再用**精选**变异语料度量测试强度。变异语料只能量化对已枚举突变的覆盖强度，**不是独立真值**，也不能替代基准图与独立评审。
5. 配套五项可测量指标 + 三条流程硬约束。落地顺序见 §11。

## 1. 触发案例（含自我证伪）

缺陷 `#1433`：有序列表图标与无序列表图标看起来一样。

- 上一张票 `#1390` 只修了**映射**（`1.` / `1)` 都识别为有序），映射确实正确，单测和 e2e 都过。
- 真正的问题是**字形本身**：`OrderListOutlined` 是「三条横线 + 三个 1×2 小竖块」，`DisorderListOutlined` 是「三条横线 + 三个 2×2 方块」，名字不同、画出来同构。
- 修复把 `OrderListOutlined` 改为 `ui/icons` 的规范编号字形（描边 1.7），四处测试补充字形层断言。

**自我证伪**：修完之后，用户指出「只画了 1 和 2，没有 3」。核对路径：横线在 y=7/12/17 三条，数字只有两枚（「1」在 y≈4.8–8，「2」在 y≈11.4–15.2），第三行纯横线。而我写的断言是「左缘标记 ≥2 种形状」——它恰好允许「少一个数字」。

这说明：**我的修复测试也是同一类失败**。为了让旧字形变红，我把阈值调到「正好能红」；测试被优化成「能证明我改了」，不是「能证明它对了」。这条案例是 §3 根因模型最直接的样本。

### 2.1 竞因与抽样审计（评审后新增）

上述数据只能说明「问题频繁」，不能单独证明「oracle 缺位是主因」。必须先做一次低成本审计，再决定投入顺序。

**候选成因**：

| 成因 | 可观测信号 | 本文是否已量化 |
|---|---|---|
| 测试未接入 CI | `cargo test` 与 e2e 均不在 CI；未配置步骤静默跳过 | 是（事实） |
| 规格/实现/测试三方分叉 | `#1434`：主规格 36px、实现 32px、fixture 36px | 是（个案） |
| 规格歧义 / 需求 churn | 同一需求反复开票、验收条款含糊 | 否 |
| 批量交付规模 | 单 PR 承载 4–28 项用户可见变更 | 否 |
| 覆盖空洞 | 某模块零测试 | 否 |
| oracle 缺位（本文主线） | 断言只比旧实现/mock/代理属性 | 部分 |

**审计口径（P0 前置动作）**：从近 30 天 110 张 bug 中按 module 分层抽 20–30 张，每张标注一项：

1. `no-test`：相关行为无测试
2. `not-run`：有测试但不在交付链路执行（CI/e2e）
3. `weak-oracle`：有测试且执行，但断言是相对/代理判断
4. `stale-oracle`：真值陈旧或规格/实现/测试分叉
5. `spec-ambiguity`：规格本身未定义清楚
6. `env`：环境或真机差异

产出分布后，再校准本文主线占比；分布若显示 `not-run` 占大头，优先修 CI 而不是建语料。

## 3. 根因模型：三类伪真值

验收断言需要回答「结果对不对」。没有真值时，执行者会用以下三类替代物，它们都能让测试变绿：

| 伪真值 | 典型写法 | 为什么必然漏 |
|---|---|---|
| 与旧实现对照 | 「新结果 ≠ 旧结果」「≥2 种形状」 | 只能证明有变化，不能证明变化正确；阈值由执行者临时发明 |
| 与 mock 对照 | 断言 `tauri-mock` 的返回、注入的 store 状态 | mock 与真实 Rust 命令/真实文件系统无对拍，系统性偏差 |
| 代理属性 | `data-icon` 名字、class 名、元素存在 | 名字/存在与用户看到的结果之间没有强制对应关系 |

这三类在 `#1433` 上同时出现：映射断言是「名字」、e2e 是「mock DOM」、阈值是「与旧的不同」。

## 4. UI 侧缺口（简述）

1. 没有图标/视觉件的**基准图或逐件几何规格**。`docs/design/system/spec.md` §2 只约束笔画数 ≤6、尺寸 14/18/24、一概念一形状，不规定「这个图标具体长什么样」。
2. 缺陷票没有 conformance / baseline（那套制品只给有原型的 change 用），验收只能现编。
3. `state-coverage.json` 只登记「断言过」，不登记断言强度，99% 以上是自签 `passed`。
4. 229 个 e2e 里只有 2 个做像素/栅格断言。

## 5. 非 UI 侧缺口

非 UI 的病灶相同，但真值形态不同：

| 失败类别 | 近期实例 | 该有的真值 | 当前缺口 |
|---|---|---|---|
| 解析 / 类型推断 | `#1283` 字符串属性被推断为未识别、`#1277` 前导空格 frontmatter 不识别、`#548` 语法树未就绪漏块、`#1034` 别名静默覆盖内置类型 | 固定语料 + golden 结构快照（含畸形/边界输入），与真实解析器对拍 | 测试用手写期望；无语料库、无边界矩阵、无对拍 |
| Rust ↔ 前端边界 | `#944` 系统全屏退出残留无装饰窗口、`#1112` 复制文件写空、`#1024` 配置未接线 | 真实命令 round-trip 契约测试；字段名/类型单一来源 | `src/__tests__` 零序列化对拍；207/229 e2e 跑 mock |
| Rust 逻辑本身 | 各类后端校验/文件操作 | `cargo test` | 135 个测试存在，但 CI 与 `verify.sh` 都不执行 |
| 异步 / 状态机 | `#935` ready 只发一次、`#936` 空字幕 url 是 no-op、`#633` 连播不自动播放 | 显式状态转移表 + 事件序断言 | 只断言「最终看到某个值」，隐式契约未写成规格 |
| 真值陈旧 / 三方分叉 | `#1434`（主规格 36px / 实现 32px / fixture 36px）、`#1421`、`#997`、`#895`、`#560` | 规格-实现-测试三方对拍 + 锚点所有权 | 三处手写，无一致性机检；红灯不在 CI，无人路由 |
| 性能 / 资源 | 500KB 大文件守卫「规格存在但未接入」（AGENTS.md 自述） | 基线数字入 CI + 回归门 | 无基线、无门禁 |

## 6. 为什么 18 条门禁没拦住

现状不是「没有规则」，而是规则**不可机检、靠自觉**：

- QG-4 明文禁止代理属性断言，但没有任何 AST 规则能识别某条 `expect` 属于哪一级；违规只能靠人读。
- code-review 与实现同会话、同假设集，等于自审。
- QG-5「独立验证」在实际执行中是同一 agent 换身份跑探针；本次我甚至用「像素差 32.8%」去证明两个视觉同构的图标「可区分」，差点自证。
- DQ-7 要求「同一环节 ≥3 张缺陷票必须反查」，但 `scripts/` 中没有任何按 module/失败类别聚合的机检——不靠人记得就永不发生。
- 图标线 `#1346 → #1390 → #1413 → #1433` 连续四张同环节缺陷，就是 DQ-7 失效的实例。

结论：**文字门禁不 scale。** 110 张/月的产出需要的是仪器和指标，不是第 19 条规则。

## 7. 提案 A：测试强度审计（精选变异语料）

先明确边界：**变异语料不是独立真值**。它只能度量「测试能不能杀死我们已枚举的突变」，发现不了没被建模的缺陷；而基准图能直接暴露「缺第三行数字」这类问题，是变异语料覆盖不到的。两者互补，不能互相替代。

**做法**：从历史缺陷中精选可建模的根因，还原成最小「语义突变」（mutant），跑测试看是否变红。存活 = 该断言不足以发现这个错误。

语料条目（示意）：

```yaml
id: bug-1433-missing-third-digit
issue: 1433
root_cause: 有序图标第三行缺数字，而断言只要求「≥2 种标记」
class: ui-icon
patch:
  file: src/editors/icons.ts
  replace: 'paths: [UI_ICONS.ordered.s ?? ""]'
  with: 'paths: ["<第三行数字缺失的路径>"]'
expected_red:
  - src/__tests__/editor/icon-glyphs.test.ts
  - e2e/editors/ordered-list-icon.spec.ts
```

跨域示例：

| 域 | mutant | 应当变红的测试 |
|---|---|---|
| UI 图标 | 第三行数字缺失 / 两图标字形互换 | 字形层断言 + 基准图 |
| 序列化 | 翻转一个 `#[serde(rename)]` / 字段大小写 | 契约 round-trip |
| 解析 | 把数字推断改回字符串 | golden 语料 |
| 状态机 | 全屏两个标志写成不同步 / ready 只发一次 | 状态转移测试 |
| 输入规范化 | `**x**` 归一化多删一个字符 | 输入路径断言 |

**入选标准**（不合格不建模）：可稳定复现、单根因、有明确期望行为、不依赖外部服务；排除重复票、环境性失败、需求误判类。

**三态判定**：`applicable`（补丁能干净应用）/ `killed`（测试变红）/ `survived`（测试仍绿）。补丁应用失败计为 `invalid`，必须重写，不得计入存活率。

**落地方式**：

1. 先做 3 条 PoC（UI 图标、序列化、解析各一），验证运行器与判定口径，再扩到 20–30 条精选语料。
2. 语料随源码演进，需指定维护责任人；源码改动导致补丁失效时进入重写队列，并在报告中单列 `invalid` 比例。
3. 试用期内不接 PR 门禁；只有 PoC 与 20–30 条语料稳定运行一个迭代后，才讨论 PR 抽样（口径届时写死：模块判定规则 + 抽样数量 + 可复现种子）。
4. 票据关闭后语料保留；同一 module + 失败类别复发时优先复用并升级断言。

## 8. 提案 B：五项可测量指标

先采集基线，再定目标；目标不得在基线未知时拍脑袋。

| 指标 | 定义 | 采集 | 防作弊 |
|---|---|---|---|
| 变异存活率 | `survived / (killed + survived)`（排除 `invalid`） | 变异语料运行器 | 语料锁定；语料外缺陷另行统计；禁止按语料反推测试 |
| oracle 覆盖率 | 带外部真值的 AC 数 / 总 AC 数 | 票面字段机检 + 月度抽查 | 真值枚举；基准图/用户截图类必须有人工确认记录；抽查防滥填 |
| 缺陷复发率 | 同 module + 失败类别的重复票 / 总票 | issue 聚合脚本（人工校准） | 按失败类别标签而非标题关键词；分层归一化防 Goodhart |
| 三方一致性 | 规格 / 实现 / 测试锚点不一致处数 | 一致性机检 | 单一来源 + 所有权明确；不能只在两侧改 |
| 真实系统覆盖 | CI 中 cargo test / 契约 / e2e 冒烟是否实际执行 | CI 报告 | 未配置的核验步骤显式失败，禁止静默跳过 |

说明：

- 「变异存活率」只反映已知突变，不是质量真值；报告必须与「语料外缺陷数」并列展示。
- 「oracle 覆盖率 100%」只证明字段被填写，必须搭配抽查与失效回收（连续两季无引用的真值来源降级）。
- 指标用于发现退化，不用于排名个人或单票。

## 9. 提案 C：三条域无关流程硬约束

1. **票面必须有 `oracle:` 字段**：枚举值建议 `spec-clause` / `contract` / `corpus` / `baseline-image` / `real-system-observation` / `user-screenshot`；禁止「执行者判断」。先灰度：新票 warning，一个迭代后 fail-closed。校验落点并入 `cw-tickets-check.sh`（新增 C12）。
2. **测试作者 ≠ 实现作者（限 risk-high 强制）**：独立会话只拿规格与真值写断言，并留下断言清单与会话记录；risk-medium 不强制，但需用变异语料作补充信号。变异语料不能替代独立评审。
3. **缺陷回归语料库（按准入规则）**：不是每张 bug 都建条；按严重度、可复现性、失败类别准入。季度统计同类复发；同环节复发 ≥3（或同一 module 连续 2 次）自动开「规范修订」票，DQ-7 机检化。

## 10. 提案 D：CI 接真实系统

- **P0-0**：`cargo test` 进 CI（独立 job）；e2e 冒烟子集进 CI（`#1100` 已开）。先让已有真实信号可见。
- **未配置即失败**：`CMD_FIDELITY` / `CMD_VISUAL_BASELINE` 未配置时显式失败，而不是跳过；同时给迁移开关与降级公告，避免工具链故障时全红堵 CI。
- **契约对拍**：优先配置与文件两类；实现方式明确为「生成 TS 类型 / JSON fixture / 独立集成测试」之一，不伪装成同一条端到端运行。窗口、剪贴板、全屏等 OS 效应列入例外清单，不强行进 headless CI。
- **三方一致性机检**：规格条款、实现常量、e2e 锚点三处比对；明确源文件与生成物的所有权（谁是唯一真值、变更要改哪几处）。
- **像素兜底**：定义跨平台容差、基准更新流程与失效告警；基准图必须有人验收一次，后续更新需留确认记录。

mock 定位下调为「本地快速反馈」，不再作为唯一证据。

## 11. 落地顺序、成本与风险

> **落地状态（2026-11-25 更新）**：P0 已全部落地——P0-0 经 #1444/#1445（`cargo test` 与 e2e 冒烟进 CI；冒烟首跑即抓到 Meta/Ctrl 键位跨平台缺陷）；三方一致性机检经 #1446（`scripts/anchor-consistency-check.sh`，menu_row_height 以 #1434 豁免运行，裁决后切 `--strict`）；25 张抽样审计经 #1447（`defect-mode-audit-2026-11.md`：no-test 36%、weak/stale-oracle 合计 32%、env 12%、not-run 8%）。两项跟进待用户动作：GitHub 分支保护把 verify/rust-tests/e2e-smoke 设为 required checks；#1434 裁决 32 vs 36。

| 优先级 | 动作 | 成本 | 风险 |
|---|---|---|---|
| P0-0 | `cargo test` + e2e 冒烟进 CI；未配置核验改为失败 | 1–2 人日 | CI 时长与 flake；用独立 job 与冒烟子集控制 |
| P0 | 20–30 张缺陷分层抽样审计（§2.1 口径） | 2–3 人日 | 分类噪声；双人标注抽查 |
| P0 | 三方一致性机检（先做菜单几何一类） | 2–3 人日 | 所有权不清会变成第三份手写 |
| P1 | 变异语料 3 条 PoC → 20–30 条精选 + 运行器 | PoC 2–3 人日；扩量 1 周 | 补丁漂移与维护负担；`invalid` 单列 |
| P1 | `oracle:` 字段（枚举 + 模板 + 灰度 + 机检落点） | 1–2 人日 | 字段被滥填；抽查与回收机制 |

| P2 | 解析 golden 语料、状态转移表 | 逐模块 2–3 人日 | 需要先补最小规格 |
| P2 | 五项指标看板 + 季度复盘 | 2–3 人日 | 口径漂移；先基线后目标 |

**不做**：全量 mutation、一次性建 110 条语料、为每个图标写像素单元测试、把覆盖率阈值当质量指标继续加码。

## 12. 反方观点与回应

- **「变异测试太慢/太贵」**：只做 3 条 PoC → 20–30 条精选，不接 PR 门禁；全量 110 条不是首期目标，主要成本是维护而非算力。
- **「`oracle:` 字段是流程负担」**：它取代的是「事后返工 + 用户报 bug」；先灰度 warning，再 fail-closed。
- **「UI 像素基准脆」**：底座用结构/几何断言，像素只做兜底；定义容差与更新流程，并要求人工确认记录。
- **「mock 测试够快了，为什么还要真实系统」**：`#944`/`#1112` 这类缺陷只在真实边界出现；mock 无法证伪自己。先接 `cargo test`，再小范围契约对拍。
- **「批量交付（4–28 项/PR）才是缺陷多的原因」**：本文未量化排除。若审计显示 `spec-ambiguity` 与批量规模占主导，应优先改交付粒度与需求对齐，而不是继续加测试仪器。
- **「规格模糊/需求 churn 才是主因」**：同上，审计后按占比决定投入；本文只主张「真值缺位至少是重要成因之一」。
- **「先修 bug 再谈机制」**：本提案不阻止修 bug；但图标线连续 4 张同环节缺陷说明只修不建仪器会持续消耗用户信任。
