### 3.2 冲突裁决规则

| 场景 | 裁决 |
|------|------|
| Cmd+Shift+. 系统热键冲突 | 通过 Tauri v2 GlobalShortcut API 注册为系统级全局快捷键。首次启动时检测热键是否被占用,若被占用则提示用户在设置中修改 |
| Cmd+= 系统缩放 vs 应用字号 | 应用内拦截 Cmd+=,不触发系统缩放 |
| Esc 多层含义 | 就近原则:先关面板→再退出沉浸→需多次按 |

## 五、展卷仪式系统

### 5.1 设计原则

| 规则 |
|------|
| 非阻塞:动画在独立合成线程运行,TTI 不受影响 |
| TTI 硬保证:展卷动画结束后应用必定 <1s TTI |
| 可跳过:任意键/Esc/点击 → 中断动画 |
| 批量抑制:连续操作仅首次播放动画 |
| 批量操作不播放:删除 3 篇文档时仅首次有动画,后续静默 |

### 5.2 M 阶段 TTI 验证

| 时间 | 事件 |
|------|------|
| T+0ms | 应用启动信号,开始合成动画帧序列 |
| T+5ms | 开始异步加载核心层（编辑器 + Store + 文件操作并行） |
| T+50ms | 核心层加载完成,等待动画结束 |
| T+400ms | 动画完成（用户默认不跳过场景） |
| T+405ms | resolve paint ready,此时用户可交互 |

> 如果用户在 T+200ms 按下任意键,动画立即跳至最后一帧,核心层已在 T+50ms 就绪,TTI ≈ T+200ms + paint ≈ 250ms。

## 六、性能架构

### 6.1 三级加载时序

```
T0 (0ms) 启动信号

[核心层] T0 → ~50ms
  ├─ 编辑器核心
  ├─ 主 UI
  ├─ 文件操作
  └─ 配置加载

[功能层] T0+0ms → +500ms
  ├─ 标签系统（R）
  ├─ 文件面板感知（R）
  ├─ 视觉引擎基础（P1）
  └─ 配置路径初始化（M 预埋）

[扩展层] 用户触发后
  ├─ AI 后端
  ├─ 翻译引擎
  ├─ 灵感聚类
  └─ 粒子系统
```

### 6.2 TTI 定义

| 指标 | 定义 | 目标 |
|------|------|------|
| **TTI** | 可执行打开/编辑/滚动的最早时间点 | <1.0s |

> 即使用户第一次就跳过动画,TTI 也必须 <1.0s。

### 6.3 设备基准

| 指标 | M1 Mac | M3 Mac | Intel Mac |
|------|--------|--------|-----------|
| TTI | <700ms | <600ms | <900ms |
| 动画时长 | 1.2s | 1.0s | 0.4s |
| 纹理精度 | full | full | half |
| 自动降级阈值 | — | — | Reduce Motion=ON 时关闭动画 |

> **Buffer 说明**:Intel Mac 目标留出 100ms buffer（实际目标 900ms,redline 1.0s）,最差情况下达到 1.0s 才触发消除仪式动画。

| 使用统计 | **不上传** | ❌ | 本地聚合（见 §7.2） | 重置 |

### 7.2 双目录职责表

| 目录 | 用途 | 内容 |
|------|------|------|
| `~/.config/biaoyue/` | 应用持久化配置（macOS 规范） | config.json、recent-files.json、search-index/ |
| `~/documents/biaoyue/` | 用户可见的数据文件 | 示例文件、灵感文件夹、用户自定义模板 |

### 7.3 元数据收集声明

> 「不收集元数据」指的是:不上传分析所需的任何使用数据
>
> 灵感文件中的 YAML frontmatter（tags、source、related_docs）是用户主动创建、本地存储、不上传的手段,属于 **用户自管理的数据结构**,并非「标月系统为分析目的收集的元数据」。

### 7.4 云端功能提示规范

当用户在统一文件面板或命令面板中触发云端功能（如:AI 对话切换为云端、调用翻译云服务）,**在应用底部状态栏**显示轻量提醒:

> ☁️ 模式:云端处理 · 点击切换本地

**不可永久消除**:每次切换到云端模式时均会在状态栏出现,直到用户主动切换回本地。用户无法在设置中关闭此提示。

### 7.5 本地统计安全说明

| 问题 | 处理方式 |
|------|---------|
| 本地聚合结果是否给用户看? | 是（读写统计在状态栏展示）;仅聚合不暴露原始操作记录 |
| 重装系统后统计是否丢失? | 是（跟随应用卸载/系统重装丢失） |
| 是否明文暴露给其他 App? | 统计存储于 `~/.config/biaoyue/stats.json`,文件权限 600（当前用户读写）,不可被其他 App 读取 |

## 八、HTML 渲染方案

### 8.1 M 阶段方案

| M 阶段 HTML 渲染方案 |
|-------------------|
| iframe sandbox（sandbox="allow-same-origin"） — 禁止 JS 执行 |
| HTML 中的 CSS 仅通过内联 `<style>` 或 `<link rel="stylesheet" href="blob:...">` 引入 |
| 所有图片必须转为 **base64 内联** |
| **禁止所有相对路径资源加载** |
| M 阶段暂不引入外部 CDN |

### 8.2 R 阶段方案

- Tauri 自定义协议 `tauri://biaoyue.local/<path>` 映射到用户文档同目录
- 白名单放宽:`script-src 'none'`（脚本仍禁止）、`style-src 'self' https://cdn.jsdelivr.net`、`font-src 'self' https://fonts.gstatic.com`

### 8.3 M 阶段 CSP 定义

```
default-src 'none';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self' data:;
script-src 'none';
frame-ancestors 'self';
base-uri 'none';
```

## 十二、Store 架构收敛（Single Store + Slices）

> 来源: `docs/architecture-store-slices.md`（Codex + Ponytail 5 轮对抗审查后定稿）

### 12.1 合并原双 store 为 Single Store + 3 Slices

**问题:** 原 `src/stores/index.ts`（319行,useStore）和 `src/stores/editorStore.ts`（137行,deprecated,标记合并）在 `editorMode`/`content`/`dirty`/`filePath` 字段重叠,导致跨 store 同步 bug 风险。

**方案:** 合并为 `src/store/` 目录,单 store + 3 slice 文件:

```
src/store/
  index.ts       // createAppStore()，组合 slices
  tabs.ts        // 标签、分屏、recentFiles、per-tab editor state
  nav.ts         // 面板、搜索、侧栏、上下文种子
  config.ts      // 用户偏好、主题、字体、持久化配置
```

**边界原则:** Slice 按"行为发生的位置"划分:
- 用户操作标签/编辑区 → `tabs.ts`
- 用户操作面板/搜索区 → `nav.ts`
- 用户改偏好设置 → `config.ts`

### 12.2 导航面板数据流

```
Cmd+P → nav.openPanel()
  ├─ 空查询 + 无种子 → navView='context'
  │   ├─ tabs.recentFiles.slice(0,5) → "继续"分组
  │   ├─ invoke('list_files',{dir:隐式目录}) → nav.dirFiles → "全部"分组
  │   └─ tabs.tabs.filter(dirty || half-read) → "待处理"分组
  └─ 带种子 → navView='inline'
      └─ invoke('search_files',{query: seed}) → nav.dirFiles
```

> 隐式目录 = 最近访问文件的父目录,无需用户选择 folder。
> dirFiles 每次打开 panel 按需 `invoke('list_files')` 获取,不持久化到磁盘。

### 12.3 字段 → Slice 映射

| Slice | 字段 |
|-------|------|
| tabs.ts | activeTabId, tabs, recentFiles, splitDirection, splitTabIds, splitActiveTabId, splitEditorMode, horizontalSplitRatio, verticalSplitRatio, editorMode, splitEditorMode, content, dirty, filePath, fileName, fileSize, translation, contentVersion |
| nav.ts | sidebarLeftVisible, sidebarRightVisible, navView, searchQuery, selectedIndex, contextSeed, dirFiles, panelOpen, readingMode |
| config.ts | fontSize, headingColors, config, configLoaded, configLoading |

**关键决策:**
- translation 保留 tabs.ts — 跨 tab 共用,不属于单一 tab
- readingMode 放 nav.ts — 控制侧栏/工具栏全局 chrome,不是 per-tab state 也不是持久化偏好

### 12.4 保留独立 Store 的条件

如果 future feature 满足以下任一条件,允许新建独立 store:
1. **隔离生命周期** — feature 有独立 mount/unmount（如全屏 overlay、独立窗口）
2. **多实例共存** — 同一 type 的 store 需要多个不同 instance（如多窗口各有自己的 tabStore）
3. **不频繁读写** — 写操作不应触发主 store rerender（如高频 cursor position 更新）

当前 P1/P2 功能不满足以上任何条件,继续使用 slices 模式。

### 12.5 R 阶段 store 合并计划（不阻塞开发）

1. 新建 `src/store/index.ts`:createAppStore,组合 tabs + nav + config slices
2. 迁移 `src/stores/index.ts` 和 `src/stores/editorStore.ts` 到新结构
3. 逐步替换 component import（hooks 不变,内部改用新 store）
