# UI 反馈四要素

> 用于把「太丑」「太大」这类感受性反馈，转成可执行、可核验的视觉变更。配套：[设计系统规格](../design/system/spec.md)、[决案台账](../design/system/decisions.md)、[缺陷流程](./defect-workflow.md)「非功能视觉缺陷」。

## 一、为什么需要模板

视觉返工的真实原因不是审美分歧，是**反馈缺三样东西**：量纲（多大算大）、规范锚点（违反了哪条）、期望终态（什么叫好）。缺了这三样，执行者只能猜一个数值去改；猜不中就是第二轮返工。

模板的作用不是让用户填表，是让执行者**在动手前把这三样补齐并说出来**。

## 二、四要素

| # | 要素 | 写什么 | 反例 |
|---|---|---|---|
| 1 | **位置** | 哪个界面、哪个区域（状态栏主题按钮） | 「那个按钮」 |
| 2 | **对象** | 哪个具体元素（下拉三角） | 「图标」 |
| 3 | **偏差** | 现在 vs 期望（现在占按钮一半高，期望同状态栏其他图标同高） | 「太大了」 |
| 4 | **对标** | 参照物：`design-system:§N`、台账某行、或某个已存在的同类元素 | 「不好看」 |

四条不必严格齐全，但**执行者必须补齐**，补齐不了就先问。

## 三、执行者规则（比用户模板更重要）

1. **模糊反馈不得直接猜数值。** 先给 **2–3 个候选终态**（文字描述或小样），让用户选一个；用一轮轻交互替代一轮真机返工。
2. **先查锚点。** 反馈指向的部件若在 `decisions.md` 有台账行，先确认是否已裁决过；已有裁决而用户要求改变 → 这是**推翻旧裁决**，追加新行并注明取代，不是"再改一次"。
3. **spec 无条款 = gap。** 不即兴造值；先补条款或补台账行，再实现。
4. **改完必须能回答「对上了哪一条」。** 答不出说明这次改动没有依据，下一轮还会返工。
5. **反馈涉及审美方向（"再找找更好看的"）时，不套本模板。** 这类需求走小样对比（2–3 个方案并列），不是数值校准。

## 四、示例（真实案例）

| 原始反馈 | 补全后 |
|---|---|
| 「切换主题的下拉三角很大，太丑」 | 位置：状态栏主题按钮；对象：下拉三角；偏差：三角高度接近按钮高度的一半，视觉压过主图标；对标：状态栏图标按 `design-system:§2.1` 的尺寸档。**候选终态**：A 三角降到与主图标同档并同基线；B 去掉三角，改用弹窗自身指示；C 保留三角但降一档并右移贴边 |

最终裁决为 B（去掉三角），记入台账「状态栏主题按钮」一行（PR #397）。

## 五、反面示例

- 「pinoff 的斜杠线比较长」→ 未说明"多长算合适"。执行者应按模板给出：现状是斜杠贯穿整格、期望只穿图钉本体（几何定案见**台账·pinOff 斜杠**）。该案例实际返工三轮（#352 → #366 → #368）才收敛，正是缺对标的代价。
