# Doctrine（产品铁律）

本文档是 Biaoyue 的产品铁律（Doctrine）：序言 + 十条铁律 D1–D10 + 「不为谁做」五条。
产品定义见 [产品愿景](./vision.md)，范围边界见 [范围边界](./scope.md)，阶段方向见 [交付路线图](../delivery/roadmap.md)。

## 序言

> **总纲**：用最少干扰达成用户所愿。
>
> **气质**（不具裁决力）：懂你、减负、惊喜、正向陪伴；沉浸、仪式、留白。
>
> **效力**：每条可引用、可验收。任何设计、规格、变更与铁律冲突时，须显式引用条款编号（D#）给出豁免理由并经维护者确认；本图后续所有票的裁决必须引用 D# 作为依据。可测量的性能指标（启动 <1s、滚动 60fps 等）下沉功能规格，不入铁律。
>
> **品质对标**：比 Notes 安静、比 Drafts 轻、比 Keep 有组织；生成物：**单文件即成品**——设计密度对标 contentweave 精品页。

## 一、十条铁律（D1–D10）

| # | 条款 | 一句话 | 判定问题 |
|---|------|--------|----------|
| D1 | **内容是王** | 界面 chrome 不抢注意力、不占文档展示空间 | 这个元素在不交互时出现，是在服务谁？ |
| D2 | **减法至上** | 每个元素必须证明自己存在；删不掉 = 不该存在 | 去掉它，界面是否更好？ |
| D3 | **操作即所得** | 用户直接操作：意图与响应之间步骤 = 1，录入过程不打断思路。AI 代理操作的写前确认卡（once / always / deny）是代理侧的最小打扰形态，不违本条（联动 D7） | 用户想完成这件事要点几下？ |
| D4 | **键盘优先** | 高频操作快捷键 ≥80% 可达，主流程单手键盘走通 | 主流程必须碰鼠标吗？ |
| D5 | **默认值即产品（omakase）** | 每个能力带精选默认行为，高级选项藏 override 层；首次启动即「已被组织好的工作现场」 | 新用户不看说明书，能不能直接用？ |
| D6 | **一切可变状态皆文本（malleable）** | 配置、键位、模板、扩展 = 约定目录的文本文件；扩展点先做数据文件（SKILL.md 式），不做 API | 这个调整需要改源码吗？能不能变成一份文本？ |
| D7 | **AI 可塑但必须可撤销（agentic）** | AI 能改的一切：写前确认卡、写后快照、改坏一键恢复；AI 操作永不绕过审计 | 用户手滑一下，能不能一步回来？ |
| D8 | **误操作与升级皆可逆** | 用户破坏性操作必有回退路径；升级 = 幂等迁移 + 回滚点；内置默认 / 用户覆盖 / 生成态三目录分离，升级永不毁用户数据 | 误操作或升级后，数据还在吗？ |
| D9 | **生成物离线单文件** | HTML 产物断网可看、零外部子资源（CDN 字体须有兜底）；用户自写源文件不受此限 | 生成的产物断网能看吗？ |
| D10 | **零门槛** | 普通学习者不装任何外部依赖即可用全部核心能力（含 AI） | 用户要装什么才能用核心功能？ |

> 来源：产品铁律决议（2026-10-31 维护者裁定）。旧五原则（内容是王 / 减法至上 / 操作即所得 / 思路不中断 / 误操作可逆）已全部收编：见文末「汇编记录」。

## 二、不为谁做

1. 不为**愿意折腾的系统级玩家**做整机级定制（那是 omarchy 的领地）。
2. 不为**团队/多人协作**做（远期再议，本定位周期不承诺）。
3. 不为**插件市场/公开扩展 API** 做（扩展点 = 数据文件，见 D6）。
4. 不为**云端免费服务**做（本地优先，API key 用户自持）。
5. 不为**多语言市场**调整产品节奏（中文体验优先做到极致，英文是翻译不是重设计）。

## 三、汇编记录（旧五原则的收编方式）

1. 「最少干扰」升为**序言总纲**，不占铁律席位（其余十条的母句）。
2. 「思路不中断」并入 **D3**（同为「步骤与打扰」维度）。
3. 「误操作可逆」+「升级永不毁用户数据」合并为 **D8**（同属「数据可恢复」维度：用户侧 + 升级侧；AI 侧可撤销由 D7 独占）。
4. 「操作即所得」修订版保留为 **D3**：AI 代理写前确认卡获显式豁免（Zed/Dyad defaultConsent 先例）。
5. 哲学三层的「方向/灵魂」情感词条降为**序言气质段**（不具裁决力）；红线层的可测指标（启动/帧率）下沉功能规格。
