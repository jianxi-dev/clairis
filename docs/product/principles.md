# 设计原则（设计红线与原则）

本文档提炼 Biaoyue 长期稳定的设计红线与原则，只归类不篡改。产品哲学一句话见 [产品愿景](./vision.md)；具体键位体系、逐功能行为不在本文档承载，见 `openspec/specs/`。

## 一、产品哲学三层

| 内容 | 用途 |
|------|------|
| 快、方便、舒服、喜欢 | 红线 |
| 懂你、减负、惊喜、正向陪伴 | 方向 |
| 沉浸、仪式、留白 | 灵魂 |

> 来源：全量需求文档 §1.3「产品哲学」（历史原稿已被取代，历史存根 `docs/CORE-REQUIREMENTS-clairis.md`；现行产品定义见 [产品愿景](./vision.md)）。

## 二、红线层：快 / 方便 / 舒服 / 喜欢（必须满足）

| 原则 | 含义 | 评审检查 |
|------|------|----------|
| 快 ⚡ | 启动 <1s，操作零等待，滚动 60fps | 用户感到等待了吗？100ms 内反馈？ |
| 方便 🖐️ | 高频操作快捷键 ≥80%，少点鼠标 | 能否不碰鼠标完成？单手键盘走通主流程？ |
| 舒服 😌 | 排版克制，动画平滑，无信息过载 | 截图给朋友看是否自豪？去掉元素是否更好？ |
| 喜欢 ❤️ | 细节有惊喜感，超出预期 | 用户想主动打开吗？有 wow 效果吗？ |

> 来源：[MVP-渐明-v1](../archive/2026/legacy-docs/MVP-渐明-v1.md) §2.1「V3 版原则（MVP 红线，必须满足）」。

## 三、方向层：懂你 / 减负 / 惊喜 / 正向陪伴

| 原则 | 含义 |
|------|------|
| 懂你 🧠 | 主动理解意图，预判需求 |
| 减负 🪶 | 减少决策，自动整理 |
| 惊喜 ✨ | 超出预期，带来 Wow 瞬间 |
| 正向陪伴（上瘾）🌀 | 使用后满足，不用时想念 |

> 来源：[MVP-渐明-v1](../archive/2026/legacy-docs/MVP-渐明-v1.md) §2.2「V4 版原则」；一句话定义见 [产品愿景](./vision.md)。
> 注：原文以落地阶段标注逐步实现节奏，阶段排期见 [交付路线图](../delivery/roadmap.md)，此处只保留原则含义。

## 四、设计纲领五原则

| # | 原则 | 含义 | 反模式 |
|---|------|------|--------|
| 1 | 内容是王 | 界面 chrome 不抢注意力，不占用文档展示空间 | 大工具栏、常驻侧栏、装饰性元素 |
| 2 | 减法至上 | 每个元素必须证明自己存在。删不掉 = 不该存在 | “用户可能用到”、“加一个以防万一” |
| 3 | 操作即所得 | 用户意图和系统响应之间步骤 = 1。超过一步反思 | 多步骤弹窗、层层菜单、确认对话框 |
| 4 | 思路不中断 | 录入过程不打断思维 | 弹出确认 / 切换窗口 / 改变焦点 |
| 5 | 误操作可逆 | 破坏性操作必须有回退路径 | 删除不可恢复、无确认的高危操作 |

> 来源：[纲领性设计文档](../DESIGN-PHILOSOPHY.md) §二「核心原则（5 条）」。

## 五、品质对标

- 设计产出应达到 Apple Notes / Bear / Xcode 的水准。
- 目标定位：**比 Notes 安静、比 Drafts 轻、比 Keep 有组织**。

> 来源：[纲领性设计文档](../DESIGN-PHILOSOPHY.md) §三「Apple 级对标」。竞品详细对照属调研资料，不在此复制。
