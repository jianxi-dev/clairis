# 渐晰无侧栏 Desk 与文件列表改进方案

> 状态: 设计归档
> 来源: 对 `no-sidebar-doc-navigation.md` 的批判性审查与后续方案收敛
> 目标: 明确 Desk 的真实价值,并定义无侧栏场景下文件列表应显示什么、如何显示

---

## 一、核心判断

无侧栏设计不能只是把侧栏藏起来。真正要解决的是:

1. 用户如何快速回到刚才的文档
2. 用户如何找到明确目标
3. 用户如何在忘记标题/路径时恢复上下文
4. 用户如何确认文件没有丢、状态没有丢

因此导航应拆成三种能力:

| 能力 | 入口 | 解决的问题 |
|------|------|------------|
| 手边 Recents | 按住 Cmd / 轻扫 / 顶部边缘 | 快速切换刚用过的文档 |
| Omni Search | Cmd+P | 明确查找文件、命令、面板 |
| Desk | Cmd+↑ | 重新理解当前工作现场 |

Desk 不应承担日常快速切换。日常切换由手边 Recents 负责。Desk 的价值必须和 Recents 不同。

---

## 二、Desk 的重新定位

### 2.1 Desk 不是打开器

如果 Desk 只是显示“最近文档 + 推荐文档”,它没有存在价值。最近文档已经由手边 Recents 解决,推荐文档如果不可解释也会成为噪音。

Desk 应重新定义为:

> Desk 是当前任务的上下文地图,不是文件列表。

它只在用户有以下意图时出现:

- “我刚才到底在做什么?”
- “这几篇文档之间是什么关系?”
- “我忘了标题,但记得它和当前这篇有关。”
- “我需要从当前任务抽离,看整个工作现场。”

### 2.2 Desk 应显示什么

Desk 不使用固定配额,不硬凑 9 个文档。它由四类内容组成:

```text
Desk = 当前文档
     + 本次任务现场
     + 可解释关系
     + 有状态风险的文档
```

#### 当前文档

当前文档是 Desk 的视觉锚点,应该最大、最清楚,放在空间中心或中心偏左。

显示内容:

- 标题
- 当前阅读/编辑位置附近的一句话
- 当前状态: 已保存 / 未保存 / 读到百分比 / 编辑中

#### 本次任务现场

显示本次会话中真正参与过当前任务的文档,而不是普通最近文档。

进入条件:

- 从当前文档跳转过
- 与当前文档分屏对照过
- 被当前文档引用过
- 内容被复制/摘录到当前文档
- 在同一任务窗口内连续编辑过

这些文档回答的是“我刚才围绕这个任务碰过哪些材料”。

#### 可解释关系

Desk 可以显示相关文档,但必须解释为什么相关。

允许的关系原因:

- `同一文件夹`
- `互相引用`
- `共同标题词`
- `刚才对照`
- `从这里跳来`
- `被当前文档引用`
- `包含相同标签`

没有可解释原因的推荐不应出现在 Desk。

#### 有状态风险的文档

这些文档不一定最近,但需要被用户安心地看见。

进入条件:

- 未保存
- 今天创建但未命名
- 读到一半
- 含 TODO
- 外部文件已移动或失效
- 被加入 Shelf 但还未处理

这类文档是无侧栏替代“安全感”的关键。

### 2.3 Desk 不应显示什么

不建议显示:

- 普通最近列表
- 泛泛的 AI 推荐
- 完整文件树
- 固定配额的“最近 4 + 固定 2 + 推荐 2”
- 不可解释的语义相似文档

这些内容要么和 Recents 重叠,要么增加用户判断负担。

### 2.4 Desk 交互原则

| 动作 | 行为 |
|------|------|
| 点击文档 | 打开到主 Surface |
| Space | Peek 预览,不离开 Desk |
| Cmd+Enter | 旁开 / 新分栏打开 |
| Esc / Cmd+↓ | 回到进入 Desk 前的文档 |
| 拖到 Shelf 区域 | 加入纸夹 |
| hover 文档 | 显示完整路径、字数、最近状态 |

Desk 不应自动 15 秒退出,也不应自动归档当前文档。可以在长时间无操作后降低视觉权重,但不能替用户关闭场景。

### 2.5 Desk 位置规则

Desk 的空间记忆必须稳定。

错误做法:

```text
按时间/分数排序后映射到位置
```

这会导致文档位置随时间变化。

推荐做法:

```text
documentId -> stableSlot
```

位置由文档 ID 的稳定哈希决定。时间、相关度、任务参与度只决定文档是否进入 Desk,不决定它进入后的位置。

## 三、文件列表的设计目标

文件列表不是“文件名列表”。每个条目都要让用户在 1 秒内判断:

```text
这是哪篇?
为什么它在这里?
我上次做到哪里?
点开会发生什么?
```

因此文件项必须显示四类信息:

1. 身份
2. 记忆线索
3. 来源理由
4. 状态

---

## 四、文件项内容结构

### 4.1 推荐结构

```text
[状态点] 标题                         [时间]
        记忆线索 / 搜索命中片段
        来源理由 · 父目录 · 状态
```

示例:

```text
● 无侧栏文档查看与打开              12 分钟前
  “文件列表要显示身份、记忆线索、状态、来源理由。”
  当前任务 · docs/designs · 已保存
```

### 4.2 主标题

标题优先级:

1. frontmatter title
2. 一级标题 H1
3. 文件名去扩展名

默认不显示 `.md`。只有同名冲突时才显示扩展名或更长路径。

### 4.3 记忆线索

记忆线索根据场景变化:

| 场景 | 显示内容 |
|------|----------|
| 最近编辑 | 上次编辑位置附近的一句话 |
| 搜索命中 | 命中片段,高亮关键词 |
| 读到一半 | “读到: ...” |
| 当前任务 | 最近参与任务的句子或标题 |
| 新文档 | 首行内容或“空白文档” |
| 内容太少 | 父文件夹 + 创建时间 |

不要硬摘无意义文本。没有好片段时,宁可显示结构信息。

### 4.4 来源理由

来源理由是无侧栏文件列表的关键。用户必须知道系统为什么给我看它。

推荐理由标签:

- `当前文档`
- `当前任务`
- `最近编辑`
- `最近打开`
- `同一文件夹`
- `引用过`
- `从当前文档跳来`
- `包含搜索词`
- `读到一半`
- `未保存`
- `已加入 Shelf`

### 4.5 状态

推荐状态:

- 已保存
- 未保存
- 外部文件
- 只读
- 读完
- 读到 63%
- 今天创建
- 有 TODO
- 已加入 Shelf
- 文件失效

状态点可以非常克制:

| 标记 | 含义 |
|------|------|
| 实心点 | 当前打开 |
| 空心点 | 最近打开 |
| 小折角 | 读到一半 |
| 墨点 | 未保存 |
| 夹子 | 在 Shelf 中 |

### 4.6 位置

路径信息默认低调显示:

- 默认只显示父级目录,如 `docs/designs`
- 同名冲突时显示更长路径
- hover 或展开时显示完整路径
- 右键或 Cmd+C 可复制完整路径

## 五、不同场景的文件列表

不要做一个万能文件列表。应共用同一个文件项组件,但在不同入口里调整排序和显示密度。

### 5.1 手边 Recents

用途: 快速切换刚用过的文档。

显示:

- 最多 5 个
- 标题
- 上次位置/最近一句
- 时间

不显示:

- 完整路径
- 大量状态
- 推荐原因

示例:

```text
无侧栏文档查看与打开
读到:“Desk 不是打开器,而是上下文地图。”
2 分钟前
```

### 5.2 Omni 搜索结果

用途: 明确查找。

显示:

- 最多 8 个
- 标题
- 命中片段
- 命中类型
- 父目录
- 时间
- 状态

示例:

```text
无侧栏文档查看与打开
...Desk 位置必须稳定,同一文档每次回到 Desk...
正文命中 · docs/designs · 12 分钟前
```

排序建议:

```text
当前打开/当前任务
> 标题命中
> 文件名命中
> 最近编辑
> 正文命中
> 路径命中
```

正文命中的老文件不应压过用户刚刚编辑的当前任务文件。

### 5.3 Shelf 纸夹

用途: 固定当前任务材料。

显示:

- 用户夹住的文档
- 从哪里夹住
- 为什么夹住
- 是否已处理

示例:

```text
The Desk 概念
从“无侧栏文档查看与打开”中加入
参考材料 · 未处理
```

Shelf 不是收藏夹,也不是侧栏。它是当前任务的临时材料夹。

进入 Shelf 的方式:

- 在文件列表中按 Tab
- 从 Desk 拖入 Shelf 区域
- 从正文 Portal 中加入
- 从 Omni 搜索结果加入
- 用户手动选择“夹住这篇”

Shelf 中每个文档应记录加入来源:

```text
从哪里加入
为什么加入
加入时间
是否已经打开/处理过
```

示例:

```text
三栏布局方案
从 Omni 搜索“嵌入停靠”加入
参考材料 · 未处理 · 8 分钟前
```

Shelf 的价值是让用户在无侧栏模式下仍然能临时固定 2-6 个工作材料,但不需要维护长期文件结构。

### 5.4 研究模式文件列表

用途: 批量浏览文件夹或项目。

这是唯一可以更接近传统文件列表的场景。

显示:

- 标题
- 父目录
- 最近修改
- 状态
- 可选分组

研究模式可以临时显示左侧文件列表,但它应被明确标记为一种工作模式,不要伪装成无侧栏默认状态。

## 六、补充导航设计

以下设计不是单独替代文件列表,而是和文件列表、Desk、Omni 共用同一套文件项组件。

### 6.1 返回轨迹 Trail

Trail 解决的问题不是“找文件”,而是“回到刚才那个地方”。

用户从 A 跳到 B,再跳到 C 时,系统记录路径:

```text
设计原则.md → 无侧栏方案.md → 搜索实现.md
```

触发方式:

| 入口 | 行为 |
|------|------|
| Cmd+[ / Cmd+] | 后退 / 前进到上一个文档位置 |
| 按住 Cmd+[ | 展开最近路径 |
| 左边缘轻扫 | 显示返回轨迹 |

Trail 条目显示:

- 文档标题
- 当时的位置片段
- 从哪里跳入
- 跳转原因: 搜索 / 链接 / Recents / Desk / Portal

示例:

```text
无侧栏方案
从“侧栏安全感”段落跳入
来自 Portal · 4 分钟前
```

Trail 和 Recents 的区别:

- Recents 是时间列表
- Trail 是路径列表

用户想快速切换时用 Recents。用户想回到刚才的思路时用 Trail。

### 6.2 文档传送门 Portal

Portal 解决“我正在读/写这里,相关文档应该从这里出现”的问题。

触发方式:

- 选中文本
- hover 一个概念词
- 光标停在标题或段落 800ms
- 在右键菜单中选择“查找相关文档”

表现形式:

```text
相关
  no-sidebar-design.md
  the-desk-concept.md
  three-column-layout.md
```

Portal 中每项必须显示关系原因:

```text
The Desk 概念
命中标题词“Desk” · 被当前文档引用
```

允许动作:

| 动作 | 行为 |
|------|------|
| Enter | 打开 |
| Space | Peek 预览 |
| Tab | 加入 Shelf |
| Cmd+Enter | 旁开 |

Portal 不应自动弹出大面板。默认只显示一个极轻的墨点或短线索,用户 hover / 键盘确认后再展开。

### 6.3 任务包 Workspace

Workspace 解决“我记得自己在做什么,但不记得文件在哪里”的问题。

它不是用户手动维护的文件夹,而是系统根据工作行为自动形成的任务包。

形成条件:

- 同一批文档在短时间内反复共同出现
- 多个文档被加入同一个 Shelf
- 多个文档围绕同一个搜索词打开
- 多个文档互相引用或分屏对照

Workspace 示例:

```text
无侧栏改版
  no-sidebar-doc-navigation.md
  the-desk-concept.md
  CORE-REQUIREMENTS.md
  最近搜索: “Desk 位置稳定”
```

用户可执行动作:

- 保存当前任务包
- 重命名任务包
- 从任务包恢复工作现场
- 将任务包加入 Desk

Workspace 应在 P2 前保持克制。P1 可以先以“最近任务现场”的形式实现,不急于做完整管理界面。

### 6.4 自然语言找文档

Omni Search 后续应支持用户用记忆描述找文档。

示例输入:

```text
昨天写的那个关于注意力的
上周打开过的无侧栏方案
包含 Desk hash 槽位的文档
我读到一半的那篇
```

R 阶段不需要语义模型,可以先做规则解析:

| 表达 | 解析 |
|------|------|
| 昨天 / 上周 / 今天 | 时间过滤 |
| 关于 xxx | 标题 / 正文 / 标签匹配 |
| 打开过 / 写过 / 读到一半 | 最近记录 / 编辑记录 / bookmarkFolds |
| 包含 xxx | 文件名 / 标题 / 简单正文匹配 |

自然语言搜索的结果仍使用标准文件项结构,并在来源理由中显示解析结果:

```text
无侧栏文档查看与打开
匹配“上周 + 无侧栏 + 打开过”
docs/designs · 7 月 3 日
```

### 6.5 阅读完成收尾台

读完文档后不应自动归档。用户可能只是停留、摘录、回看或准备复制。

推荐改成收尾台:

```text
已读完
[收起] [标记已读] [下一篇] [相关文档]
```

规则:

- 不自动关闭当前文档
- 不自动归档
- “下一篇”只给一个主推荐
- “相关文档”可展开更多
- Esc 或继续滚动即可退出收尾台

收尾台推荐来源:

1. 同一任务现场中的下一篇
2. 当前文档引用的文档
3. 读到一半但未完成的相关文档
4. 同一文件夹最近打开的文档

每个推荐必须显示原因:

```text
The Desk 概念
当前文档引用过 · 预计阅读 4 分钟
```

### 6.6 文件状态安心提示

侧栏的隐藏价值是安全感。无侧栏设计必须在关键时刻告诉用户“文件还在、状态没丢”。

提示出现时机:

- 保存完成
- 关闭文档
- 切换文档
- 打开外部文件
- 文件路径失效
- 退出应用前仍有未保存文档

提示内容应短、具体、可撤回:

```text
已保存到 docs/designs
已加入 Shelf
还有 2 篇未保存
文件已移动,是否重新定位?
```

这些提示不常驻。它们只在状态发生变化时短暂出现,避免重新变成状态栏。

## 七、文件列表交互

所有文件列表入口应使用一致动作:

| 动作 | 行为 |
|------|------|
| Enter | 当前窗口打开 |
| Cmd+Enter | 旁开 / 新分栏打开 |
| Space | Peek 预览,不改变当前位置 |
| Tab | 加入 Shelf |
| Cmd+C | 复制路径 |
| Esc | 关闭列表 / 返回 |
| ↑ / ↓ | 移动选中 |

hover 时可以显示轻量操作:

```text
预览 / 旁开 / 加入纸夹 / 更多
```

这些按钮不应常驻显示,否则会污染扫描效率。

## 八、推荐的信息分组

默认文件列表最多三组:

```text
继续
当前任务
最近
```

每组最多 5 条。超过时引导用户使用 Omni 搜索。

示例:

```text
继续
  无侧栏文档查看与打开
  读到:“Desk 不是打开器,而是上下文地图。”
  当前文档 · 2 分钟前

当前任务
  The Desk 概念
  “文档不应该被找到,它们应该在物理空间中等待你。”
  引用过 · 关联当前文档 · 7 月 3 日

  三栏布局方案
  命中:“嵌入停靠”
  同一设计组 · 6 月 29 日

最近
  CORE Requirements
  上次编辑: Omni-Search 是唯一命令入口
  最近编辑 · 昨天
```

## 九、实施建议

### R 阶段

只做最能立刻提升无侧栏可用性的部分:

1. Cmd+P Omni Search
2. 手边 Recents
3. 统一文件项组件
4. Space Peek
5. 经典侧栏兼容开关
6. 轻量安心提示

R 阶段文件搜索只做:

- 文件名
- H1 / frontmatter title
- 最近记录
- 父目录
- 简单正文片段,如果已有索引可复用

不要在 R 阶段做完整 TF-IDF、语义搜索或复杂推荐。

### P1 阶段

加入:

1. Shelf 纸夹
2. 当前任务识别
3. Desk 上下文地图
4. 文档关系原因标签
5. 阅读完成后的收尾台
6. 返回轨迹 Trail
7. Portal 文档传送门

### P2 阶段

加入:

1. 语义搜索
2. 本地 embedding
3. 项目地形聚类
4. 更智能的任务包 Workspace
5. 自然语言找文档

---

## 十、最终原则

无侧栏文件列表的关键不是“显示更多文件”,而是“显示更有解释力的文件”。

每个条目都要回答:

```text
它是谁?
它和我现在有什么关系?
我上次对它做了什么?
我点开会去哪里?
```

Desk 的关键不是“更漂亮的最近列表”,而是“让用户重新看见当前工作的现场”。
