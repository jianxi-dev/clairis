## 一、产品哲学（一句话）

**用最少干扰达成用户所愿。**

---

## 二、核心原则（5 条）

| # | 原则 | 含义 | 反模式 |
|---|------|------|--------|
| 1 | 内容是王 | 界面 chrome 不抢注意力，不占用文档展示空间 | 大工具栏、常驻侧栏、装饰性元素 |
| 2 | 减法至上 | 每个元素必须证明自己存在。删不掉 = 不该存在 | "用户可能用到"、"加一个以防万一" |
| 3 | 操作即所得 | 用户意图和系统响应之间步骤 = 1。超过一步反思 | 多步骤弹窗、层层菜单、确认对话框 |
| 4 | 思路不中断 | 录入过程不打断思维 | 弹出确认/切换窗口/改变焦点 |
| 5 | 误操作可逆 | 破坏性操作必须有回退路径 | 删除不可恢复、无确认的高危操作 |

## 三、Apple 级对标

设计产出应达到 Apple Notes / Bear / Xcode 的水准。

具体标准:

- 打开就写，无需学习
- 没有令人焦虑的状态指示（如红色未保存）
- 功能的发现不依赖文档，靠直觉
- 输入时不打扰，保存时无仪式

竞品参照:

| 竞品 | 优点 | 缺点 |
|------|------|------|
| Notes | 极简输入、新建即保存 | 关闭需点"完成" |
| Drafts | Inbox 心态、Action 链 | UI 过载 |
| Bear | Quick Capture、自动保存 | 界面元素稍多 |
| Google Keep | 打开即写、快捷至上 | 仪式感缺失、广告 |

Jianxi 目标: **比 Notes 安静、比 Drafts 轻、比 Keep 有组织**。

## 四、快捷键体系

### 4.1 优先级分层

| 层级 | 类型 | 示例 |
|------|------|------|
| L1 | macOS 系统保留 | Cmd+Space / Cmd+Tab / Cmd+Q / Cmd+H — 永不占用 |
| L1.5 | 应用内全局（焦点在渐晰时） | — |
| L2 | 编辑器快捷键 | 文字编辑/光标移动 — 仅在编辑状态 |
| L3 | 应用焦点快捷键 | Cmd+O/S/N/W/=//\\ |
| L4 | 面板/模式快捷键 | Cmd+1/2/3/4、Cmd+Shift+E/A/T |
| L5 | 临时快捷键 | Esc 关闭/退出、↑↓ 选择 — 仅在特定状态 |

### 4.2 冲突裁决规则

| 场景 | 裁决 |
|------|------|
| Cmd+Shift+. 系统热键冲突 | Tauri v2 GlobalShortcut API 注册为系统级全局快捷键。首次启动时检测是否被占用，若被占用则提示用户在设置中修改 |
| Cmd+= 系统缩放 vs 应用字号 | 应用内拦截 Cmd+=，不触发系统缩放 |
| Esc 多层含义 | 就近原则：先关面板 → 再退出沉浸 → 需多次按 |

### 4.3 快捷键映射表（核心）

| 快捷键 | 行为 | 触发条件 | 阶段 |
|--------|------|---------|------|
| Cmd+O | 打开文件 | 应用焦点内 | M |
| Cmd+S | 保存文件 | 应用焦点内 | M |
| Cmd+N | 新建文档 / overlay 内新建 buffer | 应用焦点内 / overlay 内 | M |
| Cmd+W | 关闭标签 | 应用焦点内 | R |
| Cmd+=/- | 字号缩放 | 应用焦点内 | M |
| Cmd+B/I/U | 加粗/斜体/删除线 | 应用焦点内 | M |
| Cmd+\\ | 进入沉浸阅读 | 应用焦点内 | R |
| Cmd+1/2/3/4 | 主画布模式切换 | 应用焦点内 | P1 |
| Cmd+P | 统一文件面板 | 应用焦点内 | R |
| Cmd+[/Cmd+] | 后退/前进历史导航 | 应用焦点内 | R |
| Cmd+Shift+E | 大纲侧栏 | 应用焦点内 | P1 |
| Cmd+Shift+A | AI 对话面板 | 应用焦点内 | P1 |
| Cmd+Shift+, | Quick Capture Inspector (flat list + archive + 转正) | 应用焦点内 | R |
| Cmd+Shift+. | 灵感快速录入（系统级全局，热启动 < 50ms / 冷启动 < 200ms） | 任何 App 下 | R |
| Cmd+Shift+T | 翻译面板 | 应用焦点内 | P1 |
| Esc | 关闭面板 / 退出沉浸 | 就近关闭 | M/R |

## 五、UI 架构原则

### 5.1 无边栏哲学

- 删除左侧边栏（导航已由 Cmd+P 承载）
- 删除右侧侧栏
- 无浮动工具栏（38px 回收给内容区，操作进 More 菜单）

### 5.2 默认不打扰

| 路径 | 正确做法 |
|------|---------|
| 新建文件 | 自动生成 `Unnamed-YYYY-MM-DD-HHMM.md` 并自动保存。零弹窗 |
| 保存文件 | 自动保存成功 = 不告诉用户。只有失败才出声 |
| 关闭应用 | 无需确认（内容已保存） |
| 打开应用 | 直接到工作现场（最近文件 / 继续上次） |

### 5.3 状态栏分级

| 层级 | 显示 | 条件 |
|------|------|------|
| 常驻（opacity 0.6） | 行/列 · 字数 · 阅读进度 · 页面宽度 · 模式 | 始终 |
| tooltip（hover） | 完整路径、编码 UTF-8、换行符 LF/CRLF | 鼠标悬停 |
| 临时（opacity 1.0, 3s 淡回） | 保存失败红色提示 | 出错时 |
| 可点击 | 页面宽度（弹浮窗）、编码（弹选择器）、模式（切模式） | 始终 |

### 5.4 语义色

| 颜色 | 含义 | 用于 |
|------|------|------|
| 品牌蓝 #0071e3 | 激活/选中 | 时钟徽章、选区、聚焦环 |
| 红 #ff3b30 | 错误 | 保存失败 |

> 红色绝不用于脏/未保存状态。

## 六、Capture Overlay 专属评价标准

### 6.1 评价维度（5 维度）

| 维度 | 定义 | 测量方法 | 标准 |
|------|------|---------|------|
| Capture Latency | 从念头产生到可以开始输入的时间 | 按键 → 第一字上屏毫秒数 | P50 < 500ms / P90 < 1500ms |
| Actions per Capture | 完成一次想法记录的手部操作数 | 鼠标点击次数 + 键盘按键次数 | < 3 次 |
| False Activation Rate | 想保留但丢失 / 想关闭但意外提交的频率 | 自报 1 周使用中的误操作次数 | < 1 次/天为良好 / < 1 次/周为优秀 |
| Window Discoverability | 用户一次想找这个窗口时，能不能 5 秒内找到 | 用户测试（不看 Help 文档） | > 90% 用户 5 秒内成功 |
| Return Friction | 回到之前任务的成本 | 关闭 overlay 后，重新到达"先前工作状态"秒数 | < 1.5s |

### 6.2 Overlay 红线

- ❌ 不允许常驻 3+ 按钮
- ❌ 不允许输入区上方 > 1 行辅助信息
- ❌ 不允许保存数据丢失
- ❌ 不允许视觉噪声 > 2 级（主产品是 3 级）
- ❌ 不允许与主产品视觉语言冲突

### 6.3 交互哲学

**Quiet Chrome**: 输入时只显输入框，hover 边框才显现功能。

| 状态 | 可见元素 |
|------|---------|
| 纯输入态（默认） | 仅 textarea + 极淡边框（opacity 0.3） |
| hover 态 | 顶栏淡入（pin/关闭 button + label） |
| hover history 区 | 各条目的 [✓][⋯] 淡入 |
| 3s 无操作 | 顶栏淡出 → 回到纯输入态 |

### 6.4 输入设计

| 要素 | 规则 |
|------|------|
| 输入组件 | 多行 textarea（max 6 行，auto-resize） |
| Enter | 换行（不打断 / 不提交） |
| Cmd+Enter | 提交（显式操作，误触率极低） |
| 新建 (Cmd+N) | 提交当前 buffer + 清空 + 保持 prefix |
| 字号范围 | 12-22px，Cmd+=/- 调节，持久化到 ~/.clairis/config.toml |
| 主题 | 跟随主窗口，不独立配置 |

### 6.5 Double-Enter 重置

```
prefix mode 下 Cmd+Enter:
  buffer 非空 → 提交，保持 prefix mode
  buffer 空  → Double-Enter 重置 → 清空 prefix → 回到空 mode
```

不需要 Delete 键。手指始终在 Enter 上。

### 6.6 误操作保护

- 关闭 overlay 时未提交 buffer → 静默一次 write 兜底（防 data loss）
- 超小目标（胶囊 44x44）附近的按钮需要 200ms 守卫
- /双击最小化采用 defer single-click pattern 避免 popup 与 restore 打架

### 6.7 独立窗口

Capture Overlay 是独立的模态 — 使用时存在，不用时消失，对主窗口零干扰:

- **打开**: 主窗口 Cmd+Shift+. 触发子窗口创建
- **关闭**: 子窗口独立关闭，不影响主窗口
- **数据**: 共享 store（Rust 层 invoke 回写同一份 inbox-*.md）

### 6.8 多屏

- overlay 默认: **主窗口所在屏**
- 鼠标拖动: 可拖至副屏
- capsule: 跟随 overlay 所在屏停靠

### 6.9 Pin 置顶

Pin = 系统级 always-on-top（覆盖全屏应用）:

- 层级: Jianxi Overlay (pin) > 用户所有窗口 > 桌面
- 即使用户全屏 Keynote 演示，overlay 仍在最上面

### 6.10 历史日链接

每日分隔行 `[查看]` 打开主窗口的文件:

```
│ 今天 · 7 条          [查看]  [折叠 ▴]  │
```

点击 [查看] → `invoke('open_file', { path: '~/documents/inbox/inbox-2026-07-14.md' })` → 主窗口打开当日文件。

## 七、设计红线（Never Do）

| 反模式 | 印哥原话 |
|--------|---------|
| "越多选项越多按钮就越好" | "不是越多选项越多按钮就越好，而是用最少做出更多最方便的功能" |
| 藏功能在 More 菜单 | "抽屉 / 折叠 / 自动隐藏 != 好的发现性" |
| 新建文件弹 Cmd+S 弹窗 | "Cmd+Shift+S 也要弹出窗口，然后选路径命名，是不是也很麻烦" |
| amber 点 + morph 动画 | "全部删除。因为不再有'未保存'这个状态" |
| 默认隐藏工具栏 | "默认隐藏功能不是好的设计" |
| 5 档快捷 | "还是 3 档选项就好，还是分窄/中/宽" |
| 把关闭按钮默认隐藏 | "点击关闭按钮才出现是不必要的视觉复杂度" |

新增红线 (Capture Overlay):

- 不允许 top bar 常驻 > 2 个 icon (关闭 + pin)
- 不允许输入区上方 > 1 行辅助信息
- 不允许 textarea 默认高度 > 6 行
- 不允许保存需要 2 次以上点击
- 不允许 overlay 改变主窗口状态（不切换 tab/不滚动/不刷新）

## 八、印哥的评审方法论（5 步）

印哥在评审任何设计时，按以下顺序追问:

1. **"还有没有更短路径？"** — 任何操作都会被追问能否更简
2. **"这个用户必须知道吗？"** — 信息展示被问价值
3. **"删掉它会怎样？"** — 元素存在必要性被质疑
4. **"能不能让用户不思考？"** — 认知成本被反复压低
5. **"苹果会怎样做？"** — 对标 Apple 级别的产品

设计师必须提前用这 5 个问题 self-check。

## 九、新增功能设计流程

### Phase 0: 需求提出

**输出**: `docs/requirements/REQ-<功能名>-vN.md`

按模板填写:
- 至少 3 个场景故事（谁在什么场景 → 触发什么 → 期望什么）
- P0 诉求列表
- 待决策的开放问题
- 验收标准（每条必须是 pass/fail 可观察）

### Phase 1: 方案设计

**输出**: `docs/designs/<功能名>-v<N>.md`

按模板写:
- ASCII 终态（最少 2 态）
- 键盘覆盖表
- 状态机
- 物理/存储设计
- 评价 Checklist（P0 项全部是 pass/fail）
- 开放决策（C1-Cn，每个附推荐项 + 原因）

### Phase 2: 3 轮 /codex 碰撞

通过 /codex skill 真实调用碰撞，每轮不同角度:

| 轮次 | 焦点 |
|------|------|
| R1 | 场景覆盖 + 核心交互 + 竞品对标 |
| R2 | 键盘覆盖 + 误操作保护 + 状态机完整性 |
| R3 | 性能边界 + 多端兼容 + 未来扩展性 |

仅当 /codex 调用失败且印哥确认，才退回到 `delegate_task`。

### Phase 3: 决策点集中

提取 ≥ 4 个**设计师无法自己判断**的决策点:

```
C1: [问题]
- A: [选项] 优点: 缺点:
- B: [选项] 优点: 缺点:
- 设计师推荐: [A/B] 原因:
```

印哥确认后 → 方案定稿。

### Phase 4: 实施规格

**输出**: `docs/<功能名>-SPEC.md`

- 新增 / 修改文件列表
- 每个文件的 API / 接口签名
- 状态机的代码映射
- 测试用例（E2E 验收用）

### Phase 5: 代码实现 + 自测

**先通过内置浏览器完成真实自测**，收工后才交印哥实测。

自测清单:
- [ ] P0 Checklist 全部过
- [ ] 每个键盘快捷键都能按
- [ ] 每个状态机转换都通
- [ ] 关闭 / 横移 / 多屏场景测过
- [ ] 3 个典型场景故事都跑通

### Phase 6: 印哥验收

实测通过 → 归档至 `docs/archive/`，版本 +1。

## 十、教训追踪

记录每次修复错误的根因，避免重复:

| 错误 | 后果 | 修正 |
|------|------|------|
| 把 Cmd+S 从快捷键表移除 | 用户仍然想手动保存 | 加 Ctrl+S (无 UI) |
| amber 点 + morph 动画 | 视觉复杂度增加 | 直接删除 |
| 5 档快捷 | 认知负荷 | 3 档 + 滑块 |
| 独立的 [+] 全屏按钮 | 多余元素 | 预览 icon 变 Maximize2 |
| overlay 单行 input | 多行情绪输出障碍 | 改为 textarea |
| overlay 双 Enter 语义读错 | 保存逻辑全部推翻 | prefix 模式 + Double-Enter 重置 |
| overlay 顶栏过度设计 | 按钮多、噪声大 | Quiet Chrome + 双击最小化 |
| 缺少评价体系 | "摸弄" 式迭代 | 定 5 维度 + Checklist |
