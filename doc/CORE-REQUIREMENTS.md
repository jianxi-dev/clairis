## 一、产品定位

### 一句话定义

**轻量秒开的 Markdown 阅读编辑器** — 让不懂 Markdown 的普通用户也能优雅地查看和编辑文档，并在阅读中获得愉悦体验。

### 核心价值

```
美观 > 功能 > 性能 > 扩展
```

我们优先保证阅读体验的优雅和愉悦，其次才是功能完整度。性能（秒开）是基本线，扩展性是远期考量。

### 目标用户

| 用户画像 | 占比 | 特征 | 使用场景 |
|----------|------|------|----------|
| **普通阅读者 (核心)** | 70% | 不懂 Markdown 语法，需要即开即看 | 打开 .md 文件像看书一样阅读 |
| **轻度编辑者 (次核心)** | 20% | 偶尔修改格式或新增内容，习惯点按操作 | 调整标题、加粗、插入列表/表格 |
| **技术用户 (辅助)** | 10% | 熟悉 Markdown 语法，需要源码控制 | 直接写 Markdown，精确控制格式 |

### 与竞品的差异

| 维度 | MDWRT | Typora | Obsidian | VS Code |
|------|-------|--------|----------|---------|
| 启动速度 | <1s (Tauri) | ~2s (Electron) | ~3s (Electron) | ~5s (Electron) |
| 用户门槛 | 极低，不暴露语法 | 低-中 (已有主题/公式/Mermaid/导出等) | 中，需理解 Markdown | 高，面向开发者 |
| 默认体验 | 开箱即美(排版/主题) | 默认较简陋，需选主题 | 需折腾主题+插件 | 需配置插件 |
| 功能丰富度 | 聚焦阅读美观+基础编辑 | 成熟(主题/公式/图表/导出/TOC/字数) | 知识库+双向链接+图谱 | 无限扩展 |
| 文件组织 | 单文件 → 目录树 + 多页签 | 文件树 | 知识库/双向链接 | 工作区 |
| 跨平台 | macOS → Windows → 移动端 (远期) | macOS + Windows + Linux | 全平台 | 全平台 |
| 阅读质量 | 独立渲染引擎，可达极致排版 | 编辑器即渲染 | 主题依赖 | 代码风格 |

## 二、核心需求 (P0 — 必须实现)

### 2.1 阅读体验

| 需求 | 描述 | 验收标准 |
|------|------|----------|
| **秒开** | 冷启动 <1s, 打开 .md 文件即显示 | 双击 .md 文件后窗口显示到内容可读 <1.5s (基线: M1 Mac, 50KB .md 文件) |
| **完整 GFM 渲染 (P0)** | 支持标准 GFM 语法 (表格/任务列表/代码块/引用/图片/链接/粗斜体/列表/分割线) | 所有 GFM 语法正确渲染 |
| **扩展语法渲染 (P1+)** | LaTeX 公式、Mermaid 图表、Obsidian Callouts (非 GFM 标准，Phase 1 起补充) | 独立于 P0 交付 |
| **纯阅读模式** | 隐藏所有工具栏/面板，全屏沉浸阅读 | 一键切换阅读/编辑模式，动画过渡 |
| **字体排印** | 默认排版参考 Medium/微信读书水准 (字号/行距/字距/对比度/窄栏宽/留白) | 打开即舒适阅读，无需任何调整 |
| **Dark/Light 主题** | 自动跟随系统 + 手动切换 | 两套完整配色方案，切换顺滑 |
| **滚动顺滑** | 60fps 平滑滚动，大文件不卡顿 | >500KB 文件流畅滚动 (编辑器 decoration 在该阈值下自动禁用) |
| **阅读进度指示** | 侧边或顶部显示当前阅读进度 | 滚动时进度条实时更新 |

### 2.2 L2 级 WYSIWYG 编辑 (Typora 风格)

编辑模式的核心是 **Markdown 语法标记被视觉美化/隐藏，但底层始终保持纯 Markdown 文本**。

| 需求 | 描述 | 验收标准 |
|------|------|----------|
| **语法标记美化** | 编辑时 `#`/`**`/`*`/`` ` ``/`> ` 等符号淡化或替换为可视化元素 | 用户几乎看不到 raw 语法标记 |
| **标题可视化** | `### 标题` → `[H3 ▼] 标题` (下拉可选1-6级) | 点击标签下拉可切换标题级别 |
| **加粗斜体** | `**粗体**` → 粗体显示(隐藏 `**`)；`*斜体*` → 斜体显示(隐藏 `*`) | 选中文本 + Cmd/Ctrl+B/I 切换 |
| **列表美化** | `- 无序` → • 无序；`1. 有序` → 1. 有序 | 符号淡化显示 |
| **任务列表** | `- [ ] 任务` → ☐ 任务，可点击切换 | 点击 checkbox 切换 `[ ]`↔`[x]` |
| **引用美化** | `> 引用` → 左侧灰线 + 灰色背景块 | `>` 符号隐藏，视觉块展示 |
| **代码美化** | `` `代码` `` → 灰底等宽字体；``` `代码块` ``` → 带高亮的代码块 | 反引号隐藏 |
| **链接美化** | `[显示](url)` → [显示] 蓝色可点击 | URL 默认隐藏，hover 或选中时露出 |
| **表格编辑 (简单)** | 工具栏按钮插入/删除行和列，单元格内编辑 | 不拖拽列宽，自适应文本 |
| **图片插入** | 支持本地文件对话框选择 + 粘贴 | 自动转为相对路径，兼容多种图片格式 |
| **工具栏 (轻量)** | H1-H6 / B / I / 列表 / 任务 / 引用 / 代码 / 表格 / 链接 / 图片 | 正好覆盖常用格式，不臃肿 |
| **快捷键** | B/I/U/S/O/T/Shift+M 等 10+ 快捷键 | 高频操作可盲操 |
| **源码模式** | 切换到原始 Markdown 编辑，无装饰 | Cmd/Ctrl+Shift+M 切换，保留编辑状态 |

**「#」标题标记处理策略:**

```
为什么不在编辑器中完全隐藏 #:

  用户需要在编辑时感知当前标题级别
  完全隐藏 → 误写 H1 为 H3 看不出
  
为什么不在编辑器中暴露 raw ##:

  对普通用户不友好，界面不干净
  
解决: 将 "## " 替换为可视化标签 "[H2 ▼]"
  
  - 标签显示当前标题级别
  - ▼ 下拉可选 1-6 级或切换为段落
  - 下拉选择后 → 自动修改底层文本的 # 数量
  - 选中时露出原始符号，可选手动修改
```

### 2.3 文件管理

| 需求 | 描述 | 验收标准 |
|------|------|----------|
| **单文件打开** | 系统对话框选择 .md 文件 | Cmd+O，文件类型过滤 .md .html .txt |
| **拖拽打开** | 拖拽文件到编辑器窗口 | 松开即打开，支持 .md / .html / .txt |
| **.txt 文件处理** | .txt 以纯文本方式阅读和编辑，不做 GFM 渲染 | 无格式退化 |
| **双击 .md 文件** | 系统文件关联，双击即用 MDWRT 打开 | macOS 通过配置 plist 实现 |
| **保存** | 原子写入，崩溃不损坏原文件 | tempfile → persist 模式 |
| **自动保存** | 编辑停止 2 秒后自动保存 | 无需手动 Cmd+S |
| **最近文件** | 侧边栏顶部列出最近打开的文件 | 5 个，点击即开，支持清除历史 |
| **文件夹浏览** | 左侧边栏选择文件夹，树形显示目录 | 展开/收起目录，点击文件在右侧打开 |
| **多页签** | 右侧预览区支持多个页签同时打开 | 页签可关闭、切换、拖拽排序 (Phase 1) |
| **文件关联配置** | 首次启动询问是否设为 .md 文件默认打开方式 | 可选，不强制。不关联 .html (避免安全风险) |

### 2.4 HTML 文件支持

| 需求 | 描述 |
|------|------|
> ⚠️ HTML 预览/编辑为 Phase 2 功能。本节仅记录需求规范。

| **HTML 预览** | 打开 .html 文件，在渲染区以网页方式预览 |
| **HTML 编辑** | 切换到编辑模式后，以 CodeMirror HTML 语法高亮编辑 |
| **格式切换** | 预览/编辑一键切换 |
| **安全性 (详)** | 预览使用 `srcdoc` + sandbox 属性 (不含 `allow-same-origin`)。CSP 通过注入 `<meta http-equiv="Content-Security-Policy">` 实现。资源加载需本地资产代理 (Tauri custom protocol) + 路径白名单。禁止 `file://`/`javascript:`/`tauri:` 协议。通过 Tauri 资产协议提供相对路径支持 |

### 2.5 翻译功能

> ⚠️ Cmd/Ctrl+T 是目前翻译快捷键。注意该快捷键在浏览器/Safari 等软件中为"新建标签页"，有可能与用户习惯冲突。设计时需提供快捷键自定义或首次使用时提示。

| 需求 | 描述 | 验收标准 |
|------|------|----------|
| **本地翻译** | 配置 Ollama 本地端点，调用本地模型翻译 | 流式输出，逐字显示 |
| **云端翻译** | 配置 OpenAI 兼容 API (密钥存 keyring) | 流式输出，逐字显示 |
| **全文翻译** | 打开翻译侧边栏，翻译整篇文档 | 原文分段左右对照或上下对照 |
| **选中段落翻译** | 选中文本后右键/快捷键翻译选中内容 | 不整篇翻译，仅翻译选中文字 |
| **语言配置** | 可配置源语言/目标语言 | 保存为配置 |
| **翻译历史** | 同一个 requestId 去重，单活跃 slot | 新翻译自动取消上一次 |

## 五、技术选型 (已决策)

| 层 | 选型 | 理由 |
|----|------|------|
| 壳 | Tauri v2 | 秒开、小体积、跨平台 |
| UI 框架 | React 18 + TypeScript + Vite | 生态好，团队能力匹配 |
| 编辑器内核 | CodeMirror 6 | GFM 原生支持，decoration API 实现 L2 美化，轻量 |
| 阅读渲染 | marked + DOMPurify + 自定义 CSS 引擎 | 独立于编辑器，可做到极致排版。DOMPurify 确保输出安全 HTML |
| 状态管理 | Zustand | 简单 TS 友好，可演化为多页签 store |
| 样式 | Tailwind + 自定义主题 CSS | 开发效率高，主题系统的基础 |
| 翻译后端 | Rust reqwest (Ollama + OpenAI) | 安全防 SSRF，需完善隐私确认流程 |
| API Key 存储 | OS keyring (keyring crate) | 安全，不落盘明文 |

### 为什么放弃 TipTap

| 对比项 | CodeMirror 6 (L2) | TipTap (ProseMirror) |
|--------|-------------------|---------------------|
| GFM 完整度 | 原生全支持 | 每个格式需扩展，兼容性差 |
| 存储格式 | 纯 Markdown，零转换 | 需 markdown↔PM 来回转 |
| 阅读质量 | 独立渲染图层，不受编辑器限制 | 渲染被编辑器绑定 |
| 代码块/公式 | CM6 扩展生态成熟 | 扩展重度依赖 @tiptap 生态 |
| 启动开销 | CM6 轻量，毫秒级初始化 | TipTap 初始化 PM schema 更重 |
| 移动端 | 纯 Web 技术，迁移友好 | Tauri mobile 兼容 |
| 学习成本 | 团队已有 CM6 集成经验 | 需额外学习 PM 知识 |

## 六、已知技术风险

### 6.1 CM6 L2 编辑器 — 硬问题

| 风险 | 说明 | 缓解策略 |
|------|------|----------|
| **点击导航 vs 点击编辑** | L2 模式下链接可点击，但用户可能想点链接位置放置光标 | 方案: Cmd+Click 导航链接，纯 Click 放置光标 |
| **IME 输入法组合** | 中文/日文输入法在 decoration 替换模式下的光标和 composition 处理 | P0 方案: composition 激活时自动降级为无装饰/暴露 raw 语法标记，composition 结束后恢复 decoration。P1 再优化完整 IME 体验 |
| **复制粘贴语义** | 从外部粘贴 HTML/富文本时，strip 为纯 Markdown。粘贴前需过 DOMPurify 消毒 + URL 协议过滤 | 粘贴通道: 消毒 → 转换 → 限制大小 → 插入 |
| **嵌套标记** | `_**粗斜体**_` 等嵌套语法在 decoration 中的展示 | 使用 CM6 stream parser 层级标记处理 |
| **逃逸字符** | `\*not italic\*` 等逃逸序列的显示 | CM6 `markdown` language parser 原生处理 |
| **格式受损回退** | 用户手动输入 `##` 后 CM6 decoration 应实时更新 | decoration range 动态监听文本变更 |
| **大文件 >500KB** | decoration 数量过多导致卡顿 | 自动关闭 decoration，降级为无装饰源码模式 |

### 6.2 翻译 & 隐私

| 风险 | 说明 |
|------|------|
| **发送全文到云端** | 开启 OpenAI 翻译时会将文档全文发送到第三方 API，需用户明示同意 |
| **Token 消耗失控** | 长文档翻译可能消耗大量 API token，应显示预估量并在超过阈值时确认 |

### 6.3 渲染安全

| 风险 | 说明 |
|------|------|
| **marked 不消毒** | marked 官方不保证输出安全 HTML。渲染阅读模式前需过 DOMPurify 或类似消毒层 |
| **HTML iframe 安全** | HTML 预览模式需 CSP 限制 + sandbox 属性禁止导航/脚本/表单/外部资源加载 |

### 6.4 已知待清理项

- `package.json` 仍保留 TipTap/ProseMirror/turndown 依赖 (v1 遗产)。Phase 0 启动前清理

│  │  ├ 文件 I/O (dialog + fs + tempfile::persist)     │  │
│  │  ├ 目录浏览 (fs::read_dir 树形返回)               │  │
│  │  ├ 文件关联 (macOS plist / Windows reg)           │  │
│  │  ├ Config + keyring                               │  │
│  │  ├ 翻译代理 (Ollama + OpenAI, 流式)               │  │
│  │  └ 日志 (tracing)                                 │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘

数据流:
  文件 → Rust fs::read → store (content, fileKind) → 渲染层

  文件类型分支:

  ┌─ fileKind=markdown ──────────────────────────────┐
  │  阅读:  marked → DOMPurify → 精美 CSS 渲染        │
  │  编辑:  CM6 + decoration L2 (IME 降级)            │
  │  保存:  原样写回 (纯 markdown)                    │
  ├─ fileKind=html ───────────────────────────────────┤
  │  阅读:  iframe srcdoc + CSP + sandbox              │
  │  编辑:  CM6 HTML 语法高亮                         │
  │  保存:  原样写回                                  │
  ├─ fileKind=text ────────────────────────────────────┤
  │  阅读/编辑: 纯文本 (不做 GFM/HTML 渲染)            │
  │  保存:  原样写回                                  │
  └────────────────────────────────────────────────────┘
  
  保存: store.content → Rust fs::write (tempfile::persist)
```

## 八、盈利模式分析

### 定位

MDWRT 不是一个流量产品，而是一个**付费工具产品**。目标不是 100 万用户免费，而是 1 万用户每年付费 $20-30。

### 推荐策略: Freemium + 一次性买断

| 版本 | 定价 | 功能 |
|------|------|------|
| **免费版** | $0 | 阅读模式 + 基础编辑 (H/B/I/列表/引用/代码/表格) + 源码模式 + 代码高亮 + 文件打开 + 最近文件 |
| **Pro 版** | $14.99 一次性买断 | 翻译功能 + 自动目录/统计/笔记 + 主题系统 + LaTeX/Mermaid/Callouts + 导出 PDF/HTML + 多页签 + 侧边栏文件树 |
| **企业版** (远期) | 按需定价 | 私有部署 + 管理控制台 + SSO |

### 为什么选这个模式

| 考虑 | 说明 |
|------|------|
| **用户群体** | 普通用户不愿意订阅制，但可以接受低单价买断 |
| **对标 Typora** | Typora 从免费→$14.99 一次性付费，验证了 markdown 工具的商业价值 |
| **开源与否** | 建议开源免费版核心代码 (MIT)，Pro 版闭源。好处: 社区贡献 bug fix、提升品牌信任度 |
| **为什么不开源全部** | 纯开源靠赞助的月收入中位数 <$100，不足以覆盖开发投入 |
| **发布渠道** | Mac App Store + 官网下载 (官网分成 100%) |

### 开源策略

- **免费版代码** → GitHub MIT 开源
- **Pro 功能** → 闭源，通过包管理 (npm private registry 或 Rust crate feature gate)
- **运营** → 不需要"运营"。提 PR/提 issue 正常维护，主要精力在产品本身
- **收入目标** → 月均 $500-1000 就算成功 (覆盖云服务 + 证书成本)

### 收入估算 (保守)

| 渠道 | 转化率 | 假设用户量 | 年收入 |
|------|--------|-----------|--------|
| GitHub → 免费用户 | 5% 下载率 | 10,000 下载 | — |
| 免费→Pro 转化 | 10% | 1,000 付费 | $14,990 |
| Mac App Store | 自然流量 | 500 购买/年 | $7,000 (苹果抽 30% = $4,900) |
| 合计 | | | ~$20,000/年 |

> 不能靠这个覆盖全职收入，但作为 side project 实现正的 cash flow 是可行的。
>
> ⚠️ **收入估算的假设风险:** 10,000 GitHub 下载 → 1,000 付费用户 (10% 转化率) 偏乐观。markdown 工具市场免费竞品多，实际转化率可能在 2-5%。保守估计首年收入 $5,000-10,000。收入预期不宜过高。
>
> ⚠️ **15-21 周时间线风险:** 跨平台 + 完整 GFM + L2 编辑器 + 文件系统 + 翻译 + HTML 沙箱 + 侧边栏/页签 + LaTeX/Mermaid + 移动端适配，开发量显著高于 15-21 周的估计。建议 Phase 0 按 4-6 周规划，整体 6-12 个月。移动端和 Windows 支持应独立评估。

## 十、关键决策记录

| 决策 | 选择 | 理由 | 替代方案被否原因 |
|------|------|------|----------------|
| 框架 | Tauri v2 | 秒开小体积 | Electron (~3s 启动，~300MB 打包) |
| UI | React + TS + Vite | 团队能力匹配 | — |
| **编辑器** | **CodeMirror 6 (L2)** | **GFM 原生 + 零转换损耗 + 轻量** | TipTap GFM 兼容性差、roundtrip 损耗 |
| 阅读渲染 | 独立 HTML 渲染层 | 不受编辑器限制，极致排版 | ProseMirror 渲染 = 编辑器渲染 |
| 状态管理 | Zustand | 简单 TS 友好 | — |
| 样式 | Tailwind | 开发效率 | — |
| 存储格式 | 纯 Markdown | 无转换损耗，用户可读 | HTML/PM JSON 会锁死数据 |
| 盈利 | Freemium + 一次买断 | 匹配用户预期 | 订阅制对工具类产品阻力大 |
| 开源 | 免费版 MIT + Pro 闭源 | 社区贡献 + 收入两全 | 全开源零收入; 全闭源无社区 |
| 翻译本地端 | Ollama | 免费、隐私安全 | — |
| 翻译云端 | OpenAI API (keyring) | 高质量、兼容多模型 | 自己维护翻译引擎不现实 |
