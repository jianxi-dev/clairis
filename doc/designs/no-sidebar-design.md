# 渐明无侧栏设计方案 

> 来源：5 轮 Claude + Codex 创意碰撞（2026-07-03）
> 关联：PLAN-REVIEW-LOG.md、the-desk-concept.md、design-concept-v3.md

---

## 一、核心论题

**侧栏的真正功能不是文件管理——是安全感。** "你的文件还在，你没丢东西。"

去掉侧栏不能只做减法。必须提供等价的安心感，用全新的方式。

### 推翻的假设

| 旧假设 | 新命题 |
|--------|--------|
| 用户需要"找到"文件 | 文件应该来找用户 |
| 文件管理 = 层级组织 | 文件管理 = 空间记忆 + 认知共鸣 |
| 导航 = 视觉扫描列表 | 导航 = 召唤 + 场所 + 仪式 |
| 打开文件 = 工具操作 | 打开文件 = 产品标志性愉悦 |
| 读完 = 结束 | 读完 = 仪式性收尾 |

### 四条红线（对齐产品原则）

| 原则 | 无侧栏方案如何兑现 |
|------|-------------------|
| **快** ⚡ | 没有侧栏需要加载。Resonance 是后台索引，零阻塞 |
| **方便** 🖐️ | Cmd+↑ 书桌、Cmd+K 召唤、双击即读。全键盘 |
| **舒服** 😌 | 无信息过载。桌面最多 7±2 个文档，不存在"200 个文件的文件夹" |
| **喜欢** ❤️ | 书角折痕、墨迹遗存、阅读完成仪式——打开和关闭都让人愉悦 |

## 二、三层架构

```
┌──────────────────────────────────────────────────────────┐
│                    第三层：The Desk（书桌）                 │
│                    Cmd+↑ / 捏合触发                       │
│                   全场景转换，非面板                       │
├──────────────────────────────────────────────────────────┤
│                    第二层：Resonance（共鸣）                │
│                    被动感知，无需操作                       │
│                    边写/边读边浮现关联                      │
├──────────────────────────────────────────────────────────┤
│            ┌─────────────────────────────────┐            │
│            │        第一层：Surface（表面）    │            │
│            │    100% 屏幕 = 你的内容           │            │
│            │    无按钮、无面板、无文件信息      │            │
│            │    唯一可见：文字 + 书角折痕       │            │
│            └─────────────────────────────────┘            │
│                                                          │
│   ──── Time Bands（时间带）──── 贯穿三层的横向纹理 ─────  │
│   ──── Ink Relics（墨迹遗存）── 贯穿三层的纵向深锚 ─────  │
└──────────────────────────────────────────────────────────┘
```

### 第一层：Surface（表面层）

**用户永远身处这一层。** 这是默认可视态——纯内容，零 chrome。

写作者看到：暖白纸面，日期如干墨，光标等待
读者看到：排版完成的一篇文章，可直接阅读

**规则：**
- 没有任何按钮、面板、侧栏指示器
- 工具栏不显示，仅在鼠标移至屏幕顶部 2px 边缘时浮现（极淡 12px 线）
- Tab 栏不存在——切换文档通过书桌或 Cmd+K 完成
- 状态信息藏入墨痕：字数、进度、时间——都不是"条"或"栏"，是纸的纹理

### 第二层：Resonance（共鸣层）

**被动智能层。** 不需要用户操作。当你在 Surface 层打字或阅读时，Resonance 在后台工作。

**写作者时的共鸣：**
```
你暂停输入。段落右侧出现一段淡墨文字——
"设计不是解决问题…"（摘自 设计哲学.md, 3天前）
不是弹窗，不是卡片。像另一页纸的墨水洇透了这一页。
你按 Tab，当前页淡出，那篇旧文档在精确段落打开。
```

**读者时的共鸣：**
```
你读到"注意力经济"。页面边缘微温。
hover 看到一行："我在《数字极简》笔记里也提过这个词。"
点击回到那篇笔记的精确段落。
不是 AI 推荐。是"我刚刚读到过那个。"
```

**技术方案：**
- 纯本地运算，无需联网，无需 AI
- 段落级 BM25/TF-IDF 索引 + 标题匹配 + 反向链接 + 时效衰减
- 置信度不足时不展示任何内容
- 启动时 + 文件变更时后台重建索引
- 后续可加入本地 embeddings（ollama 或 CoreML）

### 第三层：The Desk（书桌层）

**主动导航层。** 用户主动触发，全场景转换。不是面板，不是侧栏——是编辑器本身的"抬起头"状态。

详见下文 §四。

## 三、用户流程全景

### 写作者全天流程

```
 打开渐明 ──→ Surface 层：上次的文档在精确位置等待
                │
   开始打字     │ 页面安静铺开，无保存焦虑，无文件名要求
                │
   暂停思考     │ Resonance 在边缘浮现关联片段
   按 Tab       │ 跳转到旧文档的精确段落（不离开 Surface 层）
                │
   想切换文档   │ Cmd+↑
                │
               ┌▼──────────────────────────────┐
               │      The Desk                  │
               │  当前页缩小，桌面出现            │
               │  5 个文档按空间记忆排列          │
               │  最近的伸手可及，旧的稍远半透明   │
               │                                │
               │  点击某个文档                    │
               └────────────────────────────────┘
                │
   新文档展开   │ 回到 Surface 层
                │
   写完一段     │ 右下角出现极淡的"完成"标记
   关闭窗口     │ 页角轻轻折起，保留位置
                │
   明天打开     │ 书角折痕停留 0.5 秒后平展
                │ "页面记得我的手在哪里。"
```

### 读者全天流程

```
 双击 .md 文件 ──→ Surface 层：直接排版完成的一篇文章
                    文件名在标题上方淡入后消失
                    第一印象："文档变得可读了。"
                     │
   滚动阅读      右侧边缘的墨色深度显示进度
   停在标题      "已读"标记像压花般出现
                 hover 可复制路径或在 Finder 中打开
                     │
   读到末尾      最后一行带有安静的停顿，不是生硬停止
   阅读完成      底部边距打开，像页面呼出一口气
                 三组淡墨操作：重读、标记已读、打开另一篇
                     │
   打开新文件    Cmd+O 或 拖拽 .md 到页面任意处
                当前页轻抬让出空间，新文档落在上面
                     │
   关闭页面      页面折叠成一条细墨线后消失
                 "文档被妥善收好，不是遗失。"
```

### 阅读完成时刻（10 秒细读）

这是渐明最独特的体验之一：

| 时间 | 体验 |
|------|------|
| 0s | 最后一行抵达。底部边距自然打开，像页面呼出一口气 |
| 1s | 最后一段停留在视野中，不是硬停止。让你把最后一句话看完 |
| 3s | 墨痕出现：文档标题、阅读时间、单个"已读"标记。存档感 |
| 5s | 结尾下方的纸变半透明——桌面隐约可见。2-3 张相邻纸页，每张显示一句"活着的句子"：同一文件夹的、最近打开过的、与本文共鸣的 |
| 7s | 光标移向某句话 → 当前文档轻抬让出空间。点击打开那张纸，拖拽 .md 到桌面，或直接关闭 |
| 10s | 关闭 → 页面折叠成一条细墨线后消失。文档被收好，不是遗失 |

## 四、The Desk（书桌）详细设计

### 触发方式

| 方式 | 描述 |
|------|------|
| **键盘** | `Cmd+↑` — 直觉：抬起头看周围 |
| **触控板** | 三指捏合 — 与 Mission Control 肌肉记忆一致 |
| **鼠标** | 移到屏幕最上边缘悬停 400ms — 仅作为发现路径 |
| **阅读完成时** | 读完文档后自动浮现（§三完成时刻 5s 处） |

### 视觉转换

```
                    Cmd+↑
  ┌──────────────────────┐
  │                      │
  │   当前文档全屏        │
  │   文字在呼吸          │
  │                      │
  └──────────────────────┘
           │
           │ 0.3s ease-out 过渡
           │ 页面升起，文字淡化成缩略
           ▼
  ┌──────────────────────────────────┐
  │  ╔════════════════════════════╗  │
  │  ║   设计哲学.md              ║  │  ← 当前文档缩小，带阴影漂浮
  │  ║   设计的本质不是解决…       ║  │     像你举起了一页纸
  │  ║   last edited 3h ago       ║  │
  │  ╚════════════════════════════╝  │
  │                                  │
  │  ┌──────────┐   ┌──────────┐     │
  │  │ 周会记录  │   │ 架构笔记  │     │  ← 最近 5 个文档
  │  │ 昨天      │   │ 2 天前   │     │     按空间记忆排列
  │  │ "讨论了…"  │   │ "Rust和…" │     │
  │  └──────────┘   └──────────┘     │
  │                                  │
  │     ┌──────────┐                 │
  │     │ 排版规范  │                 │  ← 稍远半透明
  │     │ 5 天前   │                 │
  │     └──────────┘                 │
  │                                  │
  │   ── 底部：墨痕 ──────────────   │
  │    ↑ 搜索 / Ink Relic           │
  └──────────────────────────────────┘
```

### 桌面布局逻辑

**位置决定意义，非随机：**

| 区域 | 含义 |
|------|------|
| 中央偏左（伸手可及） | 刚刚还在写的/读的 — 最近活跃 |
| 右侧堆叠 | 刚在参考的 — 对照/引用 |
| 左上方远处 | 几小时前的 — 稍远记忆 |
| 半透明/在边缘 | 几天前的 — 知道存在但不突出 |
| 叠在一起 | 同一主题的一组文档 |

**约束（来自 Codex 风险警告）：**

> "空间记忆听起来很美，但位置如果是随机的，就会坍缩成 Pinterest。"

1. 位置**必须稳定** — 同一文档每次回到桌面时在同一个位置
2. 文档数**必须稀疏** — 最多 7±2 个（认知负荷上限）
3. 超过 9 个 → 最近的 5 个 + 2 个关联 + 2 个被遗忘的（Ink Relic 推荐）
4. 用户**不能手动"整理"桌面**——一旦可整理，就变回另一个文件树

### 交互矩阵

| 动作 | 结果 |
|------|------|
| 点击文档 | 展开到全屏（回到 Surface 层） |
| 拖拽到另一个文档上 | 两者建立关联（反向链接） |
| 拖拽到右下角废纸篓微痕 | 归档（非删除） |
| 悬停 | 稍大预览 + 时间 + 字数 |
| Cmd+F 在桌面状态 | 搜索所有文档（"桌面浮墨"） |
| 空白处右键 | "新文档出现在手边" |
| Esc 或 Cmd+↓ | 回到当前文档 |
| 15 秒无操作 | 自动回到当前文档（桌面不是停留的地方） |

## 五、四个概念详解

### 5.1 Resonance（共鸣）

**一句话：** 打字时暂停，旧文档的片段在页面边缘浮现。非搜索，非 AI 推荐——认知共振。

**实现路径：**

```
Phase 1 — BM25 本地索引
   ├ 启动时扫描所有打开过的 .md 文件
   ├ 段落级分块（按标题分节）
   ├ 建立倒排索引 (TF-IDF)
   └ 实时匹配当前段落 → 返回 top-3 片段

Phase 2 — 反向链接 + 重复短语增强
   ├ 解析 [[wikilink]] 和 [显示](路径) 格式
   ├ 检测重复出现的短语/概念
   └ 加入时效衰减（近期文档权重更高）

Phase 3 — 本地 embeddings（可选）
   ├ Ollama / CoreML 本地模型
   ├ 语义相似度匹配
   └ 置信度更高，召回更广
```

**交互规格：**

- 仅在用户暂停 >2 秒时触发（打字时不干扰）
- 最多显示 3 个片段，在段落右侧/下方
- 置信度 < 阈值时完全不显示
- 片段样式：淡墨色（`color: rgba(0,0,0,0.25)`），比正文淡，hover 加深
- 按 Tab 或点击 → 交叉淡入到目标文档的精确段落
- 不创建"搜索结果页"，不打断当前流

**阅读模式下的 Resonance：**
- 读到时，同文件中的相关段落共鸣（同一主题的后续/前文）
- 读完时，跨文件共鸣（下一条推荐阅读）

### 5.2 Time Bands（时间带）

**一句话：** 时间不是列表，是氛围。从页面顶缘下拉，时间像拉伸的湿纸。

**行为纹理（不分析情绪）：**

| 纹理 | 视觉表现 | 含义 |
|------|----------|------|
| 高密度写作段 | 颜色深、行距紧 | 那天写了很多 |
| 反复修改段 | 边缘模糊、微微抖动 | 反复改同一段 |
| 废弃开头 | 浅色、不完整形状 | 写了一半放弃的 |
| 长暂停 | 大片空白 | 思考了很久 |
| 删除疤痕 | 细碎的点状纹理 | 大量删除的痕迹 |

**交互：**

- 从页面顶部（日期标记处）下拉
- 时间线以视觉节奏展开，不是列表
- 拖拽穿过时间带 → 捕捉到一个句子 → 释放后打开那篇文档
- 200+ 篇/天的情景坍缩成爆发段："早上的冲刺""导入的那批"

### 5.3 Ink Relics（墨迹遗存）

**一句话：** 你反复写过的概念会结晶成墨迹。拖拽墨迹到页面中央，所有承载过它的文档层叠浮现。

**这东西从哪来：**
- 自动检测：跨文档反复出现的名词/短语/地名/人名
- 用户标记：选中一段文字，`Cmd+Shift+R` → "记住这个"
- 从 Resonance 升级：同一片段被多次共鸣 → 自动升格为 Relic

**交互：**

```
你写过很多次"注意力"这个词。
它不是标签，不是文件夹——

┌──────────┐
│ 注意力    │  ← 一个 Relic，在书桌底部或页面边缘
└──────────┘

把它拖到页面中央 →

┌──────────────────────────────────┐
│                                  │
│   当前文档变暗                    │
│                                  │
│   「注意力经济」— 数字极简.md      │ ← 层叠浮现
│   「注意力的危机」— 周会记录.md    │
│   「注意力是唯一的货币」— 哲学.md  │
│   「注意力的设计」— 设计咨询.md    │
│                                  │
│   每篇只显示包含"注意力"的段落      │
│   点击 → 在那段精确位置打开        │
│                                  │
└──────────────────────────────────┘
```

**跟标签的区别：**
- 标签是主动分类，Relic 是自然结晶
- 标签需要命名，Relic 不需要——它就是那个词本身
- 标签是平面列表，Relic 是"持有"它的文档集合
- 标签需要手动维护，Relic 自动出现和淡去

### 5.4 The Bookmark Fold（书角折痕）

**一句话：** 关闭不是退出命令，是放置页面的手势。右下角轻轻折起，保留精确位置。

**视觉：**

```
关闭前                           关闭后（下次打开时 0.5s）
┌──────────────────────┐        ┌──────────────────────┐
│                       │        │                       │
│                       │        │                       │
│   最后一段文字         │        │   最后一段文字         │
│   停留在视野中         │        │   停留在视野中         │
│                       │        │                       │
│                       │        │              ╔════╗   │
│                       │        │              ║ 折 ║   │  ← 淡墨色折痕
│                       │        │              ║ 角 ║   │     0.5s 后平展
└──────────────────────┘        └──────────────╚════╝───┘
```

**规则：**

| 场景 | 折痕行为 |
|------|----------|
| 读完（滚动到末尾） | 折痕在末尾，带"已读"标记 |
| 中途关闭 | 折痕在关闭时的位置 |
| 未读任何内容 | 无折痕 |
| 下次打开 | 折痕停留 0.5 秒后平滑展开，光标/视线落在折痕处 |
| 新建未保存文档 | 不折（没内容可记住） |

**加入此功能的理由（来自 Codex 原话）：**

> 关闭变成物理动作："我把页面放在这里。"
> 重开变成："页面记得我的手在哪里。"

## 七、与现有架构的关系

### 无侧栏状态 = readingMode 的进化

当前已有 `readingMode: boolean`，隐藏侧栏 + 工具栏 + Tab 栏。

无侧栏方案将其变为**默认状态**：

```diff
- readingMode: 阅读模式, 可选
+ surfaceMode: 默认模式, 始终为 true
```

### Store 变更

```typescript
// 现有 store 需新增
interface AppStore {
  // ... 现有字段

  // 无侧栏新增
  deskMode: boolean;            // 是否在 Desk 层
  lastScrollPositions: Record<string, number>;  // 每篇文档的阅读位置
  bookmarkFolds: Record<string, {
    position: number;           // 滚动位置
    sentence: string;           // 最后可见句子
    completed: boolean;         // 是否已读完
  }>;
  resonanceIndex: {
    // BM25 倒排索引（存在内存或 SQLite）
    // 非 React 状态，通过 worker 管理
  };
  inkRelics: Array<{
    phrase: string;
    docRefs: Array<{ path: string, paragraphs: number[] }>;
    strength: number;  // 0-1, 低于阈值自动衰减小
  }>;
}
```

### 工具栏降级

从现有常显 → 仅在以下情况浮现：
1. 鼠标移到屏幕最上 2px 边缘
2. `Cmd+Option` 键按下
3. 悬浮 400ms 后，12px 高的细线变成 28px 工具栏

## 九、Codex 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 空间记忆位置随机化 → Desk 坍缩成 Pinterest | 中 | 高 | 位置必须稳定，同一文档永远在同一位置 |
| Resonance 置信度不足 → 从不显示（无用） | 高 | 中 | BM25 调参 + 渐进展示：低置信度时缩小字号而非隐藏 |
| Resonance 置信度太低 → 总是显示（噪音） | 中 | 高 | 严格控制阈值，"不显示"是安全默认 |
| 用户从 Finder 拖入海量文件 → Desk 膨胀 | 中 | 中 | 体验设计已内置 7±2 容量上限 |
| Bookmark Fold 对非 .md 文件（.html/.txt）失效 | 低 | 低 | 仅存储 scrollPos，无折痕动画 |
| 现有用户习惯了侧栏 → 更新后困惑 | 高 | 中 | 提供"经典模式"配置项（恢复侧栏），新用户默认无侧栏 |

## 十、与现有设计概念的关系

| 原有概念（v3） | 无侧栏方案中的位置 |
|----------------|-------------------|
| 帷幕（Curtain） | 工具栏降级为 2px 边缘触发器——完全对齐 |
| 液态工具栏 | Resonance + 极淡边缘浮现——扩展了"工具在需要时出现" |
| 写作流（Flow Mode） | Surface 层是永久的 Flow Mode——不再需要"模式切换" |
| 氛围引擎 | 通过底色纸质感 + Time Bands 的行为纹理实现——不增加新主题 |
| 告别屏幕 | Bookmark Fold 替代——从"关弹窗"变成"纸上折角" |
| 智能编织 | Resonance + Ink Relics 完全覆盖——更具体，可落地 |
