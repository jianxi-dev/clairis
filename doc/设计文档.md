# Markdown 编辑阅读器 App — 设计文档

> 受 Talari (TeX 断行排版 Markdown 阅读器) 视频启发，跨平台 Markdown 编辑器。
> 经过 5 轮 Codex 对抗审查，42 条发现全部采纳。

---

## 一、总览

跨平台 (macOS + Windows) Markdown 编辑器，默认 WYSIWYG 编辑 + 源码模式可切换。支持字体缩放、标题颜色（仅编辑区渲染）、全文翻译（Ollama 本地 / OpenAI 云端，流式逐字输出）。

### 技术栈

| 层 | 选型 |
|---|---|
| Shell | Tauri v2 (Rust) |
| UI | React + TypeScript + Vite |
| WYSIWYG | TipTap (ProseMirror) |
| 源码编辑 | CodeMirror 6 |
| 状态管理 | Zustand |
| 样式 | Tailwind CSS |
| 翻译后端 | Ollama (本地) + OpenAI API 兼容 (云端) |

### 核心需求

| 需求 | 方案 |
|------|------|
| 秒开 | Tauri 冷启动 <1s |
| 跨平台 | macOS + Windows 一套代码 |
| WYSIWYG 默认 | TipTap 点哪改哪 |
| 源码模式切换 | CodeMirror 6，CSS display 切换 |
| 字体大小 | CSS 变量滑块，持久化 |
| 标题颜色 | H1-H6 独立 color picker，仅渲染态 |
| 翻译 | 全文翻译 + 流式逐字输出 |
| 翻译后端 | Ollama / OpenAI 用户配置切换 |

### 数据流

```
文件存盘
    ↕ (Rust commands: open_file / save_file)
编辑器内容 (markdown string)
    ↕ (Zustand store)
     ├─ TipTap (ProseMirror doc) — 正常模式单一数据源
     └─ CodeMirror (raw markdown) — 大文件/源码模式

翻译流:
用户 Ctrl+T → Rust 加载 config + keyring →
  ├─ Ollama: POST /api/chat stream (newline JSON)
  └─ OpenAI: POST /v1/chat/completions stream (SSE data:)
→ Rust emit("translation-chunk", {requestId, text})
→ 前端过滤 requestId → 逐字追加侧边栏
```

## 三、技术决策

| 决策 | 选择 | 理由 | 替代方案被否原因 |
|------|------|------|----------------|
| 编辑器内核 | TipTap (ProseMirror) | 真 WYSIWYG，点哪改哪 | CodeMirror 非真 WYSIWYG |
| 单一数据源 | TipTap doc 权威 | 避免两个 buffer 分歧 | - |
| 文件 I/O | 全 Rust 后端 commands | 安全，权限可控 | 前端 fs 插件权限太宽 |
| 翻译 HTTP | Rust reqwest 后端 | 后端校验 endpoint 防 SSRF | 前端 http 插件不安全 |
| API Key | OS keyring | 明文存 key 是安全漏洞 | config.json 明文不安全 |
| 标题颜色 | CSS class 装饰 | 不侵入文档 attribute | style attr 会泄露到序列化 |
| 翻译并发 | 单活跃 slot + requestId | 防竞态 | 多并行浪费资源 |
| 文件写入 | tempfile::persist 原子替换 | 崩溃不损坏原文件 | 直接写入有损坏风险 |
| 大文件 >500KB | 纯源码编辑，不加载 TipTap | 防性能崩溃 | - |
| 模式切换 | CSS display:none/block | 保留编辑器状态 | conditional mount 销毁状态 |
| 快捷键 | 平台感知 Cmd/Ctrl | macOS 习惯 Cmd，Windows 习惯 Ctrl | 写死一个平台不友好 |
| Markdown 格式 | 基础 GFM（不含 frontmatter） | MVP 范围适中 | 完整 GFM 开发量大 |

## 五、实现步骤

### 步骤 0 — 项目脚手架
- `npm create tauri-app@latest` → React + TS + Vite
- 安装前端依赖: TipTap, CodeMirror 6, Zustand, Tailwind
- 添加 Rust 依赖: reqwest (stream), serde, futures-util, tauri-plugin-dialog, keyring, tempfile, tracing
- 配置 `capabilities/default.json`: dialog + event-listen（最小权限）
- 验证: `cargo tauri dev` 启动无误

### 步骤 1 — 状态管理 + 类型定义
- `types/index.ts`: AppConfig, HeadingColors, EditorMode, TranslationProvider, RawMarkdown
- `stores/editorStore.ts` (Zustand):
  - editorContent: `ProseMirrorDoc | RawMarkdown`
  - editorMode: wysiwyg | source | sourceReadOnly
  - fontSize: number
  - config: AppConfig
  - translation: { active, requestId, text, loading, error }
  - dirtyFlag: boolean

### 步骤 2 — ProseMirror Schema + Markdown 互转
- 与 TipTap StarterKit 匹配的规范 schema
- `MarkdownSync.ts`:
  - `markdownToDoc(md)`: markdown → ProseMirror Node
  - `docToMarkdown(doc)`: ProseMirror → markdown
- GFM 支持: `@tiptap/extension-table` + `@tiptap/extension-image` + `@tiptap/extension-code-block-lowlight`
- 表解析: `prosemirror-markdown` + table token 映射（table, table_row, table_cell）
- Frontmatter: 读取时保留在 buffer，保存时原样追加

### 步骤 3 — WYSIWYG 编辑器
- WysiwygEditor.tsx 初始化 TipTap + schema
- 默认模式
- Heading 颜色通过 CSS class 装饰，不侵入文档 attribute

### 步骤 4 — 源码编辑器
- SourceEditor.tsx 初始化 CodeMirror 6 + `lang-markdown`
- CSS `display:none/block` 切换而非 conditional mount

### 步骤 5 — 模式切换 + 双向同步
- 正常模式: TipTap 是单一数据源，源码视图从 TipTap 序列化
- 源码模式存/译: 提交 CodeMirror → 反序列化回 TipTap → 再执行
- 大文件模式 (>500KB): 纯 RawMarkdown，保存/翻译直接从 CodeMirror

### 步骤 6 — 文件操作
- Rust `commands/file.rs`:
  - `open_file()` → dialog → fs::read → 返回 string（检查文件大小）
  - `save_file(path)` → 原子写入: tempfile::persist（同目录 temp → replace）
  - `save_as_file()` → dialog 选路径 → 写入
- 前端 `useFile.ts` 封装 Tauri invoke
- 跟踪 dirtyFlag，关闭/切文件提示保存

### 步骤 7 — 配置持久化
- Rust `config.rs`:
  - AppConfig: fontSize, headingColors, ollamaEndpoint, openaiEndpoint, openaiModel, translationProvider, langPair
  - `app_config.json` 存非密配置
  - API key → `keyring` crate，以 `{provider}:{endpoint_host}` 为 key
  - keyring CRUD: set_password（覆盖）/ delete_password / get_password
  - 配置损坏: rename 备份 → 回退默认 → toast 通知

### 步骤 8 — 字体大小
- CSS 变量 `--editor-font-size`
- FontSizeControl 滑块组件
- 实时缩放，保存到 config

### 步骤 9 — 标题颜色
- `extensions/HeadingColor.ts`: TipTap 自定义扩展
  - 继承 Heading，通过 CSS class 应用颜色
  - 不侵入文档 attribute
- HeadingColorPanel: H1-H6 独立 color picker
- Config 存 `{ h1: "#ff0000", h2: "#00ff00", ... }`

### 步骤 10 — 翻译后端 (Rust)
- `commands/translate.rs`:
  - 命令 `translate_text(text, sourceLang, targetLang, provider)`
  - endpoint/model/key 从 config + keyring 加载（不接受前端参数）
  - Provider-specific 解析器:
    - Ollama: POST `{endpoint}/api/chat` stream → newline-delimited JSON
    - OpenAI: POST `{endpoint}/v1/chat/completions` stream → SSE data: event
  - 后端取消: 全局单活跃 slot + AbortHandle
  - slot 生命周期: 新请求 abort 旧请求 → emit chunk → done/error/close 清理
  - Endpoint URL 规范化: normalize base URL，拒绝 query/fragment

### 步骤 11 — 翻译前端
- `hooks/useTranslation.ts`:
  - invoke 触发翻译
  - listen "translation-chunk" 匹配 requestId → 追加文本
  - listen "translation-done" → 结束态
- TranslatePanel: 侧边栏面板
  - 语言对切换（英⇄中，默认英→中）
  - 流式逐字输出
  - 加载态/错误态 UI
- TranslationSettings: endpoint, model, API key 输入

### 步骤 12 — 工具栏 + 快捷键
- EditorToolbar: 模式切换、字体滑块、翻译开关、颜色配置入口
- 快捷键（平台感知）:

| 快捷键 | 功能 |
|--------|------|
| Cmd/Ctrl + S | 保存 |
| Cmd/Ctrl + O | 打开 |
| Cmd/Ctrl + Shift + M | 切换编辑模式 |
| Cmd/Ctrl + T | 翻译 |

## 六、错误处理

| 情况 | 策略 |
|------|------|
| Ollama 未运行 | 前端显示 "无法连接 Ollama" 提示 |
| API Key 无效 | OpenAI 返回 401，显示 "API Key 无效" |
| 网络超时 | 前端超时提示，可重试 |
| 大文件 >500KB | 自动切源码模式并警告 |
| 大文件 >2MB | 只读源码模式，禁用编辑 |
| 空文件 | TipTap 渲染空文档 |
| 配置文件损坏 | 备份 → 回退默认 → toast 通知 |
| Frontmatter | 读取保留 buffer，存回原样写入 |
| 源码解析失败 | save/translate fallback 原始字符串 |
| 翻译竞态 | 单 slot + requestId 过滤 |
| 日志安全 | 不记录文档 payload 和密钥 |

## 十、边界范围 (MVP)

### 范围内
- 单文件打开/编辑/保存
- WYSIWYG + 源码双模式
- 基础 GFM（标题、粗斜体、列表、链接、图片、表格、代码块）
- 字体大小可调
- 标题颜色 H1-H6 可配置
- 全文翻译（英⇄中），Ollama / OpenAI 双后端
- 配置持久化

### 范围外（后续阶段）
- 多文件/文件树浏览器
- 选中片段翻译
- Frontmatter 编辑支持
- 脚注/任务列表语法
- Linux 平台
- 原生菜单栏
- 导出 PDF/HTML
- 协同编辑
- TeX 断行算法（参考 Talari，后续独立优化）
