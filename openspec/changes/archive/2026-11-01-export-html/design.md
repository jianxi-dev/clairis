# Design: 导出 HTML

## D1 单文件、离线

产物必须断网可看：样式内联进 `<style>`，图片若能读到就内联为 data URL；读不到的图片保留相对路径并在结果里报告「N 张图片未能内联」。不引用任何 CDN。

## D2 渲染来源

用 Clairis 自己的 `renderMarkdown`（marked + DOMPurify），不搬 md-bundle 的渲染器。样式取 `src/styles/reader.css` 与 `tokens.css` 的原文（Vite `?raw`），加一层 `.export-root` 包裹避免与应用样式冲突。

## D3 不注入署名

不加 byline / 「made with」徽章 / 生成器标记。产物只含文档本身与必要样式。

## D4 UI 入口

页签右键菜单 → 「导出 HTML…」→ `save_as_file`（系统保存对话框）。默认文件名 = 当前文档名 + `.html`。成功提示「已导出」，失败给人话错误（不显示路径以外的技术细节）。

## D5 图片内联

相对路径图片：按当前文档目录解析 → `read_file_base64` → `data:<mime>;base64,...`。远程 URL 保持原样（离线不可用但可点）。无法读取的保留原引用并计入失败数。

## D6 测试

- `buildHtmlDocument`：标题、正文 HTML、内联样式存在；不含 `<script src=http` 或 CDN 链接。
- `inlineImages`：相对路径 → data URL；缺失文件 → 保留原引用并返回计数。
- 不含署名标记（断言无 `byline` / `generated by`）。
- e2e（tauri-mock）：右键页签 → 菜单出现「导出 HTML…」；点击后 mock 的 `save_as_file` 被调用（记录参数）。
