# Design: 浮层定位

## D1 为什么要写优先级，而不是一条阈值

用户的原话是「最短路径」+「不是所有都无脑的最小路径，也要考虑位置显示的最优点及显示的统一性和整齐性」。

单一阈值会造出难看的东西：为了让菜单贴近触发点，不同的块可能得到 3px、6px、9px 三种偏移；用户连续打开两次，菜单位置还会跳。**整齐**在感知上比"少移 5px"重要得多。

所以写成三层：先保证看得全、不挡手，再保证同类一致，最后才取最近。

## D2 量什么

**矩形最近距离**，不是中心点距离。

一个 200px 高、贴在指针右边的菜单，中心点离指针 100px+，但用户实际要跨过的空白只有 4px。用中心点会逼着菜单设计成"又小又方"，与本意相反。

```
dx = max(0, max(a.left - b.right, b.left - a.right))
dy = max(0, max(a.top - b.bottom, b.top - a.bottom))
distance = hypot(dx, dy)   // 相交时为 0
```

## D3 阈值 8px

小于一个字符宽（14px 正文），也小于任何可点击目标的最小尺寸。实测三个入口都是 4px（等于设计里的视觉缝隙），8px 留一倍余量。

## D4 例外要显式

「统一定位组」不是免责条款：实现里必须能指名哪几个浮层属于同一组、用哪条对齐边。否则每次"为了整齐"都是临时判断，迟早有人为了近 3px 单独偏移。

## D5 覆盖范围

目前进 e2e 的是块菜单、二级插入面板、大纲浮层；其余（斜杠菜单、单元格插入菜单、表格边界气泡）在新增或改动时按同一判据补用例。

## Verification

`e2e/shortest-path.spec.ts`：
- 三条 `gap ≤ 8`（块菜单 / 二级面板 / 大纲）
- 一条**同类位置一致**：同一手柄连续召唤两次，浮层相对偏移完全相同
