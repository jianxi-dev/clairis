## Context

文档属性面板（`src/components/Content/DocPropertyBar.tsx`）的三处行为与用户预期不符，对应 #1127。现状实现观察（本 change 的修改基线）：

- 选择按钮文案由 `allSelectableSelected` 决定，只有全部可选字段都选中才显示「反选」；可选中单位只覆盖字段行，标签行不可选中，值文本节点也落在选中范围内。
- `isManagedDateKey`（`src/lib/frontmatter.ts`）已把 `created` / `updated` 标为托管只读键，面板内已做行级只读（锁图标、禁改名、禁删除、禁类型菜单），但这两个日期没有独立的只读展示区：A 模式底部 footer 只有字段计数，B 模式备注行也只放计数。
- `useDocPropertyPanelStore.variant` 已有 A / B 两种形态，但 `setVariant` 没有按钮调用，用户在界面上无法切换；`variant` 仅内存态、未持久化，窄窗下也不会自动切胶囊。

约束：视觉数值只在 `docs/design/system/spec.md` 定义一次，实现与票面只引用条款号或 token 名，不复制像素值；场景标题与主规格逐字一致；1 task = 1 ticket = 1 PR。

## Goals / Non-Goals

**Goals**

- 选择模型与用户预期一致：字段名称与标签可选中，值不参与，按钮随选中数在「全选 / 反选」间切换，反选为反转选择集。
- 托管日期有明确的只读展示位：A 模式 footer 左侧、B 模式备注行右侧，值取自 frontmatter。
- 形态可切换、可持久化、窄窗自动适配：标题栏 AB 图标切换，写入全局偏好，窄窗默认胶囊、手动切换后以用户为准。

**Non-Goals**

- 不改 frontmatter 键名校验、别称表、模板套用逻辑。
- 不改属性区拖拽排序、就地改名、类型切换。
- 不改文档属性以外任何面板的形态切换。
- 不新引入文件系统时间读取（托管日期值一律取自 frontmatter，保存逻辑沿用既有）。

## Decisions

### D1 选择模型：字段名称 + 标签，值不参与，反选为反转

- 选择：可选中单位限定为**字段名称**与**标签**两类节点，值文本节点不参与选中。0 个选中时按钮显示「全选」，≥1 个选中时显示「反选」；「反选」语义为**反转当前选择集**（已选的取消、未选的选上），与现有「全选后再点一次」的补集语义一致，但切换条件从「全部选满」改为「选中数 ≥1」。
- 放弃的替代方案：保留「全部选满才显示反选」（现状，用户要勾满才变反选，与预期不符）；把值也纳入选中（用户明确选择单位是字段名称，不含值，值纳入会圈中大段文本，观感混乱）。理由：以选中数为切换条件、以字段名 + 标签为选中单位，既满足「选中任意一个即见反选」，又让反选是纯粹的反转操作，语义清晰可验收。
- 连带：`allSelectableSelected` 的判据改为「可选中节点（字段名 + 标签）中已选数是否等于总数」，按钮文案与 `title` 随选中数切换；标签行纳入可选中集合，反选时标签同样被反转。

### D2 托管日期：排除出可编辑列表，A footer 左 / B 备注行右只读展示

- 选择：用 `isManagedDateKey` 把 `created` / `updated` 从可编辑字段列表排除，不进入字段行渲染；两日期以只读形式展示，A 模式放在底部 footer 左侧（与「N 个字段」同行），B 模式放在备注行右侧，均带锁图标、无输入框，点不动。值取自 frontmatter，保存时由既有逻辑维护，不新引入文件系统时间读取。
- 放弃的替代方案：在字段行内继续渲染托管日期（现状，行级只读但无独立展示位，A footer 与 B 备注行都看不到日期）；另读文件系统时间戳（会与 frontmatter 值不一致，且超出本次范围）。理由：`isManagedDateKey` 已确立「托管只读」语义，把日期从可编辑列表剔除、在两形态各自指定位置只读展示，用户在设计稿指定的两处都能看到，且值源唯一（frontmatter）。
- 连带：frontmatter 缺失 `created` / `updated` 时对应位置不渲染空壳（只有值存在才显示对应日期项）。

### D3 形态切换：全局偏好持久化 + 窄窗自动胶囊

- 选择：属性区标题栏右侧按钮区新增 AB 切换图标（与模板 / 折叠 / 设置同组），点击在 A / B 间切换；切换写入**全局偏好** `docPropertyVariant` 并持久化；窄窗（窗口宽度 < 720px）默认使用胶囊形态，用户手动切换后以用户选择为准。
- 放弃的替代方案：单文件记忆（用户已裁定不采用，全局常驻才是目标）；仅内存态（现状，重开应用丢失，用户明确要「重开应用仍是上次的形态」）。理由：全局偏好持久化满足「重开保持」，窄窗自动胶囊满足「不被挤成一列」，手动切换后以用户为准满足「用户有最终控制权」，三者各司其职。
- 连带：`setVariant` 接线到 AB 按钮；窄窗判断以窗口宽度为输入，用户手动切换记录偏好，窗口变化时优先用户选择、仅在用户从未手动切换且窄窗时走胶囊。

### D4 设计数值落点：先补条款再引用，不复制像素值

- 选择：本 change 涉及 footer 日期字号、AB 切换图标尺寸两项视觉数值。这些属设计系统尚无刻度的新面，先在 `docs/design/system/spec.md` 登记条款（§2.3 追加 AB 切换图标条目、§7 追加属性面板 footer 与图标密度档位），再在 anchors 与票面引用条款号，不复制像素值。
- 放弃的替代方案：在组件样式里直接写像素值（违背「视觉数值只在 spec.md 定义一次」的硬约束，后续改动无单一来源）；不登记条款直接引用（条款不存在，锚点无来源）。理由：先补条款再引用，保证数值有唯一来源、票面与 e2e 只引条款号，与仓库既有约定一致。
- 连带：新增 AB 图标概念须先过 `docs/design/system/spec.md` §2.3 再进 `src/ui/icons.ts` 注册表（24×24 viewBox、笔画 1.7、尺寸档 14/18/24）。

## Risks / Trade-offs

- [反选语义从「补集」改为「反转」，与现有「全选后再点」行为在「全部选满」时结果一致，但部分选中时反选结果不同] → 用户明确要反转，语义与按钮文案「反选」一致；e2e 断言选中任意一个后按钮变「反选」、反选后选择集互补。
- [标签纳入选中集合后，标签行的选中态与字段行需统一视觉反馈] → 标签行与字段名选中态共用 `dpb-row-selected`，选中高亮落在标签胶囊与字段名上，值不圈中；e2e 断言标签可选中、反选时标签被取消。
- [托管日期从字段行剔除后，若依赖字段行计数或行序的逻辑需同步] → 日期不计入字段计数，「N 个字段」仅统计可编辑字段；e2e 断言日期不出现在字段行、且字段计数不含日期。
- [窄窗自动胶囊与用户手动偏好的优先级若处理不当会反复横跳] → 以用户手动切换为最高优先级，仅在用户从未手动切换且窄窗时走胶囊；e2e 覆盖窄窗自动胶囊、手动切换后窗口变化仍保持用户选择。
- [AB 图标新增若未先补 spec §2.3 条款会违背图标注册约束] → D4 先落条款再注册；票面与 e2e 只引用条款号。

## Migration Plan

1. 无数据迁移、无配置结构变更；回滚 = git revert 本 change 提交。
2. 实现顺序与 tasks.md 切片一致：1.1 先落选择模型（字段名 + 标签可选中、按钮随选中数切换、反选反转），2.1 再接托管日期只读展示与 AB 形态切换（含全局偏好持久化与窄窗自适应）。
3. 设计系统条款（§2.3 AB 图标、§7 footer / 图标密度）与 2.1 同批落，避免「组件已引用条款而条款未定」的半态。
