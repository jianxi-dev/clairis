## Why

文档属性面板上一轮（`doc-property-acceptance` / `doc-property-acceptance-2`）把 O2 收口为「日期选择器密度」——面板宽度、月历格、翻页键与时分步进的几何，`--dpb-cal-*` 已有定义。但当时明确留下的空白是**值区怎么录入**：现有实现只有「点值 → 开面板 → 面板内选 → Enter 或点外部提交」，编辑态的值区是一枚不可输入的静态触发器，日期字段点日格不会提交，双击会被当成两次普通点击。维护者验收后确认了一套完整的日期/日期时间字段操作模型，需要单独成 change 固化，否则会在下一批真机验收里再次被当成缺陷反复返工。

## What Changes

- **值区可输入**：日期与日期时间字段在编辑态把值区渲染为可编辑文本控件（沿用同一个 `DatetimeEditor` 与同一个 popover，不新建第二个选择器）。点击仍打开面板；可直接键入或粘贴。
- **日期字段**：单击日历日格**立即提交并关闭面板**（已确认）；「今天」走同一提交路径；直接键入/粘贴 `YYYY-MM-DD`（`YYYY/MM/DD` 容错），保存时归一化。
- **日期时间字段**：日格与时分只改草稿；Enter 或点外部保存为 `YYYY-MM-DDTHH:mm`；直接键入/粘贴 `YYYY-MM-DD HH:mm`（`T` 分隔、可选秒、`/` 容错），保存时归一化。
- **双击**：双击值区 = 打开面板并把焦点放到时分输入（日期时间）或日历日格（日期）；双击不表示「保存」。
- **提交语义**：Enter / 失焦保存，Esc 回退原值；非法输入回退原值并提示。空输入允许保存，写回空值——不回退「今天」，不渲染 `—`。
- **托管日期**：`created` / `updated` 保持只读，不出现输入、粘贴或双击编辑入口。
- **非目标**：不改面板宽度与 `--dpb-cal-*` 密度；不动时分步进（含 O2 的 32px 间距与 WebKit 56px 组）；不动形态切换、footer 与整体布局；不新增用户可设置项或持久化键。

## Capabilities

### New Capabilities

- 无新增能力域。

### Modified Capabilities

- `doc-property-panel`：P-3 字段类型系统与智能编辑——补充日期/日期时间值区的直接输入、粘贴归一化、空值写回、日期日格单击提交、双击聚焦与一次性提交语义；「面板内操作不提前提交」收窄到日期时间字段（日期日格单击是显式例外）。
- `doc-property-panel`：托管日期只读展示——补充在新输入面下 `created` / `updated` 仍无输入、无粘贴、无双击编辑入口。

## Impact

- 前端：`src/lib/frontmatter.ts`（日期/日期时间输入归一化；空输入按合法空值处理）、`src/components/Content/DocPropertyBar.tsx`（`ValueView` / `DatetimeEditor` 的值区控件、草稿同步、日格提交、双击聚焦）。
- 样式：仅复用既有类与尺寸；若值区元素类型变化，沿用现有盒模型，不引入新的像素值。
- 测试：`src/__tests__/frontmatter.test.ts`（日期 `/` 容错由拒绝改为接受并归一化、空值、日期时间分隔符归一化）、`src/__tests__/components/Content/DocPropertyBar.test.tsx`（日期日格由「点后等 Enter」改为「点即提交」、值区出现可编辑文本控件）、`e2e/doc-property-panel.spec.ts`（类型切换日期用例去掉多余的 Enter、新增直接输入/粘贴/空值/双击/托管只读用例）。
- 无 Rust 侧改动；无配置 schema 或持久化格式变更；无新增外部依赖。
