# Proposal: 编辑态 = 预览态（E-8 显示契约）

## Why

编辑态已经具备完整的块级装饰与编排层，但用户实测判定「显示有些混乱，不如直接看预览」。逐项取证后确认，问题不在功能缺失，而在**编辑态另造了一套外观**：

- 语法高亮器 `defaultHighlightStyle` 给标题加了 `underline + bold`，与装饰层的字号/配色打架。
- 多行引用逐行套 `padding`，一张引用被撑成两条间距翻倍的灰带。
- 高亮块（`> [!TIP]`）同时命中引用装饰，卡片外面多出一层引用底色。
- 围栏代码块的开启/闭合围栏行各占一整行，卡片上下各多出约 38px 空白。
- 缩进列表（`  - 项`）不识别，直接显示 `- ` 原文且没有缩进。

用户的要求很明确：**编辑态看到的效果要和预览态一样，相当于在预览里编辑。** 这是产品级显示契约，不是零散 bug，因此立条目。

## What Changes

1. **显示契约条目标格**：新增 E-8，规定编辑态与预览态共享纸面、排版、配色与块级渲染。
2. **排版变量单一来源**：编辑态与预览态读同一组 `--type-*` / `--heading-*` 变量（由同一 store 注入）。
3. **去掉编辑器专属外壳**：不装行号槽、折叠箭头、活动行高亮（已在上一批完成，写入契约防回退）。
4. **高亮器与装饰层分工**：语法高亮只负责代码 token，不得改写标题/正文排版。
5. **块级组合规则**：多行引用是一张卡片；高亮块只保留自己的卡片；围栏代码块不额外占行；嵌套列表保持缩进与项目符号。

## Impact

- `e2e/editor-display-parity.spec.ts`（同貌回归）
- 无 Rust 侧改动，无数据格式改动。
