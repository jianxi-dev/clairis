# Design: 块菜单/图标体系与单元格编辑

## D1 图标体系单一来源

**决定**：`src/editors/icons.ts` 是唯一图标词汇表。要求：
- 所有图标 ∈ 豆包图标表（命名后缀 `Outlined`），逐个 `svg[data-icon]` 可断言；
- 纯字形图标（`kind:"text"`，当前 11 个：H1–H6、¶、A…）**仅允许**用在「转为」网格行内，且必须与 path 图标同字号/同视觉重量；其它位置（手柄、动作行）一律用 path 图标。

**理由**：现在 60 个图标里 11 个是文字字形，同一菜单里 `H2` 是字、`有序` 是线，视觉不成体系——这是用户说「不符合图标体系」的直接原因。

**失败后果**：菜单仍然一眼看出是拼凑的。

## D2 转为 = 图标网格

**决定**：「转为」渲染为 5 列 × 2 行图标网格（10 项：正文/H1/H2/H3/有序/无序/待办/代码/引用/高亮），当前块型高亮；结构动作组（缩进和对齐、颜色、复制、剪切、删除、翻译）保持列表行，行高 32px。

**理由**：豆包把「转为」做成图标网格、把命令做成列表行——两种密度的分组本来就是它「不小气」的来源。我们全做成列表，10 行同样长的文字，视觉上就是一张表。

**失败后果**：菜单仍是长列表，用户继续觉得「小气」。

## D3 表格块菜单

**决定**：表格不再进 `NON_CONVERTIBLE`。菜单 = 结构组（标题行/标题列/均分列宽，开关态）+ 动作组（删除表格）+ 在下方添加。三个开关直接改 GFM 分隔行与列宽，失败即回滚（不产生半写状态）。

**理由**：表格是最高频的块，菜单里一行都没有。

**失败后果**：表格的转换手柄点开只有一个「在下方添加」，等于没有。

## D4 单元格编辑面

**决定**：单元格进入编辑时，用**行内可编辑元素**（contenteditable 的 span 或 CM6 单行实例，取实现成本低者）替代 `<input>`，保留 GFM 单元格单行约束：
- `/` 打开锚定插入菜单（已有 `trigger: "anchor"` 通道）；
- 行内 markdown 粗体/斜体/链接/代码即时渲染；
- Enter 提交、Tab 提交并右移、Esc 取消、失焦提交；
- 提交文本必须经过 `sanitizeCellText`（禁止换行与裸管道符）。

**理由**：现在是 `<input type=text>` 且 `keydown` 一律 `stopPropagation`，任何编辑器能力都进不来。

**失败后果**：表格里只能写字，斜杠、链接、加粗全部失效。

## D5 工具条只留有用的

**决定**：删除背景色整块能力（含 `mdb-bg-*` 写入路径与 `setCellBackground`）；合并按钮仅当选区跨 ≥2 行时渲染；单格选区不渲染工具条。

**理由**：E-9 现在要求「单格也显示工具条 + 提供背景色」，与用户实际使用完全相反——背景色他们说「功能不能用，频率很低」，合并「单格都显示」是噪音。

**失败后果**：规格继续要求一个没人用且不好用的控件。

## D6 标点归一放在输入形态层

**决定**：在 `smart-input` 的输入处理里按「前后字符都是 CJK 或行内代码外」规则替换 `，`→`,`、`／`→`/`；替换可撤销（一次 undo 回到全角）。不处理已是 ASCII 的字符，不碰代码块/行内代码/URL。

**理由**：在渲染层替换会让源码与显示不一致（违反 E-7 红线「显示=源码」）。

**失败后果**：代码块里的逗号被改，或显示与源码漂移。
