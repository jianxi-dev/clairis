# Proposal: 块菜单/图标体系与单元格编辑对齐豆包（第二批）

## Why

用户在一次真机走查里报出 17 条 md 编辑态问题。其中 7 条已独立成缺陷票（#103–#109）。剩下这批不是「实现 bug」，而是**能力缺口**：菜单没做全、图标体系不是豆包的、单元格只能敲纯文本、工具条按旧规格做了用户不要的东西。它们要么超出 E-7 的现有条文，要么与 E-9 直接冲突，必须走需求闭环。

## What Changes

1. **块菜单功能补齐**：转为之外补结构动作组（缩进/对齐、颜色、复制、剪切、删除、翻译），表格块补 标题行 / 标题列 / 均分列宽（当前 `NON_CONVERTIBLE` 把表格菜单清空，只剩「在下方添加」）。
2. **块菜单视觉与图标体系**：「转为」改成 10 项图标网格（豆包 5×2）；菜单图标 16→18px；行高/字号/间距按 token；「在下方添加」补图标与右侧 chevron，形态与其它行一致。
3. **单元格富文本编辑**：单元格编辑从原生 `<input>` 换成可跑行内 markdown 的编辑面，`/` 打开锚定插入菜单，支持粗体/斜体/链接/行内代码。
4. **单元格工具条瘦身（修订 E-9）**：删除「单元格背景色」；「合并单元格」仅在选择 ≥2 行时出现；单格不再弹工具条。
5. **全角标点归一**：中文输入法下的 `，` → `,`、`／` → `/`（可扩展其余标点）。

## Capabilities

### Modified Capabilities

- `editing`：E-9 修订（工具条内容与可见条件）。

### New Requirements

- E-11 块菜单与图标体系
- E-12 单元格富文本编辑
- E-13 全角标点归一

## Impact

`block-convert.ts` / `block-menu.ts` / `icons.ts` / `editor.css` / `table.ts` / `cell-toolbar.ts` / `smart-input.ts`；新增 e2e 覆盖状态矩阵与视觉锚点。

## 与缺陷票的关系

#103–#109 是同一批走查里的**实现缺陷**，走 fix 线，不被本 change 阻塞；本 change 只处理能力缺口。E-9 的修订会让 #109（圆点移除）与工具条相关断言变更，实施时按本 change 的新条文对齐。
