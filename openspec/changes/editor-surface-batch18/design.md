# 设计 — editor-surface-batch18

来源：spec issue #805；需求四要素 `docs/requirements/editor-surface-batch18/requirements.md`。

## D1 文件动作的单一入口 = 页签右键菜单

「导出 / 刷新 / 打开文件位置」是**文件级**动作，归属文件页签右键菜单；格头 ⋯ 是**格级**菜单（新建、分享、分栏、源码模式、定位），不再承载文件动作。

- 页签右键菜单最终顺序（10 项）：悬浮小窗、向右分栏、向下分栏、**导出**、复制路径、**打开文件位置**、移动到…、**刷新**、关闭、关闭其他。
- 格头 ⋯ 菜单最终 6 项：新建文件、分享、右分、下分、源码模式、定位。
- 删除「关闭右键菜单 → 定位到页签 → 打开格头菜单 → 展开导出子菜单」的跳转函数，导出子菜单改为在同一右键菜单内就地渲染。

## D2 导出子菜单复用同一能力清单

导出能力清单（Word/.mdpkg/图片/PDF/HTML/ZIP）保持单一真相源，由右键菜单与任何未来入口共同消费；子菜单项沿用 `data-export-item` 契约，执行函数抽为可复用回调，不再依赖格头菜单的打开状态。打印**不进入**该清单。

## D3 打印 = 独立菜单项 + 预览态打印视图

打印从导出二级项抽出，成为导出正下方的同级项。行为：

1. 由当前活动页签内容构造**打印专用视图**（不复用屏幕 DOM，不切换当前模式）：同一 `renderMarkdown` 管线 + 图片属性解析 + 媒体解析；mermaid 走既有渲染器绘制成 SVG。
2. 打印视图挂载在屏幕外（可布局，不能用 `display:none`，否则 mermaid 文本测量失败），等待绘制完成。
3. 置 `documentElement` 打印标记 → `window.print()` → 在 `afterprint`/`finally` 中移除视图、清除标记。
4. 打印期间不修改 store 的 editorMode，不滚动静默恢复原 scrollTop。

失败兜底：渲染或 mermaid 绘制失败时仍允许打印，但打印视图保留可读的源码块（与预览失败态一致），并在控制台记录错误；不静默吞掉。

## D4 打印版式与预览同源

打印视图复用预览的排版类（`preview-content` + 阅读 token），打印样式表负责：

- `@media print` 下隐藏应用根、只显示打印视图；
- A4 纵向、10mm 边距；
- 代码块/表格/引用/图片/mermaid 避免块内断页；一级标题另起页；
- 白底黑字、去阴影、去固定宽度。

屏幕态（非打印媒体）打印视图不参与布局与命中测试。

## D5 滚动可达性：先复现后修，修共同根因

用户报告含图片文档无法滚回顶部。复现文档含：1 个 58MB mp4（以图片语法引用 → 预览渲染为 `<video preload="metadata">`）、2 张 3012×1772 jpg，其中一张 `{width=884 height=520 crop=1655,973,5405,3181}`。

已知可观测异常：裁剪图在预览里按 `crop` 的 w/h 写成显示盒，得到 5405×3181 的布局盒（被 `contain` 裁到容器可视宽，但高度按 3181 参与布局）。这条作为**首要嫌疑**，但不得直接当结论：

1. T3 先在真实应用（`npm run tauri dev`）复现，记录滚动容器 `scrollTop`、`scrollHeight`、图片/视频加载前后的高度变化、滚轮方向与可达最小值；
2. 依据测量结果确认根因，写在票面（DQ-2）；
3. 修复作用于共同根因：图片显示尺寸受容器宽约束（裁剪高度按比例），并保证高度变化不吞掉可达顶部；
4. 修复后重跑同一复现路径（DQ-3/DQ-5）。

## D6 测试取点

- 菜单：页签右键菜单与格头菜单的真实 DOM，断言项数与索引顺序、子菜单就地出现、格头不含三项。
- 打印：`window.print` 计数 + `emulateMedia({media:"print"})` 下的可见性 + 打印视图内容（含 mermaid `svg`、不含 CodeMirror 源码行）+ 打印后视图移除与模式/滚动恢复。
- 滚动：真实尺寸图片的预览，滚到底后滚轮回顶断言 `scrollTop=0` 且首块可见；裁剪图宽度 ≤ 容器宽。
