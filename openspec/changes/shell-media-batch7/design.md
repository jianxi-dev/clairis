## Context

本批 8 项反馈全部是界面交互与视觉一致性问题，无数据模型、无迁移、无新外部依赖。结构性工作只有三件：

1. 把「悬停浮层不得在指针到达前关闭」从散落补丁升级为**可复用的生命周期规则**（第三次复发，DQ-7）。
2. 视频播放器的画面变换与尺寸适配从「ArtPlayer 默认」提升为**由容器驱动的自有状态**。
3. 引入**自动布局**这一新能力（纯逻辑 + 一个 store 动作）。

现状要点（代码复核）：

- 状态栏主题弹层：`StatusBar.tsx` 中 `scheduleThemeClose()` 设置 150ms 定时器；弹层 `onPointerEnter` 只执行 `setThemeOpen(true)`，**不取消定时器**；弹层 `bottom = innerHeight - rect.top + 6`，与按钮间有 6px 死区；底部隐藏态下指针离开 footer 会 `setStatusBarPeek(false)`，整条状态栏卸载，弹层随之消失。
- 视频：`autoSize: true` 但重排只在 window resize 时触发；栏目尺寸变化（分隔线、格全屏）不触发。控制条右侧现有 `playlist(42) / rate(50) / loop(52) / subtitle(54) / note(56) / fullscreenWeb(60) / pip(40) / hints(80)`，无截图、无画面变换。
- 沉浸：`readingMode` 只给根节点加 `immersive` 类，CSS 仅收拢 `.app-chrome`（每栏栏头）；状态栏显式豁免；阅读空间与 `readingMode` 无关；沉浸页签由单条 `ImmersivePeekBar` 承担。
- 颜色：状态栏右侧 `--app-text-2` 无降级，左侧 `opacity-60`；未选中页签 `opacity-70`；阅读空间卡片底行 `text-gray-400`；栏目全屏按钮 `hover:text-[var(--app-accent)]`，邻居 `hover:text-[var(--app-text-2)]`。
- 悬浮窗：图片 `max-h-full max-w-full object-contain` 装在 `flex h-full` 里（按高适配，永不滚动）；HTML 走 `sandbox=""` + `srcDoc`（脚本被禁、外链样式不执行）。

## Goals / Non-Goals

**Goals:**

- 8 项反馈各自产出用户可见的变化，每项都能用 e2e 在真实页面上观测。
- 把弹层生命周期写成仓库级规则，并被 UI 状态矩阵引用；后续同类控件有统一验收面。
- 视频画面状态（旋转/缩放/亮度/平移）成为播放器内部单一状态源，切文件复位。
- 沉浸模式用派生可见性实现，不写回用户偏好、不做状态快照。
- 自动布局是纯函数 + 一个动作，可单测、不碰页签归属。

**Non-Goals:**

- 不重做主题系统、不改色彩值、不新增主题。
- 不重做播放列表/循环/字幕/笔记。
- 不改网页全屏策略（仍不用 macOS 原生全屏）。
- 不改阅读空间数据来源、排序、密度。
- 不做图片编辑（裁剪/滤镜）。
- 不做多窗口布局同步。

## Decisions

### D-1 悬停浮层生命周期规则（仓库级）

统一六条，适用于所有「悬停打开 + 指针需要横越间隙」的浮层：

1. **进入即取消**：指针进入面板（或其桥接区）时，必须取消已排期的关闭定时器。关闭只在「离开面板与触发器的并集」后重新排期。
2. **间隙归零**：触发器与面板之间的视觉间隙必须由面板的透明内边距/桥接元素覆盖，不使用「两个相邻元素之间的空白」作为视觉分离。
3. **关闭冗余**：除 hover 离开外，必须有外部 `pointerdown`（`contains()` 双守卫）、`Esc`、滚动/窗口尺寸变化关闭。
4. **卸载清理**：组件卸载时清除定时器与监听器。
5. **父级卸载安全**：若触发器的父容器可能因其他交互卸载（如状态栏临时显现），浮层必须随之安全消失，且不产生悬挂状态。
6. **可访问性**：触发器带 `aria-haspopup` 与 `aria-expanded`；面板 `role="menu"`，项 `role="menuitem"`/`menuitemradio`。

**替代方案**：纯 CSS `:hover` 加 `:has()` —— 无法跨 portal，也无法在测试里分步观测；**拒绝**。仅把定时器从 150ms 调到 400ms —— 治不了「进入不取消」的根因；**拒绝**。

永久落点：`docs/design/approved/popup-lifecycle/spec.md`（本 change 交付），并在 `docs/agents/ui-test-matrix.md` 增加「弹层」状态列。

### D-2 状态栏主题入口的两种交互共存

- **悬停**：打开面板（保持现状）。
- **单击图标**：循环 `system → light → dark → warm → system`（恢复 `#381` 之前的点击语义）。
- **点击面板项**：直接设为该项并关闭。

三者不互斥；面板打开时单击图标同样循环，面板保持打开并高亮新当前项。

**替代方案**：单击只开/关面板 —— 用户明确要求能直接切换；**拒绝**。单击在面板打开时关闭面板 —— 会让「点图标换主题」在面板停留时失效；**拒绝**。

**取舍**：指针停在图标上会同时打开面板，此时单击会「既换主题又看到面板」。这是用户显式要的行为，接受。

### D-3 图片右键菜单走应用内自绘

菜单渲染必须**同步**：`contextmenu` 事件处理内只做 `preventDefault` + `setState`，不 await 任何 `invoke`。菜单动作按需异步：打开所在文件夹复用 `reveal_in_finder`；另存为复用 `save_binary_as_file`；复制路径走 `navigator.clipboard.writeText`；关闭预览复用现有动作。

菜单项：打开所在文件夹 / 另存为… / 复制文件路径 / 关闭预览。关闭：选一项、外部 `pointerdown`、`Esc`、滚动、切换文件。

**替代方案**：保留 WebKit 原生菜单 —— 延迟不可控且与全站菜单风格不一致；**拒绝**。

### D-4 「关闭其他」图标造型

单一实心 ×（两条交叉描边）+ 右侧两条短横线（代表其余项），去掉虚线描边与第二枚小 ×。`IconName` 字符串保持 `closeOthers` 不变（e2e 与调用点依赖它）。

**替代方案**：两枚 × 只把虚线改实线 —— 18px 下仍是两枚小叉，辨识度不够；**拒绝**。

### D-5 视频控制条顺序与间距

顺序由 `position` + `index` 决定，目标：

| 位置 | 控件 | index |
|---|---|---|
| left | 上一集 `prev` | 5 |
| left | 播放/暂停（内置） | 10 |
| left | 下一集 `next` | 15 |
| right | 播放列表 | 42 |
| right | 画面（旋转/缩放/亮度） | 44 |
| right | 倍速 | 50 |
| right | 循环 | 52 |
| right | 字幕 | 54 |
| right | 时间戳笔记 | 56 |
| right | 截图 | 58 |
| right | 网页全屏 | 60 |
| right | 画中画 | 64 |
| right | 快捷键说明 | 80 |

间距收紧通过覆盖 ArtPlayer 的 CSS 变量（控制高度/内距/图标尺寸）实现，落在独立的播放器样式文件并在全局样式入口导入；不逐个改内联样式。

**替代方案**：把旋转/缩放/亮度各做成独立按钮 —— 右侧会到 12 个按钮，进度条被挤；**拒绝**（改为一个「画面」弹出面板）。

### D-6 视频画面变换的状态与数学

播放器内部单一状态：

```
{ rotation: 0 | 90 | 180 | 270, zoom: 1..4, brightness: 0.5..1.5, panX, panY }
```

- 应用顺序：先旋转，再缩放，再平移，亮度作为 `filter: brightness()` 独立叠加。
- 缩放 > 1 时允许指针拖拽平移，平移量按缩放后的可移动范围夹取；缩放回到 1 时平移归零。
- 双指捏合：`gesturestart` / `gesturechange` 记录起始缩放并相乘；桌面无手势事件时回退为 `Ctrl` + 滚轮。
- 切换播放源复位为默认值（旋转 0、缩放 1、亮度 1、平移 0）。
- 音频不渲染画面面板、不接受手势。

**替代方案**：用 ArtPlayer 自带 `flip` —— 只有水平/垂直镜像，没有旋转；**拒绝**。

### D-7 视频尺寸适配由容器驱动

在播放器容器上挂 `ResizeObserver`，尺寸变化（去抖后）调用播放器自身的重排入口。这覆盖三类变化：拖分隔线、格全屏、窗口缩放。

**替代方案**：只依赖宿主组件的 `ResizeObserver` —— 它只改宿主尺寸，不会通知播放器重排，正是当前缺陷；**拒绝**。监听 `window.resize` —— 栏目内部变化不触发；**拒绝**。

### D-8 截图走系统另存为

`video` 元素当前帧 → canvas → `toBlob("image/png")` → 转二进制 → `save_binary_as_file`，默认文件名 `<视频名>-<分:秒>.png`。取消保存不产生文件。

**替代方案**：用 ArtPlayer 内置 `screenshot` —— 直接触发下载到默认下载目录，用户不知情且无法选位置；**拒绝**。

### D-9 沉浸模式用派生可见性

不修改 `statusBarHidden` / `railState`，而是在渲染时派生：

- 状态栏可见 = `!readingMode && !statusBarHidden` 或「沉浸 + 底部热区临时显现」。
- 阅读空间可见 = `railState === "pinned"` 时恒可见；否则沉浸态视为 `collapsed`。

退出沉浸时派生条件自然复原，无需快照、无需写回。

**替代方案**：进入沉浸时强制 `setStatusBarHidden(true)` / `setRailState("collapsed")` —— 会污染用户偏好，退出后回不到原状态；**拒绝**。

### D-10 沉浸页签条按栏独立

删除单条 `ImmersivePeekBar`，改为每栏自己的栏头在沉浸态按需展开：

- 指针进入某栏顶部热区（该栏内容区顶缘 16px）→ 该栏栏头在 300ms 内展开（高度恢复、透明度 1），贴合该栏宽度与横向位置。
- 指针离开该栏栏头 400ms → 收起。
- 拖拽页签期间抑制收起。
- 各栏独立计时、互不影响；同时只允许一栏处于展开态（避免多条栏头堆叠）——指针进入新栏时立即收起旧栏。

**替代方案**：保留全局条但加栏标识 —— 用户明确要求「每个栏目独立显示页签条」；**拒绝**。

### D-11 chrome 前景色 token

在主题 token 中新增两档：

- `--app-chrome-rest`（默认暗）
- `--app-chrome-hover`（悬停亮）

应用面：状态栏右侧图标（AI 除外）、顶部未选中页签名、栏目右侧按钮（模式/全屏/更多/关闭）、阅读空间卡片底部按钮行与路径文字。删除这些表面上的 `opacity-60` / `opacity-70` / `text-gray-400` / `hover:text-accent` 拼凑。AI 图标显式保持 `--app-accent`；选中页签保持 accent。

**替代方案**：沿用 `--app-text-2` + 各处 opacity —— 现有六种实现就是这么来的；**拒绝**。

### D-12 悬浮窗媒体与主预览对齐

- 图片：容器可滚动；图片 `width: min(100%, naturalWidth)`、高度自动。长图可纵向滚动；小图不放大。
- HTML：`src` = 本地资源地址（与主预览同一套 `asset://` 生成），`sandbox="allow-scripts allow-same-origin allow-popups"`；不再使用 `srcDoc`。只对 markdown / 纯文本 / 代码类型读取文件内容；二进制与 HTML 不预读。

**替代方案**：保留 `srcDoc` 但加 `allow-scripts` —— 整份文件塞进属性仍有大小与资源解析问题，且与主预览两套实现；**拒绝**。

### D-13 自动布局：纯函数 + 一个动作 + 一个按钮

新增纯逻辑模块，输入 `{ root, tabs, focusedPaneId }`，输出新树；不触碰页签归属，只重排 leaf 的位置与比例。

规则（n = 当前 leaf 数，按深度优先顺序取）：

| n | 形状 | 比例 |
|---|---|---|
| 1 | 单栏 | — |
| 2 | 左右均分 | 恰一栏为媒体时媒体侧 0.62 |
| 3 | 左主栏 + 右侧上下 | 0.5 / 0.5 |
| 4 | 2×2 | 全部 0.5 |
| 5 | 左列 3 + 右列 2 | 0.5 / 0.5 |
| 6 | 左列 3 + 右列 3 | 0.5 / 0.5 |
| >6 | 按 3 列分行 | 均分 |

媒体 = 图片 / 视频 / PDF。媒体栏优先放入面积更大的位置（3 栏的主栏、2 栏的宽侧、4 栏的左上）。

**替代方案**：按文件类型分组（文档一组、媒体一组）—— 会把用户有意并排的同类文档拆开；**拒绝**。

## Risks / Trade-offs

- **弹层与点击循环共存可能误触** → 面板打开时点击循环是显式需求；用 `aria-live` 提示当前主题，并在面板中高亮当前项降低困惑。
- **视频画面变换与 ArtPlayer 内部 CSS 冲突** → 变换作用在视频元素（`<video>`）而非 ArtPlayer 根容器；缩放/旋转后调用一次尺寸重排，避免黑边。
- **每栏独立页签条增加渲染成本** → 复用现有栏头 DOM，仅切换类名/内联样式，不新增组件实例；隐藏态仍保留 DOM（不重挂载，保住拖拽）。
- **自动布局重建树可能丢失顺序** → 纯函数只重排 leaf 引用，页签数组原样搬运；单测断言「页签集合、顺序、activeTabId、editorMode、焦点栏」五不变。
- **颜色 token 改动波及面广** → 先在 token 层定义，再逐表面替换；e2e 断言四处计算色相等，防漏改。
- **HTML 悬浮窗允许脚本** → 与主预览一致（同一沙箱策略），属于已知且已接受的安全面；不引入 `allow-top-navigation`。

## Migration Plan

无数据迁移。界面状态（主题、栏布局、阅读空间宽度）沿用现有持久化；沉浸态与视频画面状态均不落盘，退出/切文件即复位。

回滚：单个表面可独立 revert；自动布局为新增按钮与动作，删除即回到手工布局。
