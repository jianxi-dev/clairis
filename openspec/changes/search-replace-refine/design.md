## Context

搜索替换浮窗是编辑器内最高频的查找入口，当前形态由既有交付叠成。2026-11-18 夜跑对账（#1114）把它的问题归为 10 项：结果摘要按原始文本渲染露出表格结构符号、选中行回车提示是带底色 svg、替换框无清除、输入行与按钮高度偏松、标题栏偏高、滚动后键位不重绑、悬停预览开面板不复位、拖拽后结果窗高度永久固定、⌘N 只选不定位。

现状实现观察（本 change 的修改基线）：

- `SearchReplacePanel.tsx` 行尾键位列对选中行渲染 `Icon name="enterKey"`（带底色键帽 svg），其余行渲染 `⌘${index+1}` 字符；⌘1~9 按全局结果索引绑定，滚动后不变。
- 搜索框有一键清除（清空 + `inputRef.focus()`），替换输入框没有。
- 悬停复位只发生在切换替换态（`toggleReplace` 关替换时清 `hover`），开面板时 `wasOpen` 分支只清 `hover` 相关的部分状态，残留导致首次悬停失效。
- 结果窗高度经 `resultsMaxHeight` 测量（9 行 × 行高 + 内边距），但拖拽高度记忆写在组件外层状态，重开浮窗不回默认。
- ⌘N 分支只 `setSelected(digit - 1)`，不调用 `locate`。

约束：视觉数值只在 `docs/design/system/spec.md` 定义一次，实现与票面只引用条款号或 token 名；本 change 无 Rust 改动；场景标题与主规格逐字一致（上一轮同类 change 归档两次因场景标题被改名 abort）。

## Goals / Non-Goals

**Goals**

- 结果摘要对用户可读：表格块按行拼接单元格文字，结构符号不出现在摘要里。
- 选中行回车提示与键位字符同体系，无底色块。
- 替换框可一键清除并保持焦点；输入行、按钮、标题栏密度统一。
- 键位随滚动重绑可视前 9 行；开面板即复位悬停残留；高度未拖拽时随内容、拖拽仅会话内记忆；⌘N 一步直达。

**Non-Goals**

- 不改搜索算法（匹配规则、大小写、正则、整词）。
- 不改替换语义（含正则捕获组替换）。
- 不改搜索面板以外任何浮窗的样式统一。
- 不改状态栏显隐机制、分布条跳转、八向缩放与位置记忆。

## Decisions

### D1 摘要文本化：展示层清洗

- 选择：在摘要渲染层清洗。表格块按行拼接单元格文字，管道符、方括号引用等结构符号在渲染时剥离；命中高亮仍按原字符坐标包裹，定位、替换、diff 数据流不动。
- 放弃的替代方案：索引层清洗（在 `searchScan` 扫描阶段把块预先转纯文本）。理由：那会改变命中坐标语义，波及定位、替换事务与 diff 预览，风险面大，且搜索匹配规则不在本次范围。展示层清洗只作用于摘要渲染，改动面最小。
- 落地形态：清洗逻辑落 `src/lib/` 独立工具（块文本化 + 表格拼行），由 `SearchReplacePanel` 摘要渲染处调用；工具不进入 `shortcuts.ts` 或任何全局注册面。

### D2 回车型：`↵` 字符

- 选择：选中行行尾改渲染 `↵` 字符，与状态栏「↵ 定位选中」同一字符、同一字号档，去掉底色胶囊。
- 放弃的替代方案：保留 `enterKey` svg 仅去掉底色（仍是键帽图形，与相邻 `⌘N` 字符体系不一致）；为 `↵` 另画无底色 svg 变体（引入新图标条目，成本高于字符方案，且 issue 明确要字符）。理由：`↵` 字符与键位数字同字体同字号，视觉成体系，实现最简。
- 连带：`enterKey` 图标在搜索浮窗内的使用面移除（图标注册表条目本身保留，其他消费面不受影响）。

### D3 清除按钮清空后保持焦点

- 选择：替换输入框非空时显示清除按钮，点击清空替换词并调用 `replaceInputRef.focus()`，行为与搜索框清除逐字对齐。
- 放弃的替代方案：清空后焦点留在浮窗根（用户要重新输入得再点一次输入框）；不做清除（现状，用户只能逐字退格）。理由：与搜索框对称，减少重来路径，焦点留在原输入框是清除动作的最小打扰。

### D4 密度档位：统一高度 + 标题栏对齐

- 选择：搜索行、替换行两个输入框与「逐个替换 / 全部替换」按钮统一同一高度档；标题栏高度与文件卡片悬浮窗对齐，关闭图标改用同一套。
- 放弃的替代方案：只调输入框内边距、不动按钮（输入框与按钮高度不一致，行内对齐松垮）；标题栏单独定一套新数值（与参照窗脱节，违背 S-1 的同构语义）。理由：统一档位后行内对齐整齐，标题栏对齐复用既有同构要求，观感连贯。
- 数值归属：控件高度是设计系统尚无刻度的新面，新档位先落 `docs/design/system/spec.md` §7（控件密度条款），再落 `src/styles/tokens.css` token；票面与 e2e 只引用条款号与 token 名，不复制像素值。

### D5 快捷键常驻语义：滚动重绑可视前 9 行

- 选择：⌘1~9 绑定到当前可视区前 9 行，滚动结果区时键位随行重绑，每行行尾显示对应键位；第 10 行起不显示键位。
- 放弃的替代方案：固定绑全局前 9 条不随滚动变（现状，键位指向已滚出视口的行，按了看不见）；改为每页 9 条的分页模型（改交互骨架，成本高，用户已确认滚动式不反对默认解）。理由：重绑后键位与所见一致，按 ⌘3 看到的就是第 3 行，直达语义才成立。
- 连带：S-3「滚动后快捷键列常驻」场景的 THEN 需要改写为重绑语义，键位列 sticky 常驻不变。

### D6 悬停预览复位时机：开面板即复位

- 选择：每次浮窗打开（open 由关转开）时重置悬停与选中残留，替换模式下首次悬停结果行即正常唤出全文预览卡。
- 放弃的替代方案：仅在切换替换态时复位（现状，开面板后首次悬停失效，正是 issue 缺陷）；每次 query 变化时复位（覆盖不到开面板瞬间的残留）。理由：复位点唯一放在开面板时，语义最简，恰好覆盖「关闭再开失效」的缺陷路径，不引入新的复位时机。

### D7 结果窗高度自适应优先级

- 选择：未手动拖拽时高度由命中内容决定（上限 9 行）；拖拽只在本次会话内记忆，重新打开浮窗回到自适应。
- 放弃的替代方案：拖拽后永久记忆（现状，重新搜索后高度卡死，issue 缺陷）；完全不记忆拖拽（用户调好的高度松手即回弹，体验差）。理由：会话内记忆兼顾「用户调好的高度本次不丢」与「重开回到合理默认」，记忆生命周期与浮窗打开会话对齐，语义清晰可验收。

### D8 ⌘N 直达：setSelected 后必须 locate

- 选择：⌘N 分支执行 `setSelected(N-1)` 后必须调用 `locate(hit)`，滚动编辑器到该命中并高亮选中，一步完成。
- 放弃的替代方案：仅 `setSelected`（现状，用户还要再点一次行）；仅滚动不高亮（用户无法确认定位到哪处命中）。理由：直达的语义是一步看到命中，滚动 + 选区高亮同时完成才满足，否则键位直达退化为两步操作。

## Risks / Trade-offs

- [展示层清洗若表格拼接与命中高亮坐标错位，会丢高亮] → 清洗只动渲染输出、不动命中坐标，高亮按原坐标包裹；e2e 断言摘要不含 `|` 且命中 mark 数不变。
- [`↵` 字符在不同字号下观感与 ⌘N 可能不齐] → 同一字号档、同字符体系；e2e 断言键位列文本内容。
- [键位滚动重绑可能让用户误以为键位是固定全局序号] → 每行行尾即显示当前键位，所见即所绑；状态栏说明文案不变。
- [拖拽记忆的会话边界模糊（何为一次会话）] → 以浮窗打开周期为界：同一打开周期内记忆拖拽值，关闭即清，重开回自适应；e2e 覆盖「拖拽后重开回到自适应」。
- [⌘N 后 locate 会移焦点，若处理不当键上下文丢失] → 沿用现有 `locate` 内「editor 聚焦后立即回浮窗输入框」的既有保护，↑↓ 不失灵；e2e 断言 ⌘N 后 ↑↓ 仍可用。

## Migration Plan

1. 无数据迁移、无配置变更、无持久化结构变更；回滚 = git revert 本 change 提交。
2. 实现顺序建议与 tasks.md 切片一致：摘要与回车型先行（纯渲染面），再清密度与清除按钮，再键位重绑，再复位与高度，最后 ⌘N 直达；每步带对应 e2e 断言，先改与新行为相反的旧断言再落实现。
3. 设计系统条款与 token 随密度票同批落，避免「组件已引用 token 而条款未定」的半态。
